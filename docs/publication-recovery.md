# 已导入Workflow的独立发布恢复

0.346新增本机零派发证据登记和独立恢复声明，解决“执行器在物理HTTP前阻止发布，本机却已保守记为unknown”的阻断。原unknown、write_attempted、Task历史和旧一次性批原样保留；不新建任务或App绕过保护。

## 证据及使用

1. 本机操作者运行 `tools/register_publication_evidence.py`，明确指定项目、既有数据目录、work内冻结包、完整40位来源提交、docs内JSON报告、操作者和说明，并带 `--acknowledge-local-source`。工具只读Git提交中的报告，严格检查JSON、相对路径/链接、plan/manifest/approval/attempt摘要、实际方法路径与计数，拒绝任何发布/Key/运行派发。它不执行旧包，不请求网络，也不从聊天取得凭据。
2. 登记只生成新的加密签封元数据，绑定唯一原unknown及其运行记录摘要、当前Task/App/修订、完整公共环境、成果SHA和核心图。签封是在登记时新增的本机完整性保护，不是给旧回执补造历史签名，更不是独立网络审计。操作者如为代理，记录 `agent_delegated`，不伪造人类批准。
3. “运行→发布当前Workflow”中明确读取本机依据，选中来源、准备声明，填写核对说明并分别确认零派发依据及一次新核对，随后主动选择使用此声明。所有这些步骤均只访问本机，原unknown不改；浏览器不接收任意文件路径/上传证据。
4. 原“读取草稿并准备发布”才会读取Dify当前草稿和发布状态。两者必须匹配且尚未发布；再由原发布勾选和按钮明确派发。声明不能替代新的外部操作/资源/费用范围批准，HTTP200/null本身也不是恢复授权。Chatflow仍保持原保护，本次不扩展。

## 一次性及失败

声明15分钟有效。恢复准备原子占用一份声明给唯一新发布提案；发布派发标记与消费声明同事务落盘。并发准备最多一个成功；新发布一旦可能派发，旧证据不能再使用。重启不自动派发。新发布前核对失败而未派发时，只能重新明确准备本机声明，不能重放原提案；过期/失败原记录仍保留。源变化或证据签封不匹配拒绝操作。有效签封的历史声明保留原状态及血缘，当前来源不适用时标记不可沿用，不把历史改成成功。

平台接口没有原子草稿条件锁，读写之间仍存在外部修改窗口；返回后核发布图，未知不自动重发。支持的证据格式是有完整冻结哈希和运输准入记录的公开批量执行器回执，不泛化为任意网络中断或操作者口头声明。

## 本轮验证及真实边界

95项定向后端检查、9项API接通的浏览器检查和前端构建通过。涵盖签封/哈希/方法路径、两项确认、错源/晚到、并发占用、前后远端变化、失败不消费、派发后消费、旧unknown及历史保持。物理HTTP/模型被显式拦截；隔离UI使用既有合成测试Task，不声称完成新空任务入门或真实平台验收。命令和替身位于 `backend/tests/test_publication_recovery.py`、`backend/tests/test_publication_dispatch_receipt.py` 及 `tools/publication-recovery-ui352/`，既有Workflow/Chatflow发布定向回归保持。

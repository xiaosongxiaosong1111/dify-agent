# 自动规划修复的范围与本机修复

0.53.0 改进模型生成流程候选后的修复，不是 Dify 运行失败后的自动修复。

## 明确的小修复

Python 解析器明确报 expected ':' 时，Sierra 可在相应语句头插入一个冒号。保留原文其他内容和注释，插入后必须 AST 解析通过；比较全部操作符、标识符、字面量、语句、缩进边界和注释，仅允许该行多一个冒号。支持行尾注释、多行语句头和 CRLF，代码不执行。

这一步在本机完成并记录在 deterministic_fixes，不为补冒号追加模型请求。使用既有自动修复次数上限，max_retries=0 时关闭本机修复；批次格式归一化按一轮计。修复只改变未确认候选，仍须完整静态校验、配置确认、构建与真实验证。

同时存在其他语法问题、需要多个代码结构改变、无法确认插入位置等情况不猜测，保留候选并暂停，不花额外模型调用尝试歧义修复。JSON 格式修复仍按原有次数、时间、费用与未知用量约束运行；没有拓扑或资源依据时不能放宽验收来成功。

## 不能借修复改方案

原先仅比较关键字和字面量会漏掉标点、缩进或节点列表重排。现在有效 Python 代码须 AST 语义相同且注释保持；无效代码仅许可明确单冒号修复，不能把函数调用换成索引、改变切片／元组、移动返回语句到条件块或改资源常量。

顶层字段、节点属性／名称／顺序、连接、输入输出、模型／资源配置、循环／迭代政策与内部顺序均保持。未改动的 JavaScript 兄弟节点可保留，不阻止另一个 Python 小修复；JavaScript 内容本身不自动改。发现变化停止为需确认，候选保留、不自动应用。

修复记录区分循环内部与迭代内部。前端规划记录和上限设置说明本范围，不能把生成候选阶段的小修复称为完整运行自修复。

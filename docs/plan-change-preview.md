# 保存前查看流程变化（0.315）

流程页编辑器旁“查看保存前变化（只读）”比较当前后台保存计划和本次编辑原文。先核对变动，再使用原有“后台校验并保存计划”；预览不是保存、确认或执行批准，也不会改变原保存门禁。

Workflow／Chatflow按节点ID和所在容器身份匹配，展示新增、移除、更改、顺序变化、顶层连接及顶层方案字段变化。节点明细给保存位置→草稿位置（1基层次）、类型及提示词、代码、模型参数、知识检索等字段类别，不把配置值或客户原文复制到摘要。改变ID按删除和新增计；相同ID在不同容器仍是独立位置。最多列30项，其余数量明确；结构无效、重复ID或超出2000节点／21层范围时不冒充已有完整明细。Agent只列顶层字段类别与其它字段数量，不套用工作流节点图。

比较使用后台精确JSON值，单个计划原文最多2MB，拒绝重复键、非有限数、坏Unicode或非对象，不替用户修复。大整数在服务器比较，不经浏览器JSON数值转换；回执绑定任务、业务修订和本次原文UTF-8 SHA-256。修改草稿、切换任务/修订或离开流程页使旧预览失效。原文有坏语法时保留编辑，用户可修正后重新比较。

未保存的需求／配置不在此次范围内；这里只列确定性的变化类别，不决定语义影响，不编译计划、不执行代码、解密或联网。相同内容明确标识，已过期计划另行提示。若实际保存推进修订，配置确认、成果与App绑定需重新核对，旧试跑不会成为新修订通过；普通保存可沿用未变需求，逐项失败/汇总输出合同变更可能重新要求需求检查。最终以后端实际保存校验和确认规则为准，不能据预览推断“可以直接发布”。

`POST /api/tasks/{id}/plan/change-preview`只接收严格正整数`revision`和完整`plan_text`；无任务404、旧修订409、坏请求422，不回显请求正文。回执`saved_plan_sha256/draft_sha256`、`content_changed`、`saved_plan_stale`、`field_changes/other_field_changes`、`node_changes`及固定影响说明，明确`draft_change_categories_only/task_modified=false/network_requested=false/plan_validated=false`。比较后仍重新核业务修订，不把快照当实时订阅。

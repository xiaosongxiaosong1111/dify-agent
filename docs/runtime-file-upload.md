# 运行文件：明确方案与单次上传

0.150增加上传这一段；0.151的三节点TXT原生提取可另行准备并批准，详见[runtime-file-run.md](runtime-file-run.md)。通用复杂文件试跑尚未完成。运行页的“运行文件 · 上传方案”先主动读取最终文件入口及本机独立记录，用户明确选择变量和原文件，再仅在本机准备。根Workflow的file／file-list入口须允许local_file，custom后缀规则严格匹配；本批支持txt/md/csv/json/yaml/yml/pdf/docx、1字节—2,000,000字节，原内容不改名、不转换。file-list在此仍每次只上传一个文件，不自动启动列表运行；TXT列表须另行批准试跑。

原字节以base64经过本机API，直接保存在E盘后端加密存储，不走multipart临时落盘，不进入对话／模型／Task／版本／DSL／普通日志／浏览器持久存储。每任务最多5份待处理方案；方案审批30分钟内有效，这是本机批准时效，不是远端文件有效期。放弃未派发方案才清除本机密文正文；超时过期可查看并主动放弃，没有静默丢失进度。

具体方案展示文件名、字节、MIME、原字节SHA256、最终成果原字节哈希、修订、原Dify地址、App及影响。确认绑定最终文件、任务修订、环境地址／版本／App及加密服务凭据版本。用户核对内容与目标，明确同意后仅POST /v1/files/upload一次，user与现有运行适配器同为flowcraft-local；不创建／发布／覆盖App，不索引知识库，不执行工作流，不主动调用模型。平台存储、扫描、留存或费用由实际环境决定；服务Key真实归属、发布图及后续权限未在线证明，不把本机配置当平台验证。

请求前读取冻结服务Key，上传原始字节；不在中途换Key。单次尝试持久化后才派发；成功仅采纳有UUID、同名、相同字节数及创建人UUID的回执，远端ID／创建人保留在独立私有记录，签名URL／storage key等不保存或返回。没有远端内容哈希或有效期校验，不能宣称完整远端一致性。

切换页面或暂停Task不会撤回已派发上传。上传超时／异常／回执不可信／重启中断记为未知，禁止同方案重发，不自动删除远端文件。本机正文在尝试结束或启动恢复时清除；已知原目标及远端ID保留。上传中更换任务／环境／凭据等不将旧回执用于新上下文；观察回执后目标失效也保存已知远端ID。执行中阻止任务并发编辑，部署空闲检查覆盖上传。旧修订记录始终可读；独立资源总览及交付报告增加第7类文件单次上传，摘要不含正文或私有ID。

**上传成功仍不是自动运行批准。** 上传记录的runtime_reference_ready与business_verified为false；普通运行／模型样例依旧拒绝JSON文件ID／URL。0.151在独立TXT提取方案里核对归属、装配可信引用、冻结最终文件与凭据、保留列表顺序／数量，再明确批准一次运行；实际Dify验证及复杂文件流程仍未完成。可继续手动在Dify上传试跑；不得悄悄算作完整交付。

本次开发测试全部使用隔离替身，没有向真实Dify发送文件、创建App或调用付费模型。真实联调须另有具体文件、目标和次数的资源方案获批，旧单次授权不可复用。


0.151补充：上传本身仍不代表可运行；三节点TXT原生提取现可另行准备并批准单次试跑，核对真实Key归属、发布图、冻结文件与连接后派发。其他格式及复杂文件流程继续阻止。见[runtime-file-run.md](runtime-file-run.md)。独立资源总览现为8类；上述第7类指上传自身，不是最新类别总数。

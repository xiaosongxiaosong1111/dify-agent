# 已记录 Dify USD 报价阈值（0.68）

运行页可明确设置累计已记录 USD 报价阈值，0停止新启动、留空关闭。它与助手模型预算、Dify启动次数及耗时阈值分别计算，保存需要范围确认与原因，审计保留跨修订历史。

依据本任务已保存 Dify 返回报价，复用费用报告的身份绑定和去重，不把多个本机记录或同一次远端执行重复加价，不相加父子节点报价。明确执行身份、完整结果与币种为USD且金额已知才能证明该段报价记录完整；未知金额、其他币种、身份不足、结果未知、冲突或汇总截断时，启用阈值后不能证明剩余预算，阻止新启动，不按0计算、不换算币种、不自动解除策略。

**这是已记录报价达到阈值后的停止控制，不是供应商账单或下一批费用硬上限。** 首批／下一批费用无法提前保证，单次可能超过阈值，已派发操作不能取消；建库、工具隐含费用或未保存执行不在其中。Workflow整体报价目前通常未知，启用此阈值后已有这类未知记录会阻止新启动。应由用户决定核对、调整策略或保留停止，不能为了运行自动把未知当免费。

接口在原 `/execution-limits` 中新增严格文字或null字段 `max_reported_cost_usd`，有限非负金额最多1000000、最多12位小数。金额用Decimal比较，不用浮点预算。旧客户端省略此字段保留已保存策略，不能通过只修改次数悄悄解除新费用限制；明确null才关闭。策略版本冲突不覆盖，业务修订、凭据及旧运行不变。

实际新运行派发前在原 Store 锁内同时检查这些限制；0报价阈值已从正式运行接口用替身验证先拒绝，没有建立pending记录或调用远端。页面只保存策略，不试跑。开发检查采用隔离任务与内存页面拦截，无新增真实Dify应用／运行或供应商调用。完整费用硬预算仍是未完成项，不能据此宣称已覆盖全部费用。

# 已发布定时流程的明确启用（0.117，已部署）

用户主动只读核对当前任务的定时成果与目标App后，仅对唯一、明确停用的trigger-schedule准备具体启用方案。方案列明环境、App／Trigger／发布版本UUID、时区、原生visual频次参数及节点类型。准备只写本机方案，不请求Dify；执行必须接受该具体方案的持续运行与费用影响，批准绑定当前修订和方案哈希。

执行重新核对当前成果、需求／配置确认、目标环境、管理凭据，以及远端发布版本、核心图、完整features／environment_variables／conversation_variables和对应触发器。缺失配置字段、原生默认补充或秘密值遮罩均不能猜作相同，要求先读取实际DSL并复核；不猜选限流／未知／替换的触发记录；不发布、覆盖或创建应用。最多一次enable_trigger=true POST，前后最多四次GET；已经启用则只读返回，不重复写。操作结果与只读历史独立保存，不改任务成果和需求。处理或未知结果阻止另一个方案追加启用，启停处理中禁止并发写入。未知启用可以另行明确停用以降低持续运行影响，仍须新的具体停用确认。

启用后是持续平台调度，Sierra单次试跑预算不会限制后续定时模型、检索或接口费用。没有自动到期停用；停用只阻止未来轮询派发，不能取消已经入队或执行的请求。必须由用户核对应用使用权限及实际业务资源。这一功能不构成费用硬上限，也不代表平台实际执行和业务验收通过。

后续只读核对可以针对旧方案的原环境／原触发器；观察到已启用／停用不能归因原写入。重启只将处理中断标为未知或未派发，没有重放。公开返回字段白名单，不包含原图、管理凭据、原生响应或内部成果哈希。

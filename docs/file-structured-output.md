# 文档的模型结构化对象输出

目标Dify1.17.1／DSL0.7.0。适配四个根节点：开始（唯一必填单文件及明确普通参数）→文档提取→一个文字LLM→结束。由用户在LLM配置中明确启用结构化输出和完整根object Schema；结束仅一个输出，直接引用该LLM.structured_output，类型object。不替用户定义业务字段，也不猜JSON文字、嵌套属性、列表隐式拼接、容器或其他路径。六种后缀沿用逐文件解析披露；PDF／Word等仍不试跑。

准备Plan6／Flow5：从最终成果冻结模型、完整参数、全部原顺序提示词及其引用、逐文件转换、输出名和完整Schema。另提供Schema JSON文字保留大整数边界原文，浏览器展示不用舍入后的对象重建规则。旧文字Plan4／Flow3及可选纯提取Plan5／Flow4保持，旧授权不会自动扩展。需要与原文件模型相同的普通运行、内容出站及费用未知三项明确确认，不估成免费或金额硬上限。

运行仍须原Key唯一App归属及完整实际发布图／配置核对，只一次运行、不上传／发布／创建或自动重试。提取文字、问题和提示词会进入Dify所配模型，服务归属、留存及供应商内部重试未知须用户核对。Dify／插件可能修复JSON或改写Schema；本机检查不证明供应商原生严格支持、原文件文字完整或字段值真实。

返回须为真正JSON对象，完整核对闭合Schema（字段、类型、必填、额外字段、嵌套、枚举及数量范围等已支持子集）。最多64000字节、20000实例值，整数限±9007199254740991，不承诺小数金额精度。不把JSON文字／数组／null转换为对象，不删字段、补默认或修复使其通过。

同一运行／发布UUID明确成功但对象不合规时，方案与原记录保持未知／不自动重试；只保留安全编号和平台成功状态用于主动诊断，不保存不合规输出、文件对象或其他原始回执。符合Schema只是技术边界，自由运行无业务通过标记。固定文件样例可使用json_schema规则核对对象，规则必须明确用户预期。

固定样例对象预览／下载另要求唯一原Plan6、实际模型批准与一次派发、原修订／输入／环境／App／运行／发布绑定及当前已存对象再次通过原Schema；无证明拒绝，不展开任意历史对象。预览仍有64000字节界限与完整已存JSON的SHA256下载绑定；历史来源不继承当前业务验收。

准备期间再次有界读取成果原字节，若与文件证明的SHA256不同即拒绝，不把旧上传证明与新数据流混用。代码与隔离检查不等于真实Dify／模型或客户验收。

# 完整对象输出验收

0.146新增json_schema检查方式：用户在验收样例中选择“完整对象 Schema”，明确输出路径与Schema；支持首轮和每个追问轮次。保存时校对规则，自动生成候选也须符合相同契约。当前修订／环境／样例绑定、人工审核及同一实际会话规则不变。

expected可以是Schema对象或原JSON文字，编辑器保留原文与重复键，不用浏览器JSON.parse覆盖；保存时后台拒绝重复键及未适配关键字。支持闭合对象、嵌套、数组、标量类型、必填、枚举和范围；禁止ref／组合／正则／默认，Schema64000字节／200类型节点／8层／50属性。实际值为对象或严格JSON对象文字，拒绝Markdown／尾随文字／重复键／NaN等，不自动修复。值限64000 UTF-8字节、20000结构节点、整数±9007199254740991，不舍入或补默认。

例如字段count须integer、enabled须boolean；{count:true,enabled:0}即使含有两个键，也不能通过完整Schema。已有json_keys仍只证明键存在，equals语义未在本次改动。

结构通过只证明已声明规则；模型事实、语言质量、客户业务及Dify所有入口的强制规则仍需独立设计及验收。Schema检查发生在Sierra收到结果后，不防止已发生的远程副作用，不增加自动重试，不修改已确认工作流。失败仍纳入既有报告、摘要和复核流程；多轮自动规则失败后沿用停止后续调用的策略。

本次使用本机隔离夹具，无真实模型／Dify调用或客户数据出站。轻量路由数据类别仍是已保存样例预期，scope18保持，未自动升级费用或旧调用许可。

0.149诊断补强：不符合Schema时显示第一条规则位置（JSON Pointer转义），区分类型／枚举／范围／必填／额外字段等；不回实例值或未知额外字段名。严格JSON文字无法解析时明确说明完整对象／唯一键／有限值未通过，不猜具体原因或自动去Markdown；超大小与编码错误另有静态提示。运行记录和当前验收摘要保留失败，没有自动修复、补默认或重跑。actual/result仍按既有规则供用户查看，这里的“不回显”指诊断文字。

# 具体停用资源方案（0.115）

用户从本任务的已匹配、唯一且状态明确的调度观察准备方案。准备仅保存本机计划，列出原环境、App UUID、触发器UUID、入口、来源观察与当前批准修订、影响和最多一次停用尝试。仅显式approve_resource_plan及对应resource_token才能执行；错误任务／修订／令牌／启用字段拒绝。不是泛化授予资源操作许可，开发本功能不代表已批准任何实际App停用。

执行前只读核对原资源UUID／入口；已停用则无需写。否则最多一次POST trigger-enable且enable_trigger固定false，再只读核对。只操作明确目标，不猜选其他记录、不发布／启用／删除／覆盖App，不暂停或修改原Task及预算。观察来自旧修订或原环境时，新方案仍对应原资源，不将目标改到当前任务的新环境；原环境绑定变化拒绝。管理console／csrf凭据瞬时冻结，每次请求前后核对连接。

失败／超时／重启未知不重放写。同一资源已有executing/unknown/not_confirmed时不能从另一方案写入。后续reconcile只有GET：看到disabled可记为disabled_observed_later，明确不能归因原请求；仍enabled不清除未知以允许重试。停用不取消已入队／正在执行的请求，其费用可能继续，不能声称App全部执行立即停止。

UI先展示资源方案再勾选接受，结果不确定时禁止重复写，提供只读核对及本机已保存记录恢复。旧批准修订不能直接执行，重新准备仍针对它原观察。公开记录字段白名单，环境名不显示已保存秘密值，验证错误不回显输入。

本次16新增停用检查及7停用页面、7观察页面均为隔离：停用两次执行、原目标核对两次皆fixture，真实API写0／Task不变。并发两个方案仅一POST、原环境、读后仍启用不假通过、畸形核对不500、未知不重试及重启恢复有独立检查。构建主497.81KB／停用5.40KB／观察4.65KB。完整2315通过142.96秒，16新停用／82相关通过11.49秒；资源明细窄列视觉修复后页面再次通过，已部署0.115。详细证据见development-status.md。

# Sierra 单层并行迭代

0.21.0，2026-10-11。扩展 T112 的首批批量模式，未完成 T112—T114 全范围或 M5。

## 行为与确认

Workflow／Chatflow 单层 iteration 的内部仍为 1—12 个顺序 code／template-transform／LLM 节点；不同数组项可以并行。必须明确 `is_parallel=true`、整数 `parallel_nums` 2—10、`parallel_safe=true` 和 1—2000 字 `parallel_reason`，说明逐项独立、无顺序依赖以及共享状态／副作用条件。声明是人工复核要求，不证明任意代码安全或业务正确；没有依据时需继续追问，不能默改并行。

旧顺序配置继续使用 `is_parallel=false`，可显式给 `parallel_nums=1`；带其他并发数或并行声明字段会拒绝，不能静默忽略。任务已确认业务需求不因保存计划自动改变，但保存新计划推进修订、配置／产物／导入确认失效；用户仍须复核完整计划再确认配置。

两种模式均 `error_handle_mode=terminated`、`flatten_output=false`，输出选择最后内部节点的单值并汇总成数组，按原输入索引排列、保留重复项。某项失败使整批失败，不计部分成功；并行已经派发的项可能仍在执行，不能承诺立即取消或不产生后续费用。没有跳过／继续失败、自动中途恢复或整批自动重试。

并发增加速率限制与同时计费风险，当前累计助手预算仍不涵盖目标 Dify 的内部 LLM 执行。内部 LLM 每项使用任务模型和参数，不读取 Chatflow 历史；必要上下文须显式绑定。来源数组、类型、作用域、上游可用性、内部顺序和 ID 校验沿用已有合同。

## 界面和生成

流程页新增“填入并行批量样例”：只填草稿，示例为最多 100 个字符串、并发 3 的独立去空白／大写转换，不读写共享数据或调用外部接口。该 100 项限制属于示例代码，不是任意计划的硬批量上限。摘要显示并发数、独立性说明、失败及费用限制。模型提示合同新增对应字段与确认要求。

原生 DSL 只发 `is_parallel`、`parallel_nums` 等 Dify 字段，`parallel_safe`／`parallel_reason` 留在 Sierra 计划／报告，不注入原生节点。自动修复的 scope 比较禁止修改并发数、安全声明、原因或失败策略。参考 DSL 摘要能摘录源并发数，但不证明整个参考已复现。

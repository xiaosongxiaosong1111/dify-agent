# 可选单文件与存在分支

适配目标为 Dify 1.17.1 / DSL 0.7.0。0.162支持生成和保留；0.163增加下述精确五节点图的独立试跑方案，其他条件文件图仍明确受限。不能因有文件上传记录就沿用普通文件试跑批准。

在空白 Workflow 的“流程 → 文件流程起步”选择“可选单文件 · 缺失时返回说明”，明确允许后缀及无文件说明，主动填入草稿。模板不覆盖现有计划、人工编辑、源 DSL、成果或导入应用，不修改需求确认，不调用模型或 Dify。

模板包含可选单文件 `document`，以及有明确默认值的可选文字参数 `missing_message`。无文件说明须明确填写，最多2000字符；应用输入可以覆盖该文字参数，省略或 null 则由 Dify 使用默认值。两条路径分别为：

- `exists` 分支：提取文档文字，结束返回 `result`。
- 缺失分支：不进入提取，结束返回说明参数，输出仍为 `result`。

单文件使用原生 `exists / not exists`，含义为非 null／null，不是文件格式、归属、存储权限、有效期或内容真实性检查。文件列表的 `empty / not empty` 是另一组运算；本批可选文件列表仍未适配，必填列表可为空的既有规则保持。

后台只证明明确的独立存在判断：根 IF 恰有一个 case、一个相同根文件变量的条件。`exists` 的匹配出口，或 `not exists` 的 false 出口，必须是到达提取节点的必要连接。缺失路径绕回提取、两出口合并到提取、多 case／多条件或容器内推断都会被拒绝。条件编辑只改所选字段，不自动交换连接；改变运算后需重新核对出口和业务行为。

原生捕获和手改保留会核对必要连接，再投影为 IR。相关开始、判断、提取、结束节点只适配原生版本1；未知版本、额外执行／旧条件字段及未适配重试／异常默认不能被省略后当成保护已成立。人工标题、说明、默认值和两个出口保持。

锁定源码辅助核对区分了缺字段经入口处理形成的 None、完全不存在的变量、空字符串和空对象。辅助函数结果不等于完整 Dify 平台运行；Sierra 不会据此把 `{}` 或原生文件 ID 当作可信文件，也不自动规范化未适配输入。实际缺失／提供文件两条路径仍待目标环境的具体方案与真实验证。


0.163条件试跑（尚待真实平台验收）：保存成果并绑定目标后，在“运行 → 带文件试跑”填写完整JSON。`{}` 与 `{"document":null}` 都可表示没有文件，二者原样保留且固定样例严格区分；不自动上传、造文件或删除存在分支。有文件须使用当前可信上传引用，空串／空对象／错误引用不降级为缺失。

新方案仅适配五根节点、四条连接的上述精确图，无其他模型／HTTP／代码／容器或隐含上下文；无文件说明参数须明确默认值及1—2000字符上限。普通文字或null按Dify默认语义处理，明确空串保留为空，不修剪／清洗NUL或坏编码。方案版本5／数据流版本4冻结两条路径、当前输入状态、预计经过与跳过节点及当前说明，静态预计不等于真实轨迹。必须另勾选分支确认及普通运行确认；重新准备或改输入清除旧同意。旧普通路线版本4／3保持，旧授权不会被扩大。

执行前仍读取Key归属和完整发布图／配置，最多两次管理读取及一次Workflow运行，不创建／发布／重试。结果须来自同一发布／运行UUID且明确成功；缺失路径还须精确返回冻结说明，不匹配记未知。完整提取路径也核对，不能只绑定本次选择。固定样例的缺文件模板可本机匹配成0文件位置的完整输入，再明确采纳；有文件样例仍需当前可信指纹匹配。规则通过不是完整业务验收，真实两条路径仍待获准目标环境执行。


0.164增加“固定文件验收样例 → 从最终DSL读取文件分支场景”。仅读当前修订最终成果原字节并冻结SHA256，不要求管理／运行凭据，不读取实际文件／输入／输出，不保存样例或请求模型／Dify。精确五节点图且全部声明后缀属于上述六种才提供完整建议，否则报明确范围限制，不截掉其他行为。

建议列出三种场景：省略文件字段、明确null、有文件。前两项按配置默认说明给出equals规则，明确只是配置规则而非客户业务正确；有文件项缺真实引用和业务规则，只说明待补条件，不造文件或采用默认人工通过。采用按钮只在本次输入为{}、未编辑样例且名称／规则／必选项仍为初始状态时可用；用户主动采用仅填未保存草稿，随后仍须主动保存和单次批准。旧输入、名称、规则及已有样例均不覆盖。

接口：`GET /api/tasks/{id}/optional-file-case-templates?revision=当前修订`。读取期间修订／最终字节变化拒绝使用旧建议；无最终成果不读旧草稿，Chatflow不转换类型。


0.165在普通运行的“读取Dify节点轨迹并诊断”中，复用原有读取结果核对原可选文件方案，不额外请求平台。只找同任务／原运行唯一Plan5，须有独立分支批准与一次派发、原输入／修订／目标一致、保存的原运行及发布UUID关联，并以实际执行核心图摘要匹配原完整两路图。Dify1.17.1详情不暴露workflow_id，不凭空要求或声称从详情得到它；发布关联来自原保存回执。当前发布／成果来源仍独立展示，旧修订不能变成当前修复证据。

节点列表须为已适配无分页data形状、非截断、无重复根节点，原生总步骤数为明确整数且与完整轨迹数量一致，远端及各节点明确成功、类型与原图一致。未知分页、缺步骤数、重复／失败／类型不符或来源不足都显示证据不足；只有完整采集后才比较预计与实际节点集合，差异列出未观察到和分支外节点。比较不证明执行时间顺序、文件文字完整或业务正确，不修改原计划静态预计标记／运行／验收，不改DSL或重跑。摘要随原诊断进入交付报告，未复制文件、参数、输出或原图。

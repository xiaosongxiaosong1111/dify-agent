# 每项内部条件分支与聚合

版本 0.29.0。单层迭代可以在每项内部按条件走不同处理路径，再汇入一个共同输出节点。原顺序体接口保持兼容；并行仍需要明确并发数、逐项独立性及副作用条件，不因内部图而默认开启。

## 计划契约

config 同时提供 entry_node_id 和 edges 时采用内部 DAG：entry_node_id 必须为实际处理入口，不能有内部入边；edges 为 1—48 条仅引用本容器处理节点的连接，每条包含 source、target、可选 source_handle。内部开始节点由编译器生成，不能在 IR 里引用或占用其 ID。nodes 仍为 1—12 项，允许代码、模板、文字 LLM、条件和无分组变量聚合。没有 edges／entry_node_id 的顺序体仍按 nodes 列表顺序处理。

条件出口必须覆盖每个 case 和 false，不允许循环、重复连接、未知出口或跨容器连线。每个内部节点都须可从入口到达并能到达同一个输出终点；output_selector 选择没有内部出边的共同节点声明的 string／number／object 输出，汇总数组类型必须一致。内部 DAG 的节点数组排列、位置不代表执行顺序。编译器输出实际内部连接和分支句柄，分层布局给同层分支不同位置。

item／index 仅在本项可用；外部值必须来自容器之前的必经节点。普通内部节点不能读取不保证存在的兄弟分支输出，只有聚合节点按已有候选值的优先顺序汇合，空字符串不自动跳过。内部聚合仅允许内部处理节点的已声明输出；禁止把用于检查的作用域占位变量当成 item、index、外部 object／number 的真实类型证明。确需聚合这类值时，先用明确输出类型的代码／模板转换节点。

## 使用与限制

流程页“填入逐项条件样例”只填写草稿。技术样例将最多100个字符串中的非空项去空白并转大写，空字符串生成包含原索引的提示，随后聚合。空字符串与只含空白的字符串按原条件区分，规则为建议，需按业务复核后确认；不是已执行结果。点击迭代父节点可预览内部条件与连接，再点击内部节点查看草稿配置。

LLM 可用独立或继承模型，内部不读取 Chatflow 历史。失败仍终止整批；输出按输入索引保留重复项。Dify 已派发的并行项可能继续，不能保证即时取消；费用仍无全任务硬上限。

不支持嵌套、一般循环、内部 HTTP／检索／人工节点、失败后跳过／继续，以及并行项内部图的人工修改保留。保留阶段完整保存源文件并阻止采用，不删除分支后算通过。0.30.0 已扩展顺序逐项内部条件／聚合图手改保留，见 iteration-graph-preservation.md。

本机 Dify 已安装 graphon 的 iteration_container_handler 源码显示：每项从父帧深复制变量池并绑定 item／index，读取子帧的指定输出后按索引汇总；源码核对不是整图运行验收。不能从实体解析或本机静态检查推断全部实际分支已跑通。本批不创建 Dify 应用、不调用模型、不执行生成代码。

后台静态、受控页面与原生结构证据以 development-status.md 的实际记录为准，测试入口 backend/tests/test_iteration_branches.py。

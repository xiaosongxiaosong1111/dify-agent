# 条件分支编辑与生成契约

0.48.0 面向 Workflow／Chatflow 的 IF／ELIF／ELSE 配置。用户修改进入现有草稿，保存会校验并使相关配置、构建和运行确认失效；不自动发布或重跑。

## 页面行为

顶层及单层迭代／循环条件节点可逐项编辑来源节点、输出字段、声明类型、比较运算、比较值与 AND／OR。卡片显示每个分支的实际出口及 false 默认出口，要求把边界和无匹配行为纳入验收。

简易编辑提供文字、数值和布尔条件。数值比较右值填写文本，布尔右值须明确选 true／false；类型变化保留原运算和值并提示核对，不隐式转换。空／空值运算保留旧右值，切换回来须再次核对。原生空值标识使用 null／not null，区别于前端曾有的 is null／is not null 别名。

页面不新增、删除、重排分支或修改连线。复杂条件、数组／文件／嵌套／变量右值模式、结构异常通过条件 JSON／高级 JSON 原样查看编辑，不自动简化。无法解析的 JSON 保留文字，交给后台拒绝，不回退或补空条件。超过显示范围不截断原文。可信当前 IF 诊断可定位对应卡片，来源不匹配、旧修订及未存编辑的保护沿用 0.47。

## 后台边界

- config 仅 cases；case 仅 case_id、logical_operator、conditions；condition 仅可选 id、variable_selector、varType、comparison_operator、value。未适配字段明确拒绝，不能丢弃嵌套、文件属性等字段后算作完成。
- 最多 32 个分支、每分支 64 个条件；分支标识、完整条件、唯一出口和可达／支配检查沿用原规则。
- 操作符依据本机 Dify 1.17.1 的 graphon/utils/condition/entities.py。null／not null 可以发出；is null／is not null 拒绝，不擅自更改已确认方案。
- value 限文字、文字数组、明确布尔值或 null。数值必须用有限数值文本；拒绝未加引号数字，避免原生联合类型把 0／1 转成布尔值。文字、数值、布尔运算检查与标量声明相容；布尔文字不自动转布尔，in／not in 的文字右值须为文字数组。
- 条件右值模板同样检查实际来源存在、输出字段和所有路径可用性。数值／布尔变量右值须完整单模板，不能拼接文字；实际展开值仍需运行验证。
- 有可靠声明时，varType 必须与来源一致。循环状态、迭代 item／index 和外部绑定使用内部传递的声明类型，不把临时校验输入一律当成文字。右值模板只在临时校验投影中改引用，原方案和最终原生模板保留；调用方 JSON 无法传入内部类型覆盖。

这些约束不证明完整数组／文件比较语义或动态输入值正确，也不代替真实运行。复杂条件不在当前平面 IR 的适配范围；需要明确协商方案，不能静默省略。

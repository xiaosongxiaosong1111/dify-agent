# 轻量建议的单次升级设计（0.317首批已实现，默认关闭）

使用与实际验证见[单次升级说明](lightweight-upgrade.md)。本文件保留设计范围，不是生产启用或真实模型验收证明。

对应FR-47/T126。现有路由只把`cases`验收建议交给所选轻量服务；默认失败即停，旧策略、旧失败包、未知费用和原任务均保持。此开发不派发真实模型/Dify，不修改生产路由。

首批只适配**已明确选择该新策略后的新建议操作**：轻量服务一次返回内容无法解析成JSON对象，且有可用的最终输入/输出用量，允许把原始有限上下文交给已固定的任务主模型一次。两次都最多6000输出tokens、120秒且受同一轮总时间/费用估算与同一任务累计账本约束，总HTTP最多2；全局`max_retries`为0则不派发此策略。两阶段不再各自追加修复调用。

网络错误、超时、缺/坏用量、资源或业务问题、模型`error`/需裁定、有效JSON但样例校验失败、暂停/修订变化、配置/路由/预算失效都不升级。旧失败不从恢复或读取入口重放；每次建议仍是用户主动启动的新操作。不是通用失败升级或供应商账单硬封顶。

新策略默认关闭，不借默认路由批准：需独立明确确认一次升级范围/两次调用上界，固定升级范围版本、主模型ID和配置指纹；主/轻量配置或任务主模型选择变化后失效，不自动找替代服务。确认只是保存策略，不执行模型。关闭时清除升级选择，旧路由的确认历史完整保留，不扩大发送数据内容。

执行分阶段记录实际模型/指纹、升级原因、原失败、尝试数、用量与估算。父操作总量汇总两阶段，最终候选来源记录实际主模型；首次轻量无效响应仍保留。第二阶段使用原始已确认发送上下文，不把无效模型正文作为新需求。累计预算沿用TaskBudget每次独立预留/结算，不清unknown、不借旧槽；第一阶段未知绝不自动第二次。主阶段预留前扣除已知第一阶段费用/耗时，超限不派发。

本机验收要求：默认旧行为/旧严格路由快照兼容；正常轻量成功1次、符合单一升级条件时最多2次且来源与两账本entry正确；无主模型/同模型/旧指纹/缺价格/未确认/零重试均在出站前拒绝；业务/资源/解析后校验失败、未知用量、暂停/修订及预算/时间阻止额外调用；主失败不再追加；不自动采纳样例或运行。UI须可看两模型与上界、明确启用并保留未存草稿，测试全部使用隔离替身。完整范围以最终实现与实际回执为准，当前文档不是验收通过或生产策略启用证明。

# 提取状态与数组诊断（0.66）

读取 Dify 节点轨迹时，对参数提取节点仅保留原生 `__is_success` 的明确数字0/1状态，不保存业务参数、`__reason`、输入或原输出。输出缺失、字符串形式、截断标识、异常格式、布尔值或其他数值均为未知，不转换、不计成功。

节点执行状态为 succeeded 而标识为0时，显示“节点执行完成，但参数未提取成功”。这可能正好触发已经确认的追问或失败分支，不能据此把已通过的业务样例改判失败。标识1仍不证明参数非空、格式正确或真实。观察只提供证据和下一步建议，不修改运行状态、验收、方案或确认，不启动修复／重跑。

数组节点的原生序号越界、非数组来源或不兼容筛选错误提供对应配置建议，要求核对筛后序号、声明类型及已确认规则，不自动换首项、强转数据或删除操作。只在对应节点类型和明确错误特征下归因。

可信当前来源诊断可定位提取、分类及数组配置卡；历史、来源不匹配、有未存草稿或当前成果不符时不提供有效编辑定位。提取／分类卡已接入共用定位容器，修复此前点击后找不到卡片的问题。数组处理有独立定位分区，不猜到其他模型卡。

适配依据是本机锁定版本的原生节点输出与控制台 WorkflowRunNodeExecutionResponse.outputs_dict 字段。开发验证为隔离轨迹、替身远端读取及受控页面，未对新增业务发起真实 Dify 运行或付费模型请求。原来的输出不回显与来源／脱敏门禁仍保持；固定提取标识是唯一新增输出观察。

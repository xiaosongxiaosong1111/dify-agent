# 模型基础测试的配置归属（0.314）

“测试连接”和“JSON输出测试”针对派发时读取的模型配置。旧实现等模型返回后整份写回旧模型对象，另一页面在途改配置会被回滚，删除后甚至恢复旧记录；JSON失败也存在旧对象写回问题。

现在当前界面在请求中携带`expected_configuration_revision`，旧基准在派发前409拒绝；字段为严格非负整数，不接受null/布尔/字符串，未知字段422。旧客户端不传正文或传空对象仍可测试。基准不是凭据，不写入模型配置。

后台在本机Store锁内读取保存配置与密钥，在锁外等待模型，返回后再锁内核对配置身份及修订。API的配置创建／编辑／删除也参与同一锁。来源相同只合并本次文本或JSON能力及检查记录，保留其它同时完成的能力核对，不再写回旧对象。更换密钥、模型、地址、单价或其它导致配置修订变化的编辑均使旧回执不适用于当前配置；删除不会恢复。

测试已派发而配置变化时返回200，并明确`current_source=false/result_applied=false`；`ok`仅描述旧配置本次观察。保留原配置修订、延时与服务报告用量，界面显示“旧配置结果，未确认当前能力”，不以旧绿卡替代当前状态。正常成功返回`current_source=true/result_applied=true`；正常JSON失败仍502，文本失败仍不改能力。JSON固定对象也拒绝重复字段，不能把`{"ok":false,"ok":true}`当成严格通过。

此处仍是既有基础测试：文本调用和单个JSON对象不是工具、图片、严格JSON Schema或一般业务质量验收。没有自动重发、切换模型、升级或新付费批授权。基础测试回执仅在本页面显示，尚无持久独立回执／幂等／费用账本；超时后不能凭界面结果认定零调用或免费。锁限本机单服务进程，数据库外直接改写及多服务进程不据此承诺。工具请求测试原有独立回执路线保持。

## 验证

旧版先复现修改／删除后的旧对象写回、并行能力丢失；严格前置门禁缺失也触发禁止出站替身，未发真实HTTP。新18项及相关81项后端分组通过，界面7项覆盖文本成功/JSON成功或失败在途修改、仅密钥旋转、删除、正常文本与JSON恢复，全部采用隔离替身。每次UI请求都携带配置基准，无自动重试或凭据回显，原16及旧账本受保护；未跑全量。

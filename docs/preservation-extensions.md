# HTTP 与变量聚合的手动修改保留

0.24.0，2026-10-11。在已有三方保留中新增明确无认证、无文件请求体的 HTTP 与无分组变量聚合。合并保持原生字段、候选顺序、请求配置和布局，源应用不被覆盖；实际导入仍只新建应用并沿用明确确认门禁。

HTTP 须明确 authorization={type:no-auth,config:null}。转换器使用原方法、URL、headers、params、body、timeout 和变量绑定做已适配校验；原文件中的重试／SSL 等其他原生字段保持原值，但不宣称其业务行为全部验证。认证、文件体、未知分组和复杂容器不删除后通过。

HTTP 地址、头、参数和递归请求体中的模板引用须是已支持的两段选择器，属于保证可用的上游；直接／嵌套 value_selector 同样检查。来自互斥兄弟分支的引用被拒绝，须先明确汇合。畸形模板、超出结构限额或循环／共享结构不能当作有效引用。已知凭据头、URL 用户密码和凭据参数在 DSL 读取阶段就拒绝，不写入参考记录；错误不回显密钥值。自由文本的全部秘密并不因此保证可识别，仍应无密钥导出。

无分组聚合将原生 variables、output_type 映射回首个存在变量策略，保留候选优先级；分组启用则拒绝。类型与所有到达路径的来源检查沿用 0.23.0，普通变量规则不放宽。静态保留不是已运行、接口可达或客户验收。

新增 **22 项后台检查**，覆盖实际 capture → merge → confirm → build API 路径，结果与原手改文件结构摘要完全一致；检验请求模板的分支隔离、类型／路径／分组、认证／文件体拒绝，以及读取前的凭据拒绝。另有 4 项受控页面检查通过、前端构建通过；所有浏览器写请求拦截，不修改用户实际任务。证据 `work/preservation-extensions-ui-result.json`／`.png`。

技术 HTTP 节点通过本机 Dify 1.17.1 原生实体解析（post、no-auth、json），没有发送请求，见 `work/http-native-result.json`。本轮没有 Dify 写入、模型费用或业务接口访问。最终全量结果以 development-status.md 为准；迭代／原生包／复杂节点保留与运行验证仍未完成。

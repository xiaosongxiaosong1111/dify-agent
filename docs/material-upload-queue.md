# 多材料逐份上传（0.329）

上传入口支持本页一次选择1—10份材料，合计最多50MB、单份仍为原20MB。先检查整批本机数量和大小，超限一份也不上传，不截断文件。之后逐份调用原本机上传/解析服务，显示每份材料ID、保存修订、已提取文字或待补充可读文字；不把保存成功当理解/业务已通过。待补文字保留原件，不阻止后面正常文件保存。

可明确停止后续上传；本份已派发请求仍可能完成并保存，后续文件保持未派发。请求失败或结果无法核对时整队列停止，不自动重传，已经保存的材料/版本不回滚；先核对原任务，不因响应中断推断没有保存。切换任务或当前来源修订变化也不继续剩余文件，旧回执不覆盖新工作区。处理时不能再选择重叠队列。每份独立推进修订并使原确认失效，不是整批数据库事务。

新界面逐份发送multipart expected_revision，服务在初始和登记前核对Task修订/空闲状态；前提变化拒绝并仅清理本次新建、尚未登记的随机原件。不会删除已登记/历史原件；数据库写入失败等未知情况不盲删文件。旧不携带修订的单文件客户端保留兼容，原提交锁内重新读取当前Task的行为也保留，不宣称旧API都具有来源前提或幂等。新队列不自动恢复/重放，记录只在本页；刷新后从任务材料与历史版本核对。

仅本机上传/解析，不调用模型、Dify或知识库，不改变原20MB/10万字及Word包/PDF范围规则。新11/相关76后端（合计87）、新UI7/原引用UI8与构建通过，未全量；原16/旧账本密文主Key/124保护，真实外部0。覆盖旧兼容、坏/陈旧修订、提交前变源/忙状态及未登记原件清理，三份顺序/未解析、整批数量大小限制、停止、第二份HTTP失败及切任务不续发。首轮Playwright内存文件总量50MB限制阻断夹具，改用浏览器DataTransfer模拟超限选择后通过，原失败日志保留。

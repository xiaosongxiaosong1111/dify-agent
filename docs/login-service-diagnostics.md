# 登录服务故障诊断（0.270）

第88批实际重连返回HTTP502，旧适配器统一记录为 `login_rejected`。502无法证明密码错误，也不等于连接根本未建立。原批次和原回执保持失败，不重放、不回填新分类。

0.270将登录POST的HTTP500–599单独标为 `login_service_error`。界面通过现有诊断组件显示服务端故障、原HTTP状态，以及先核对Dify服务和反向代理的下一步。401/403或成功HTTP内明确失败结果仍保留 `login_rejected`，不改变原认证合同。

仅诊断改变。失败仍暂停自动登录；明确重连的已尝试方案不能再次提交；没有内置重试、其他账号、原业务操作重放或新令牌提交。密码、响应正文和Cookie均不进入诊断。原工作空间、密文与其他Key保持。

78项定向检查通过：500/502/503、401/403、自动登录失败后再次请求不再登录、明确重连的一次登录/重复确认409、安全API诊断、旧空间与凭据保护及相关既有回归。固定安全故障对象的只读界面6项通过，未登录或写入。前端无源码变化，无需重建。部署快照 `0.270.0-293ea298357356cf04db` 与源码一致，只有后端dify.py、console_failures.py、main.py变化；生产15任务/全部对象/密文/主Key/旧失败成功回执保持。[结果](login-service-diagnostics-result-20261024.json)。

这些是隔离故障响应验证，没有再次触发本机Dify真实故障，也不宣称某次历史502的具体根因或密码正确性。

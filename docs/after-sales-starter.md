# 售后问答与模拟订单草稿（0.279）

此前空白Chatflow需要通过模型规划或手工拼接节点，已有基础线性草稿不能表达售后分支。现在流程页可显式准备一个固定范围的17节点草稿：

- 不明确诉求：固定澄清回复。
- 资料问答：检索已保存知识库，结果非空才进入仅按检索上下文回答的LLM；无命中进入固定回复，资料不足时提示词要求同一固定回复。
- 订单查询：提取用户明确给出的文字订单号，核对原生提取成功标识后才进入合成订单查询；提取失败进入固定追问。查询输出始终标记模拟、非真实订单。

这些是静态结构和提示词安排，不证明分类、提取、检索相关性或回答质量。非空检索结果不保证资料相关；技术失败仍可能终止，不承诺所有异常转人工。

使用步骤：

1. 在空白Chatflow任务中保存模型、目标知识库ID、检索参数和已明确接受的订单模拟依赖。草稿不选择新模型、不编造资源ID或创建知识库。
2. 流程页打开“售后问答与模拟订单分支草稿”，选择已声明依赖，填写1—10个合成订单号及说明，明确三项固定回复并勾选范围。
3. 准备预览，查看完整节点、连接、代码及静态提示。输入变动会使旧预览及勾选失效；已有计划、来源DSL、成果、App或非空编辑不允许替换。
4. 主动放入未保存编辑器。需求、配置及任务尚未改写；核对其它未覆盖需求后，通过原入口校验保存，来源为manual，重新确认配置并构建下载。
5. 保存后在配置页核对模拟依赖位置；本草稿的订单代码节点为order_lookup，真实接口接入、参数替换和重新验证仍需明确安排，不自动改写原位置绑定。额外依赖和需求不会被此模板自动实现。

复用当前模型和知识库配置，分类/提取/资料回答都继承所选模型参数。预览不调用模型、不执行代码、不解密、不写任务或预算、不访问Dify。未来真实运行会按路径调用模型和检索，可能收费；导入、发布、Key和运行仍走原资源及费用门禁。不会消费旧失败批次或自动扩大授权。

后台将输入、任务修订、请求nonce和返回完整图摘要绑定；前端核对类型/摘要，只有主动采用才填草稿。固定回复不支持模板表达式，文本逐字保留；合成表复用既有订单模板的重复键、类型、数量及凭据检查，不接收客户资料或密钥。

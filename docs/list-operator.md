# 数组处理（0.65）

顶层 Workflow／Chatflow 支持 Dify 原生 `list-operator`：明确声明的文字、数字、布尔数组可以筛选、排序、按序号提取及数量截取。不会为这些内置操作生成额外代码或调用模型；上下游节点仍可能调用付费服务。

配置包括 `variable=[上游ID,字段]`、Sierra 类型声明 `input_type` 和四个完整原生设置 `filter_by/order_by/extract_by/limit`。类型必须与上游明确声明一致，未知类型不猜，不把对象、文件或文字转换成数组。输入类型元数据不写成虚构的 Dify 字段。

原生顺序固定为筛选、筛后序号提取、排序、数量截取。条件是 AND。文字仅支持包含／不包含、前缀／后缀、相等／不等、空／非空的字面值，暂不支持 `in` 子串歧义或动态模板。数字需要有限字面数字字符串和原生比较符；布尔需要实际布尔值。标量的 key 明确为空。文字排序按字符顺序，布尔 False 在 True 前，不声称按中文拼音或业务优先级排序。

序号从1开始，只能是1—10000的字面字符串，发生在排序之前。非空数组序号越界会失败；空数组仍为空，不替换为默认首项。数量为0明确返回空数组；启用时范围0—10000，禁止原生-1产生截尾。只有明确关闭时可保留原生-1哨兵。

首批仅允许引用 `result` 数组；原生 `first_record/last_record` 在空数组时可能为 null，暂不能当作非空标量使用。对象／文件数组、动态条件和嵌套容器不在本次支持范围，须说明替代方案并获得确认，不能悄悄删除后宣称完成。结果数组可接已支持类型的迭代、终点等，仍需满足所有路径上游及提取成功保护。

流程页有专门配置卡，只写当前未确认草稿，不移动连接或默选来源。无效JSON保留原文。实际 DSL 的来源、筛选、排序、提取、截取与布局可经确认合并、构建后保留原文件；输入类型仅从实际上游声明作虚拟推导，处理链不依赖节点数组排列。不会重编译整份保留文件。

验收建议取得最终保留文件中的实际字段，轻量路由数据范围升级8，旧7/6等必须重新确认，未确认前不派发、不回退主模型。范围扩大不代表获得开发联调的数据出站授权。

验证：隔离后台生成及实际往返、错误／未知类型拒绝、旧范围拒绝；本机 Dify 原生 DTO 和5个内置纯数组函数通过。原生函数核对没有创建、发布或执行完整应用；真实整图仍待具体资源方案批准后验证。没有执行生成代码或调用付费模型。

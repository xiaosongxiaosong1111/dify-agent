# 文件列表逐项处理

0.138 将根 Workflow 明确的必填 file-list 接入 array[file] 迭代。它与原有 HTTP.files 来源并存，不转换应用类型、不把代码返回的对象当文件。0.137文件入口开发与本功能一起发布，0.137没有单独部署。

## 配置与原生行为

明确 iterator_selector=[开始节点ID,文件列表变量]、iterator_input_type=array[file]。开始变量仍需符合文件入口完整规则。逐项文档提取的来源仅该迭代自己的 item，input_type=file，empty_policy=fail_if_missing；原生 is_array_file=false，text为字符串。不能跨容器直接接根数组、索引、伪造file声明或信任标记。原始文件item直接传提示词／模板／代码也明确拒绝，文件元数据处理未适配。

提取后可使用现有支持的文字模型／代码／模板，或条件分支、共同终点聚合。任一文件获取／解析失败仍使整批失败，不跳过、不计部分成功；空文字需用户明确分支，空列表保留为空输出。按输入索引保留顺序及重复项。

执行方式不代选：顺序或并行须明确；并行需2—10并发数及逐项独立的声明／理由，失败后已派发项可能继续，不保证取消。并发数与文件数都不是费用硬上限。扫描件 OCR、解析服务及文件出站／格式／权限条件仍需明确。

前端迭代来源可选根文件列表；正文文档提取可选自己的文件item。撤销必填／改成单文件会撤销候选，保留原selector等待用户修正，不换来源。切并行不代填并发或独立性，不重建正文或连线。

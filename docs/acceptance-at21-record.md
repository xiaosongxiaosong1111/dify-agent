## 现状核对

- `execution_limits.py` 累计本任务所有修订的运行启动次数与已记录请求耗时，可配置 USD 报价阈值。失败和未知运行不忽略；启用对应阈值时，未知耗时／报价不能按零处理。策略单独版本化并保留调整原因，不改变业务修订或清空历史。
- `main.py` 在落库运行记录、派发请求前检查上限，再检查 `failure_watch.py`。同环境、完整相同输入／样例、可信轨迹且失败节点和摘要相同的连续两次运行，暂停匹配输入的运行和该失败的模型候选请求。它比较已保存证据，不判断语义根因；暂停不一定将任务总状态改成 `paused`。
- 失败组提供运行 ID、节点、分类及下一步选项：核对后试跑一次、请求一次模型候选、先改方案／补条件。决定绑定当前修订和证据 token，持久保存，只能消费一次。继续许可不能绕过运行阈值和其他确认门禁；改方案或模型候选许可不能直接放行试跑。
- `model_repairs.py` 在创建模型请求／预算调用前检查重复失败；`execution_report.py` 导出阈值、用量、阻断原因、失败组和决定摘要，明确标记为保存的控制快照，不是业务验收证明。

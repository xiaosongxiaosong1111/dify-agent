# 新定时应用发布与停用核对（0.124，已部署）

新增专用的具体资源准备、独立批准、新App导入／发布、原触发器单次停用尝试与原目标只读核对。通用定时导入／手动试跑仍受限制；不能用手动运行冒充自然定时成功。真实平台和客户业务尚未验收，T115没有整体完成。

## 首批范围

只支持已确认的Dify 1.17.1三节点Workflow：唯一visual定时入口 → 无变量／表达式的固定文字模板 → 输出唯一result文字的终点，两条明确直连。使用原UTC／Asia/Shanghai及小时／日／周／月配置，不补默认时区或时间。模型、知识库、HTTP、代码、文件、通知、依赖、容器、人审、动态模板、额外变量／特性／输出明确拒绝，不静默移除。

方案冻结修订、准入和确认、原环境、原字节hash、完整出站DSL、核心图与完整特性／变量摘要、时区／频次及固定输出。识别解码后的当前已保存凭据，YAML转义不能绕过检查；人工方案同步补齐相同保护。不声称发现所有未知秘密。

## 发布可能激活

对照本机固定版源代码：update_app_triggers_when_app_published_workflow_updated.py为新触发器设置ENABLED；sync_workflow_schedule_when_app_published.py创建schedule plan并计算下一轮时间。因此发布可能直接开始调度，不能承诺发布时保持停用。

用户分别接受具体资源和可能激活／费用影响后，最多新建App一次、发布一次、停用原新App唯一触发器一次，无Key或手动run。主发布上限180秒；已经尝试发布且有可信新App ID时，成功或失败均以原冻结连接进行独立60秒内的停用核对，总计240秒、最多5次平台只读。发布到停用间可能已有派发；停用失败可能持续调度，已入队不能取消，宿主费用未知，Sierra试跑预算不约束后续调度。

每写之前持久记录一次尝试。新导入不传旧App ID，要求明确completed，不自动接受兼容警告。发布核对实际UUID、完整核心图及特性／环境／会话变量，缺失、默认补充或秘密遮罩不猜相等。停用只选择原新App的原入口唯一可信触发器；限流、重复、缺失、未知或ID改变不猜其它目标，不重复停用。需求变更不取消已批准的原独立停用尝试；原环境／凭据改变则不能改用新连接，需人工处理。

只有完整发布匹配且读取看到原触发器disabled，才标published_and_disabled；停止但发布核对失败为stopped_unverified_publication，停用不确认为stop_not_confirmed。未知或处理中不能另建一套资源。中断恢复不重放、不自动停用／删除，保留已知App与尝试，明确可能继续调度。

## 后续核对

用户主动只读原发布图和触发器，两次GET、60秒；绑定原环境，不因当前任务改了环境而查询新连接。地址、凭据或记录变化不保存旧读取。后续disabled可记录disabled_observed_later，不能归因原停用请求，核心图匹配也不等于自然运行、送达或业务通过。原环境地址改变时提示在原Dify按原App／Trigger核对。

历史只查看和原目标读取，不恢复旧批准直接执行。不覆盖任务已有App，不创建运行Key；持续启用需使用已有观察／启用功能另行确认。

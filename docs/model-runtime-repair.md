# 模型辅助纯计算代码修复

0.58.0 在本机修复工作台增加模型代码候选路线。固定规则不适用时，可对当前来源明确失败的 1—4 个 Python 纯计算节点生成完整代码候选；不自动采纳、发布或试跑。

## 用户操作

1. 在当前失败记录中读取可信完整轨迹，再展开“固定规则不适用？生成模型代码候选”。
2. 点击预览发送内容与费用。此步骤不调用模型，展示配置的主模型名称、型号、地址、单价、费用预留、本轮费用和时间上限以及本源调用次数。
3. 检查完整业务内容。发送目标、规则、输出／异常要求、失败节点原代码及输入绑定／输出声明、固定错误类别。代码可能含业务信息，需明确同意数据发送与估算费用。
4. 明确确认后只调用一次，无自动重试；费用进入既有任务累计模型账本。若返回缺条件或待决定事项，保留暂停原因，不生成一个删减功能的假完整成果。
5. 查看完整代码前后差异、修改理由及影响。模型候选不能用本机固定规则的采纳入口绕过业务核对；必须另行明确确认。
6. 采纳为新修订，保存旧版本，失效需求及配置确认和成果／应用绑定。之后重新确认业务需求、配置、构建，并按资源方案导入验证。接入修复后验证区，保持旧失败记录。

## 范围与保护

不发送原试跑输入／输出、错误全文、材料、知识库全文或聊天历史。不发送模型 Key；公开确认 token 是绑定源码、来源、供应商配置、费用设置和次数的摘要，不包含 Key。确认后任一绑定变化会拒绝请求，生成期间来源或模型变化也不保存候选。

首批纯计算范围只接受 math／re／json 及 future 导入，禁止动态执行、文件／系统依赖和反射访问。输出候选只能为全部失败代码节点提供完整代码及理由；未知字段、其他节点、开放问题、重复／漏节点、无修改、疑似凭据或不兼容静态结构拒绝。资源、节点连接、输入参数及输出声明不由模型修改。修改业务含义无法仅靠静态检查证明，因此所有模型候选采纳都要求业务复核并重新确认需求，而不是让模型声称“没有改变业务”就自动采用。

每个源运行、源修订最多两次主动模型请求，每次都需要新的预览确认；无自动换模型。未派发失败不计请求次数，可能派发／失败／中断均保守记录。重启只把尚运行的请求记为中断，不重放；既有累计模型预算仍需核对未知费用。不是跨多个新修订的通用无进展证明，也不是 Dify 执行费用上限。

候选记录保留模型、Provider ID、规划记录 ID 和独立请求 ID，可追溯费用。独立候选／请求记录同时提交；显式采纳时重新校验原失败来源及代码差异，再原子提交新任务／记录。

## 验证与缺口

13 项新增本机检查：具体数据范围、单次调用、累计费用、确认失效、业务采纳、防绕过入口、危险代码／越界字段、失败次数上限、无重试、重启不重放及来源关联。模型响应全部替身；真实供应商费用为 0。5 项受控页面检查验证两次独立确认、完整前后代码、状态失效；真实任务不变，写入只在内存拦截。构建／视觉通过。完整后台结果见 development-status.md。

最新完整后台 1562 项通过，既有 Starlette 提示 1；原本机修复／验证界面另回归 8 项通过。尚未做真实模型修复质量或真实修复后 Dify 运行验证。其他语言、HTTP／模型／知识库／输入资源错误、实际 DSL 手改保留路线未覆盖；这些情况保留限制、协商方案，不静默删功能。自动连续修复／重跑、通用无进展、Dify 执行费用硬上限仍未完成。

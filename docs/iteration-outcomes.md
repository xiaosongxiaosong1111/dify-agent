# 批量计算的逐项失败记录

开发版本0.183，部署状态及实际检查见 development-status.md。当前只提供本机方案预览及采纳到未保存草稿；不是通用批量业务验收。

## 解决的问题

原生“失败继续”不能直接替换字符串数组的失败策略。Dify 1.17.1锁定graphon 0.7.0，继续模式会在失败位置记录None；移除异常结果会丢掉位置。直接切换会改变原输出格式及对应关系。源码只读证据见work/iteration-outcome-source-audit.json；缓存wheel的SHA256已与tagged api/uv.lock核对，未运行该包或Dify。

本功能提供明确替代：原计算返回result文字，封装后每项返回index／ok／value／error_category对象。原0基索引、顺序、重复项和成功文字保留，失败不伪装成成功。异常正文及原输入不复制到失败记录。

## 交互和边界

在流程页“批量计算：失败项保留记录并继续”选择目标，明确接受六类计算异常继续与对象数组结果，先预览完整代码和计划，再采纳。采纳只填编辑器；保存、需求／配置重新确认、生成、导入及运行仍独立。

支持范围为Workflow的四根节点：Start→单输入Python JSON数组解析→只有一个Python计算节点的迭代→唯一End。正文原函数仅main(item)，仅result:string输出。保留原正文、所有节点ID／标题／连接／布局，以及明确的顺序或并发条件。多节点、模型、HTTP、文件、其它消费者或动态代码明确拒绝，不删减后声称完成。

仅计算函数执行过程中ValueError、TypeError、ZeroDivisionError、KeyError、IndexError、OverflowError变为失败对象。输入声明、输出结构或输出类型错误在捕获范围外；其它异常、沙箱和超时仍失败。父迭代仍terminated且不展开。并发已派发项可能继续；没有自动重试、断点恢复或费用硬保证。AST范围检查不是通用安全沙箱、耗时证明或实际运行验证。

## API

POST /api/tasks/{id}/iteration-outcomes；字段严格为revision、完整plan_text、node_id、acknowledge_result_contract=true及UUID request_nonce。2MB原文、重复键／非有限数／坏编码／疑似凭据保护沿用原检查。返回候选原文、原计划／候选／原代码／封装SHA256、原目标、明确的六异常与未验证标志；不写任务或草稿存档，不读取凭据、执行代码、联网或派发模型。

界面核对任务／修订／nonce／目标与结果标志，15秒超时无重试，草稿／节点／任务变化取消旧请求、清除旧方案与选择。未知服务错误正文不展示。含超浏览器安全数字的完整计划仍只用高级原文编辑，本表单不会整体舍入。

## 0.189数值结果

# Sierra 助手模型累计预算

版本 0.16.0，2026-10-10。这是助手模型调用的累计估算门禁，完整项目费用控制仍未完成。

## 计费范围与起点

- 同一任务的需求访谈、流程建议、覆盖检查、冲突检查共用独立 SQLite 账本。每次实际派发单独记录，修复重试也计入；任务修订、历史恢复和服务重启不会重置账本。
- 新任务创建时开始登记。升级前的任务从首次登记开始，不根据旧记录猜测历史单价和费用；存在旧模型记录时，设置累计上限必须明确接受历史未纳入。
- Dify 应用执行（包括批量迭代／多轮样例）、知识库索引、模型连接探测，以及登记起点前的调用费用没有纳入。账本不是供应商总账单，也不代表原始 136 项计划已完成。
- 上限默认关闭，但调用仍登记。原有每轮规划的时间／修复次数／费用限制继续独立生效；同一调用在规划记录和累计账本中展示两次，不应将两个视图相加。

## 派发、结算与停止

派发前在同一个 Store 锁内，按此次调用的配置单价、输入文本保守估算和输出 token 限制预留费用。累计已估算／人工登记金额加未结算预留，加下一次预留超过上限时拒绝派发。已开启累计上限时，缺单价或存在费用未知条目也拒绝派发。预算拦截的规划尝试标为 `not_dispatched`，不记未知费用。

返回后按白名单用量和派发时单价结算。正常、格式不正确、业务校验失败、供应商异常但有有效用量的调用都可能产生费用。没有有效用量、价格未知、超时或中断记为 `unknown`，不能假装零费用；原有预留保留。使用供应商缓存用量和可用缓存单价估算；未描述的缓存写入价格不能确认为已结算。

实际返回的用量估算仍可能超过预留或上限，因此不是硬性的供应商账单保证。超过累计上限的模型候选及可用用量保留，不应用到需求或计划，进入暂停／核对。暂停也不撤销已发出的供应商请求；已发请求返回前阻止重复操作。访谈迟到候选不会写回需求，保存在 `interview_attempts`，可通过任务 API 核对，尚未提供专用候选编辑界面。

服务重启将未结算调用转为未知，保留预留并暂停未结束访谈／规划，不自动重发。锁及预留原子性针对当前单进程本地后端；多进程部署尚未适配。

## 明确调整与人工核对

任务面板可展开“助手模型累计预算”，填写累计 USD 上限和原因，再明确确认。关闭上限或提高上限不会删除记录。金额为 0—1000000 的有限非负十进制数，最多 12 位小数。预算策略使用独立版本号；过期操作拒绝，设置本身不会更改业务修订或替用户确认方案。

未知条目只能由用户核对供应商账单、填写金额及来源并明确确认后登记。记录标为 `user_declared_bill`；系统没有自动查验发票，不改写原始用量／预留，也不能修改正在返回或已结算条目。登记单项后保留其他条目的未保存草稿。

## 接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/tasks/{id}/budget` | 读取累计状态、起点、排除范围、账本、策略历史；无派发 |
| PATCH | `/api/tasks/{id}/budget` | 业务 revision、policy_revision、limit_usd、原因及明确确认；不清账本 |
| POST | `/api/tasks/{id}/budget/entries/{entry_id}/reconcile` | 未知条目的业务／策略版本、actual_cost_usd、账单来源及明确确认 |

账本不保存提示词、模型原文、API Key 或凭据；保留调用类型、模型标识、单价快照、用量白名单、估算和操作关联。用户填写的说明属于本地持久化内容。

## 验证

24 项新增后台检查覆盖四类实际业务入口、跨修订累计、历史任务恢复、原子预留、并发拦截、未知费用、缺单价、异常携带用量、缓存估算、人工核对、策略版本、超额候选保留、暂停及重启恢复。供应商全部受控，不产生真实模型费用。完整后台回归 511 项通过；前端生产构建通过。浏览器检查结果见开发进度文档。

真实供应商账单差异、长时间业务使用、多进程并发、Dify 执行与索引累计费用仍需后续实现／验证。

0.18.0 起新增“配置建议”任务模型调用到同一累计账本；目录读取无模型费用，采纳无模型费用，记录视图不要重复相加。

0.19.0 起新增 `kind=cases` 的“验收样例建议”模型调用到同一累计账本；生成候选计费，采纳及本地规则校验不调用模型。追加样例导致修订变化，不会清零助手费用；未包含后续 Dify 样例运行费用。本轮受控验证没有新增真实费用。

0.26.1 起提供独立的 Dify 已保存运行用量／报告金额只读视图，见 execution-costs.md。它不改变本助手账本，不实施 Dify 费用硬上限，两者不能合并称为供应商总账单。

## 0.32.0 验收建议路由

已明确选择的轻量验收建议也进入同一累计账本；按实际派发服务的价格、用量和操作 ID 登记，策略切换／修订不重置费用。仅用于验收样例建议，不自动升级、换主模型或再次试跑。参见 [路由说明](assistant-routing.md)。

# HTTP 运行诊断

0.46.0 扩展现有试跑页的“失败诊断与处理建议”，对应 T094 的 HTTP 错误归因切片。不是新增测试样例功能，也不代表 T095 的自动修复已经完成。

| 运行错误证据 | Sierra 的处理建议 |
| --- | --- |
| HTTP 节点报 API key is required for authorization but was empty | 核对该节点引用的 Dify 秘密环境变量，补齐接口凭据后重新发布；不误导用户修改 Sierra 的模型 Key，不删除认证。 |
| HTTP 节点报 Failed to parse JSON: | 核对完整请求体及变量展开后的引号、转义、空值和类型；占位符静态检查不能证明实际输入可解析，不替换为空对象或删除业务字段。 |

只有可信轨迹中的 http-request 节点类型，或者对应原生 AuthorizationConfigError／RequestBodyError 标记与明确错误短语同时存在，才给出这两类提示。类名本身、其他节点同一短语不足以归因。结论仍为“需核对”，不声称凭错误文本确定根因。

沿用现有采集时执行／发布／成果核心图核对、原应用绑定和脱敏。诊断只追加证据记录，不修改方案、原始运行、验收结论或修订，不生成修复、派发模型、发布应用或自动重跑。错误摘要不复制节点输入、输出或 process_data。

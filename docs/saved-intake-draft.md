# 本地复核并恢复保存的失败访谈草稿

需求页新增“复核并恢复保存的失败访谈草稿”。修复准入规则后，可重新核对完整保存的模型回复，主动恢复为新未确认草稿，避免复制长文或再次付费访谈。原失败与费用不改判，不恢复旧真实批。

1. 处理本页未保存编辑及待发送说明，点击读取候选列表；不会自动预览或采用。
2. 选择候选，按当前规则本地复核，查看八项需求、逐项检查及待答问题。这是确定性契约/来源检查，不证明语义正确。
3. 明确勾选后恢复，产生新修订并保存原版本，需求/配置均未确认。原失败候选保持applied=false，另记saved_intake_adoptions与saved_model_candidate来源，不伪称原调用成功或新模型检查。
4. 处理待答问题并复核后才能正常确认。离开不取消已提交恢复，请刷新核对最新修订；刷新/旧token不重复采用。

仅支持初始需求阶段，无材料、正式计划、成果、App或运行；完整未应用且因需求契约拒绝的同修订回复，最多16000字。截断/旧修订/暂停/中断/迟到/只读讨论/未知时间/候选后新用户说明拒绝。不修补JSON，不忽略重复键、引用、主题、问题或已知凭据模式。采用前锁内重核8MB内完整任务/候选指纹，修改、并发或重放拒绝。

接口均POST且no-store，错误不回显输入：

- `/api/tasks/{id}/saved-intake-candidates/list`：`{revision}`，最多最近20条的序号/完整与修订标志，不返回原文。
- `/api/tasks/{id}/saved-intake-candidates/{index}/preview`：`{revision}`，按当前来源/标准检查并返回拟恢复说明、问题、candidate_sha256及review_token；只读、不解密、不请求模型或Dify。
- `/api/tasks/{id}/saved-intake-candidates/{index}/adopt`：`{revision,review_token,acknowledge_unconfirmed:true}`，新建未确认修订及明确恢复记录，原失败与账本保持。

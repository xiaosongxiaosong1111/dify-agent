# 内部条件图的人工修改保留

版本 0.30.0，适用于单层顺序逐项迭代，内部可为代码／模板／文字 LLM 链，或受限条件／无分组聚合 DAG。并行项、嵌套、一般循环、失败继续／跳过、内部复杂节点及 LLM 记忆保留仍未适配。

读取实际编辑草稿或上传 DSL 后，从原生父容器、start_node_id、parentId 与内部连接恢复临时验证结构：一个内部开始、唯一开始出口、1—12 个受支持处理节点、1—48 条 DAG 内部连接，全部路径汇入已声明的共同输出。实际条件句柄保留，完整默认分支、引用可用性、候选类型与优先级仍按生成阶段的规则核对。未知句柄、重复连接、跨边界、环、未连通节点和不完整输出阻止采用，不删除后算通过。

验证结构只用于检查，原文件不重编译、不重新排列节点／连接，不改代码、条件、模板、模型、布局或候选顺序。内部条件、重连和其他字段与新生成值冲突时，三方差异仍要求明确选择 current／generated。采用后推进修订并使需求／配置确认失效，重新确认后最终文件严格对应明确选择；源 Dify 应用保持原状。

原生文件缺少 Sierra 使用的 iterator_input_type／output_type 类型元数据时，只从文件中上游节点和所选输出的明确类型声明推导临时检查值，原文件不新增这些字段；未知、null 或显式矛盾不能猜测覆盖。不从样例或代码语义猜实际类型。

静态图、声明类型和代码语法通过不等于真实 Dify 导入、运行或业务验收。模型次数取决于实际内部执行节点，不能按每项一次作费用保证；Dify 费用仍不在助手硬上限内。并行仍不能从原生文件中捏造逐项独立性声明，需另行实现与确认。

backend/tests/test_preserved_iteration_branches.py 覆盖文件重排、手改条件／模板／优先级／布局、实际重连、明确冲突选择、作用域和循环拒绝、类型元数据依据、隔离采用与最终文件。页面与全量实际证据见 development-status.md。

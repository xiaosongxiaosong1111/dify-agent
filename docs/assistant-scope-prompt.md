0.185已部署e057f7257fa103282597；10新增、相关100及134（交叉）和37GUI通过，最近完整仍为184的3881项。实际证据见development-status.md。

## 需要修复的问题

访谈系统提示中曾硬编码“触发、人工审核仍待适配”等过时总括，与已有受限Workflow功能不一致。仅更新界面能力卡或开发文档不会修复真正发给模型的提示；助手可能继续作出错误拒绝。

## 实现方向

复用能力接口的同一个catalog(app_type,version)，每次访谈读取当前选定类型的目录。系统提示保留准入、冲突、确认、隐私及不编造原则；具体能力与受限前提来自目录，避免另维护一套总括。Workflow、Chatflow、原生Agent分别提供，不把Workflow专用文件、定时、人审或容器扩散到其它类型。

目录始终是compiler_scope，不能证明用户资源可用、已运行或业务验收，也不是外部写入或付费调用批准。目录只是公共产品信息，不读取供应商、知识库、连接、凭据或任务资料。仍按已有访谈路径派发一次请求，不新增模型调用；公共目录增加的输入上下文沿用原预算及账本估算，不能宣称费用不变。

LLM逐节点参数及检索阈值／rerank说明移入非Agent目录；Workflow目录补充四节点纯计算逐项失败记录、汇总及重新复核要求。未知条件仍追问，超范围说明可完成项、缺条件、替代方案及体验／费用／人工影响，确认前不删功能。目录更新在派发与记录用户访谈操作前准备，准备失败不留下已派发假象。

## 验证要求

必须检查实际访谈路径发给假模型的完整system消息，不能只断言辅助函数或文档。覆盖三应用类型、目录随当前实现变更、无供应商不派发、无自动确认及不生成运行／资源；不使用真实供应商调用或客户数据。即使消息检查通过，也不证明真实模型在复杂需求下必然遵循目录，语义稳定性及业务场景仍需后续真实验收。

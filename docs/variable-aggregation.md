# Sierra 变量聚合与分支汇合

0.23.0，2026-10-11。新增顶层 `variable-aggregator` 节点，支持将不同条件分支的结果交给共同下游。支持节点类型增至 11 个，不意味着所有原生参数都已适配。

## 明确的策略

计划配置必须精确含 `variables`（按优先级排列的 1—12 个 [节点ID, 输出变量]）、`output_type`（string、number、boolean、object、array[string]、array[number]、array[object]）、`selection_mode=first_available`。返回字段名 `output`。

按候选列表取第一个实际存在的变量。不是拼接、投票、按完成时间选择或取第一个非空值：空字符串、0、false 也可以是有效结果，不能悄悄跳过。没有任何变量时，原生节点可能成功但没有 output，因此静态检查须补全来源路径，实际运行仍要验证。候选顺序、输出类型和缺资料分支是业务选择，模型不能编造默认规则。

每个候选须来自实际上游节点、引用其存在输出并具有已知且一致的声明类型；自身、后续／无关分支、重复选择或隐式类型转换被拒绝。聚合允许读取互斥分支的候选；仅此节点例外，其他节点仍按 dominator 检查其引用源在所有执行路径上游。保守检查任何 start 到聚合的路径是否都经过至少一个候选来源；存在无候选路径就拒绝，要求补齐真实默认分支，不自动添加业务 fallback。

类型目前可从代码明确输出、开始文本、模板 output、LLM text、迭代 output、前一聚合 output、知识检索 result 与 HTTP body／status_code／headers 推导；未适配文件、未知结构化 LLM 输出等类型不猜测。声明类型和图覆盖不证明运行时有正确值；任意代码的实际返回仍需 Dify 验证。

## 编译与界面

原生 DSL 发 variables、output_type、advanced_settings={group_enabled:false,groups:[]}；Sierra 的 selection_mode 不注入原生字段。分组和迭代内部聚合尚未适配，未知字段明确拒绝，不忽略。0.24.0 已扩展无分组、明确类型／路径的聚合手改保留；其他分组／复杂配置仍会阻止，见 preservation-extensions.md。

流程页“填入分支汇合样例”仅填草稿：空输入提示补充、非空输入返回文字，两个模板分支汇入同一结果出口。样例是技术提案，不自动保存、确认或修改业务需求。节点摘要与可点击图展示候选优先级及配置。保存计划保留未变化的需求确认、使配置确认／产物／导入失效，后续仍须复核并确认。

参考 DSL 摘要识别该类型并保留 variables、output_type 和 advanced_settings 原文，同时说明当前分组及任意配置复现／保留的限制。

# 需求与方案覆盖工作台

版本 0.13.0，2026-10-10。目标 Dify 1.17.1。

## 工作方式

流程页可从八类需求建立原文草稿、追加具体要求，或请求已配置的主模型拆分并核对方案。原文草稿初始全部为“待解决”；模型建议不会自动确认。逐项内容包括具体要求、精确来源、状态、节点／配置关联、验收样例、安排依据／缺口与推荐方案，以及体验、费用、人工影响。

状态含义：

| 状态 | 精确含义与门禁 |
| --- | --- |
| 已在方案安排（planned） | 关联当前任务实际存在的节点／配置，用户复核其安排依据；不是已运行、已验证或完整交付。没有关联不能保存。 |
| 待解决（unresolved） | 缺方案、条件、资源、存在分歧或超出能力；仍阻止覆盖确认、配置确认、构建、导入与运行。可补条件、调整方案，或讨论缩小范围。 |
| 暂不纳入本次范围（excluded） | 保留原要求；必须填写原因与体验、费用、人工影响，用户除逐项复核外还须单独接受这些排除项。模型不能替用户设置此状态。排除不表示该功能已完成。 |

来源可为八类需求字段或已解析材料 ID；引文必须是当前真实原文中的精确片段。计划、样例引用校验任务归属与存在性，包括迭代内部节点。清单最多 60 项；每项文本最多 3000 字，引用最多 30 个。已有项不能直接删除来绕过门禁；明确改为排除项后仍留存。确认至少关联全部八类需求来源，但这种形式完整性检查不能证明已拆分了每个业务细节。

关联验收样例不要求其已运行；没有合适样例时保留提示，待补。清单不是验收成功比例，也不把模型建议当作事实判真或完整语义证明。

## 修订与最终 DSL

- 保存清单产生新修订、清除配置／构建／运行确认，保留未变化的已确认需求和流程；清单及后续确认写入本地 SQLite。确认绑定修订、需求、资料、配置、环境、流程、样例及实际 DSL 摘要。
- 需求、配置、环境、资料、流程、样例及版本恢复变化后旧确认不可复用。恢复到没有清单的历史版本时，已启用的检查仍阻止构建，须重新建立清单。
- 有实际 DSL 引用时，须先确认当前保留文件，覆盖关联读取最终文件节点而非生成建议。单纯保存覆盖清单不会修改最终文件；校验摘要后将相同的保留文件审批绑定到新修订，并记录 carried_from_revision，仍要求新的覆盖与配置确认。文件被改动或无法读取时阻止确认、构建与导入。
- 已确认的本次范围传入后续流程规划；未确认的排除建议不能当作省略功能的授权。重新规划仍使覆盖检查失效，须对新方案复核。
- 首次保存／成功保存模型清单后，该任务启用覆盖门禁，不能通过 API 直接关闭。**未建立清单的旧任务仍使用原准入规则**，界面和报告明确提示其没有逐项覆盖证明。这一版没有强制迁移所有旧任务，不声称全产品的完整覆盖需求已实现。
- 未保存草稿阻止构建／试跑及其他任务编辑，切换页面仍保留；可撤销未保存修改。交付报告保留来源、缺口、排除原因、确认状态及待办。

## 模型执行范围

`POST /api/tasks/{id}/coverage/generate` 复用有限规划执行器：登记单价后才派发、调用前费用预留、返回用量／未知用量记录、时间与估算费用上限、有限 JSON 修复、无进展停止、用户暂停与重启恢复。结构问题、来源伪造、八类遗漏或擅自排除项会暂停，保留候选，不能删减需求后重试成功。费用只覆盖本轮模型建议，不是完整任务或供应商账单保证。正在返回的请求不能靠暂停撤回。

材料给模型的摘录总量最多 18000 字、单份最多 6000 字；截断状态明确提供。用户仍需核对全文。没有实现 OCR、自动事实冲突裁定、来源行号、自动样例生成或证明需求完全覆盖的算法。简单节点关联、来源子串和人工复核不能代替真实业务验收。

## 验证与外部操作

30 项新增后台检查覆盖：缺口门禁、源引文／引用校验、排除确认、旧凭据、类别遗漏、不得删项、修订与恢复、模型建议、候选保留、无价格不派发、暂停／修订变化以及最终 DSL 文件与审批一致性。受控模型输出只是开发检查，没有冒充真实 DeepSeek 分析。

独立无头 Edge 8 项检查通过：建立草稿、跨页面保留／构建阻止、撤销、保存与确认失效、关联和排除双确认、刷新恢复、模型遗漏反馈、真实任务不变／无页面错误。浏览器拦截全部写入；记录 `work/coverage-ui-result.json`，零模型调用。

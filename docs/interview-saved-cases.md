# 访谈读取当前保存的验收样例

原正常review访谈发送当前需求、配置、材料和历史，却没有当前保存的test_cases。因此用户已保存案例后，模型仍可能只看到历史中的数量，继续要求重贴逐例输入和期望。414本批另有“访谈之后才保存案例”的方案遗漏，本修复不改其旧失败或重跑它。

377的正常及流式review访谈现在带入当前案例的有界投影：输入、预期、必要性和多轮接续，含修订、内容SHA、项/轮数及未执行/未批准标记。共用既有30项/24000 UTF-8字节门禁；结构坏、超限、疑似凭据及非法文字，在读取Key、追加用户消息、创建访谈检查点或费用预留前返回固定422，不截断补救。无模型时的手工记录和只读discussion行为保持。

模型可用kind=test_case及当前真实ID逐字引用投影原文字段，包括多行字段。引用不存在、被修改、旧版或运行元数据时拒绝；expected只是验收设计，不能当检索事实、硬编码答案、自动确认或资源批准。当前案例投影中的额外元数据和旧运行结果不发送。访谈记录只保存来源摘要，不重复整份案例内容。

使用test_case来源的需求复核绑定案例投影摘要，输入/期望/接续变化后失效；不因无关运行元数据变化失效。旧未引用该来源的复核摘要兼容，不批量重写用户历史记录或结论。

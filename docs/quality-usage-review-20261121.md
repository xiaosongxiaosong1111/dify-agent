# 365 质量、用量、费用与演示证据复核（2026-11-21）

本项只读核对当前路由、可选升级、上下文/重试边界和同一任务累计账本，并整理已有演示证据。未改产品代码，未访问生产数据或秘密，未执行真实产品模型或 Dify 调用；本轮没有 A/B 收益对比。开发 DeepSeek 委派属于开发流程，不是产品同案例测评。

## 一、路由与可选升级

- 默认使用任务指定主模型。只有用户显式选择有密钥的轻量服务后，`kind=cases` 验收样例建议才改走轻量；访谈、流程、配置、冲突、覆盖仍用主模型。路由选择、快照指纹和策略历史均有本机实现。
- 可选“轻量 JSON 格式失败后单次升级”默认关闭。启用须独立确认升级范围，并固定当前任务主模型的选择、配置、密钥和价格指纹；服务、角色、密钥、价格、能力或主模型变化后阻止派发，不自动换服务。
- 只有轻量一次返回无法解析为 JSON 对象、状态为格式失败且最终用量完整可计价时，才向固定主模型再调用一次。发送的是原有限上下文，不附加无效模型正文；两阶段各一次，共最多 2 次 HTTP，每次最多 6000 输出 tokens、120 秒，共用本轮时间/费用与同一任务累计账本。
- 未知用量、网络/超时、截断、业务/资源/校验问题、暂停、修订或来源变化均不升级；不重放历史失败，不发起第三次调用。主阶段失败或服务重启只保留已知/未知记录并暂停。
- 这些是本机结构与替身边界，不等于真实供应商质量、全链成功率或节省。

## 二、上下文、次数和重试单位

- 历史组装默认取最近 12 条消息，窗口内不做文字静默裁剪；窗口外旧消息不提供，并在摘要中标记数量。显式 compact 时历史文字上限 24000 字符，旧消息单项最多 6000 字符，当前用户原话在该历史选择中优先；当前完整需求、本轮原话及其他上下文按既有路线另计。
- 字符数是组装范围，不是 token 数、供应商计费或账单硬限。不能据此声称所有输入都有硬 token 上限。
- 现有确定性限制是固定有限 HTTP 阶段、单次输出上限、每轮时间/费用和重试上界；不表示通用子 Agent 分工或任意输入均受限。

## 三、费用和用量分账

1. Sierra 产品搭建模型：按已配置单价和最终用量结算；缺最终用量或单价时保留 unknown 并保留估算，不冒充零费用。已启用任务累计上限时，unknown 会阻止后续派发；用户可按实际账单走显式 reconciliation 主动登记，登记后该条按用户声明账单计入。估算不是供应商账单硬限，图片预留为用户声明的估算。
2. Dify 应用实际运行：费用和调用记录单独说明；接口返回 0 或没有运行记录不能证明免费，历史 Dify 报告金额 0 也不当免费。
3. 开发 DeepSeek 使用：单独记录，用量缺失另列；不并入 Sierra 产品账本，也不伪造供应商总账。
- 已消费包、旧 unknown 和未派发预留保持原状，不因新任务或重启自动退还、借用或清零；旧授权批的不可退借边界不禁止正常用户对当前任务 unknown 主动核账，也不允许假称免费。

# 按原始说明逐项补充待答专项

0.287在需求页提供“按原始说明补充一个待答专项”。解决只有一项资料口径待答，却要整份人工重填八项需求的问题，并明确操作者/代理来源，不冒充新模型验证或人类答复。

1. 读取待答专项与原始用户说明；仅当前有效检查中的needs_input专项可补充，基础八字段缺口仍用正常编辑入口。
2. 选择专项，填写补充，选择原始用户说明并逐字引用。提供最近20条完整需求消息（每条<=16000字，合计<=64000字）；讨论、超限或已知凭据模式来源不展示，不截断伪装完整。
3. 本地预览只核对契约和引用存在，不自动证明补充由引用推出。操作者显式承担语义复核。引入新专项的补充拒绝，不能借关闭旧问题绕过新需求检查；同一专项内的语义变化仍须操作者负责。
4. 明确保存只改选定检查及其问题，保留八项需求和其他检查，新修订仍未确认。其他缺口保留，必要时按现有标准生成下一条待答提示，不填答案。原失败/费用/候选不改判。

未保存补充阻止其它编辑/执行；页面切换保留文字并失效预览，任务/需求变化或刷新清空。可明确清空草稿；离开不取消已提交保存。来源/答案/操作者绑定完整任务，锁内重核，旧预览/并发/重放拒绝。材料、正式图、成果、App或运行不在此入口覆盖。

接口POST（no-store），前缀`/api/tasks/{id}/intake/topic-resolution/`：

- `options`：`{revision}`，只读返回待答专项和可引用原始用户说明。
- `preview`：`{revision,topic,answer,evidence:[{message_id,quote}],actor,actor_note}`。最多6条引用，回答/单引用<=3000字。actor为local_operator或agent_delegated，代理须写依据说明，不接受human_signoff。
- `save`：同预览加`review_token,acknowledge_source_review:true`。生成新未确认修订，记录source_backed_resolution及逐项来源，其他字段/账本保持。actor是请求方声明的来源，不是认证身份或人类签收。

补充及引用进入后续上下文/来源列表，明确标记为操作者复核。摘要纳入补充，修复了归档旧记录后计算新摘要的顺序，避免随后走原人工/模型复核立即过期。先复现2失败/20通过，最终新22/相关114、界面9/构建截图通过，未全量。UI夹具曾误用系统消息序号，改为从实际用户来源选项读取，未改产品来源校验。

本次代理依常规可逆工作委托，引用原始用户说明第4条的三段原话：政策编号、检索非空一次LLM/空结果固定分支、TopK3无阈值不重排。只补retrieval：不新增库名/文档标题/片段等强制引用字段，也不增加相关性门槛或二次模型。任务r3→r4，八项需求和其余八条检查逐字保持，旧检查归档；can_confirm=true但需求/配置均未确认。明确记录agent_delegated，不是新增人类答复或最终业务签收。

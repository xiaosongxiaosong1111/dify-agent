# 查找与引用历史原话（0.313）

对话区的“查找历史原话”只读取当前任务保存的用户和助手消息。输入字面查询词，可筛角色；从最新记录开始，主动点击“继续查更早窗口”才读取下一窗。它不调用模型或 Dify，不保存查询词、不改任务、确认、提交序号或费用。

点击命中的“核对原文”后，后台重新核对任务、原消息位置、正文摘要和来源标签。浏览器也核对完整正文 SHA-256、Unicode 字符数及引用范围，才提供“放入只读讨论草稿”。最多引用4000个字符；完整单条原话与仅片段分开标识，未引用部分不声称已提供给模型。正文中的中文、表情和换行参加原文摘要，textarea 按浏览器规则显示换行，不作为原始字节下载。

引用标有原任务、`message:N`真实零起始位置、用户／助手、需求检查／讨论、输入／结果修订；旧记录没有的标签保持未知。引用文字明确说明历史指令和建议不是本次采纳或执行批准。它只进入只读讨论草稿，不发送、不更新需求，也不改变资源范围。已有未发送文字时拒绝覆盖；任务切换或修订变化时丢弃旧面板响应。明确发送讨论仍沿用现有模型配置及预算门禁，不能由本功能推断免费。

## 读取范围

- 区分大小写，查询词1—200字符，保留用户实际空格；不做语义检索、分词或长期记忆。
- 每窗最多检查1000条记录、100万正文字符、20个命中；任一上限结束后保留下一窗位置，不跳过未检查匹配。计数反映当窗检查，角色排除也占记录数；字数只计实际搜索正文。
- 单条正文超过10万字符、无法识别的角色或正文记为未查，不用截断正文冒充完整搜索。角色筛选外正文未搜索；后续追加内容须重新从最新窗口查找。
- 完整单条读取也限10万字符，超过返回413。当前实现在读取既有Task对象后按窗口搜索，并非数据库按页装载；不保证超大任务存储的内存上限或全历史穷尽。
- 指纹绑定任务、索引、来源标签和完整正文，定位不是授权令牌。正文或标签变化拒绝旧指纹，正常追加其它消息不使同一原话失效。业务修订在请求开始和返回前核对；返回是该次保存快照，不是持续订阅。

## 本机接口

`POST /api/tasks/{id}/history/search`：`revision`必填严格正整数、`query`必填、`role`可选`all/user/assistant`、`before_index`可选非负整数（独占上界，缺省最新）。返回当窗计数、命中片段、原始索引和指纹、`has_earlier`及`next_before_index`，无命中只说明已查范围。

`POST /api/tasks/{id}/history/message`：同修订、`message_index`、命中`source_token`，`center`可选非负字符位置。返回完整`content`、摘要与来源、`quote_text`及零起始独占上界`quote_start/quote_end`、`quote_complete`。不接受任意其它任务的指纹或额外字段。两接口标记`saved_message_lookup_only`及未修改／未调用模型／未请求外网／未验证业务。

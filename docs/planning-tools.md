# 主规划按需查询节点规则（0.318）

Workflow/Chatflow 的主规划模型现在可以按需请求一次已注册的只读规则查询。默认关闭，原16个任务未启用；本次开发使用合成 HTTPX 替身，没有新增真实 Sierra 模型或 Dify 请求。

在任务上方展开“规划只读规则工具”，核对固定当前主模型的名称、型号、地址、协议、配置版本及参考单价，填写原因并独立确认范围后保存。保存只写本机策略，不生成计划。模型须先有绑定当前配置的工具请求观察；普通文本/JSON通过不能代替。能力未验证时本功能不会自行探测或换模型。首批只适配 OpenAI 兼容协议和声明的 Dify 1.17.1，不用于原生 Agent 或其它建议。

之后在流程页主动生成完整计划。模型可直接回答（一次模型HTTP、零注册查询），也可请求唯一工具 `sierra_lookup_node_rules`。参数只能选择检索、条件、Python、文字LLM规则中的1—4个不重复类型，当前应用类型和目标版本由程序绑定。程序核对真实工具请求后，调用一次本机规则库，将完整结果按配对的 assistant/tool 消息回注固定模型一次。第二次不提供工具，不进入工具循环，也不追加修复。

工具不能访问任意文件、URL、客户资料或密钥，不能执行代码、资源或网络操作。原始消息最多2MB，结果最多32KB，超限停止而不截断；规则库本身的来源摘要计算和原有关键词上下文检索，不计作“模型触发的注册查询”。合成例子和占位资源不是当前配置、需求变更、执行批准或真实运行证明。

整轮最多2次模型HTTP，各最多请求6000输出tokens、120秒，共用原规划总时间/费用及同一任务累计账本。费用预检包含工具Schema和历史元数据；估算不是供应商账单硬限。全局自动修复上限为0时不启用此两次策略。用量未知、非法/多个工具、参数不明、暂停、修订/模型/声明版本/规则库来源变化、费用或时间不足即停，不重试、换模型、借旧预留或自动续派。

进度显示实际注册分派次数、查询类型、完成/失败/中断状态、完整结果字节和SHA256、规则来源、是否准备第二阶段消息及是否取得终稿文字。准备消息不等于HTTP已发出，取得文字不等于候选已保存；没有查询回执时，模型口述“已查询”不算工具成功。旧正式方案、静态检查、候选人工复核及资源门禁继续适用，重启只保留中断和未知账本，不自动恢复查询或模型请求。关闭策略清除当前来源指向，但保留确认历史和旧执行回执。

接口：`GET/PATCH /api/tasks/{id}/planning-tool-policy`，保存要求当前Task修订、policy_revision、范围版本1、明确确认及原因；启用还需当前来源摘要。来源绑定Task ID/类型、模型配置、声明版本、Schema和规则库，正常业务修订不强制重做范围确认，但每次生成仍绑定其输入修订。GET不解密、不写入策略或改任务。

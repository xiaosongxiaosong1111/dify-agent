# Sierra 需求准入与主动追问

版本 0.17.0，2026-10-10。已实现用户可用的标准检查、专项追问和明确人工复核；完整复杂场景能力仍在开发。

## 用户流程

创建任务并选择类型后，描述目标或先编辑八项需求。在“需求”页可看到“需求准入与下一步”，点击“请 Sierra 检查需求并继续追问”，通过已配置的搭建助手模型完成一次访谈。每轮同时返回需求整理和检查结果，无额外后台检查调用；不会定时自动调用或无限重试。

检查清单保留所有已识别缺口，本轮优先显示至多三项问题及建议、理由、体验／费用／人工影响。“围绕此问题讨论”只填入聊天输入，不自动发送，也不代表用户接受推荐。回答后正常发送即可重新检查；此前的明确内容及人工专项答案继续进入上下文。

新任务正式确认需求、配置、构建、导入和试跑之前必须通过准入。方案草拟仍可进行，草案不等于已交付。检查通过显示“说明已明确，待用户确认”，不自动批准需求、配置或资源操作。八个字段非空不等于语义已明确。

## 自有标准

| 标准 | 必须明确的内容 |
| --- | --- |
| 目标与范围 | 解决什么问题，本次必须完成及排除的内容 |
| 用户 | 谁使用、使用方式与已有知识 |
| 输入 | 字段、形式、必填条件及缺失行为 |
| 输出 | 内容、结构、接收对象与去向 |
| 规则 | 分类、分支、计算、生成和不可违反的约束 |
| 资料与依赖 | 范围及可用、待补、模拟、不适用状态 |
| 异常 | 信息不足、无结果和失败时的行为 |
| 验收 | 正常、关键分支、异常的输入与期望结果 |
| Chatflow／Agent | 上下文轮数、指代追问、开场问题、结束及人工指引 |
| 原生 Agent | 文本／知识／工具边界与失败策略 |
| 批量 | 分项、顺序／重复、单项失败及汇总 |
| 检索 | 范围、选库、无命中行为与引用 |
| 接口 | 输入输出、认证条件、可用性与异常／模拟 |
| 触发／人工 | 启动条件、输入输出去向、审核角色、拒绝和超时行为 |

类型专项固定启用；其余专项根据已保存说明、用户历史消息中的关键词及迭代计划识别。扫描只是辅助，不能证明任意复杂描述已被全面识别。模型检查同样不是业务事实验证或全量场景覆盖保证；无关键词的复杂流程、OCR 与复杂能力实现仍需继续扩展。

缺实际资源但已明确待补条件或模拟选择，不必伪装资源就绪。未实现能力应说明缺口与替代影响，请用户决定；尚未接受的建议保持未决。模型输出契约见 [intake-model-contract.md](intake-model-contract.md)。

## 来源与持续修改

明确／不适用的模型结论必须有逐字引文，来自实际输入的需求、用户消息、已解析材料或此前明确人工复核的答案。检查主题必须完整且唯一，问题只对应缺口；伪造来源、漏项和无来源明确结论拒绝应用。不得用本轮模型自己写入的新需求字段自证用户已决定。

错误候选及已产生用量继续保留在任务访谈记录／预算账本，不自动重试或更改确认方案。正常访谈中的需求更新或影响已确认方案的检查变化，失效相关确认；暂停及预算门禁沿用 0.16.0 的保护。

检查与当前需求、用户对话、资料内容／参考方式和标准主题绑定。只改模型配置不会要求从头复述业务；改变上述来源或新增批量主题需要重新检查。历史恢复保留准入记录及审计，但新任务的准入要求不会被旧版本关闭。升级前任务保留原来的八字段人工确认路径；一旦新增标准检查记录即启用对应门禁，不能把旧任务迁移算作已完成语义检查。

## 逐项人工复核

用户可选择无额外模型调用的人工路线。逐项填写明确说明或带理由的不适用说明，阅读完整替换提示并明确接受后保存；前八项完整替换需求字段，专项答案持久化并进入后续流程规划。不能跳过材料解析、参考方式确认或字段未知；新场景引入新的标准时需先保存说明，再读取标准。

人工复核记录标为 `user_declared`，不是模型验证或供应商资源验证。保存产生新修订，仍需单独确认需求；未保存草稿跨页面保留、阻止其他变更，可撤销；失败保留草稿及实际错误。专项答案表示业务意图，实际模型／记忆／检索设置仍需在配置阶段逐项核对和确认。

## 接口与验证

`GET /api/tasks/{id}/intake` 读取标准、缺口、优先问题、来源、就绪及过期状态。`POST /api/tasks/{id}/intake/manual` 使用业务 revision、来源 context_token、全部主题答案和明确确认；拒绝过期／运行中操作。正常 `/messages` 访谈已接入逐项检查，费用计入累计账本，输出上限现为 6000 tokens。没有新增模型费自动开销。

24 项新增后台检查覆盖新任务强制准入、类型及专项识别、主动追问、人工路线、来源拒绝、自证保护、答案复用、变更与恢复、旧任务迁移及准入到静态 DSL。受控验证不等于真实外部业务成功。

真实 DeepSeek 验证只调用一次 `deepseek-flash`，中文售后知识问答：实际识别 11 个标准主题，保留异常／验收／记忆／对话／检索 5 个缺口，优先追问记忆、对话行为和检索；所有明确结论引用原始用户消息。返回用量 2107 输入／4095 输出 tokens，按现有配置单价估算 0.0055461 USD；不是账单保证。验证采用 E 盘独立数据，未确认建议、未修改用户任务、无 Dify 写入。调用时输出上限为 4096；后续提高至 6000 以容纳复杂检查和思考输出，没有再次调用计费。

本地真实验证证据为 `work/intake-live-result.json`，受控界面检查为 `work/intake-ui-result.json` 和 `work/intake-ui.png`，未纳入 Git。一次售后样例不代表复杂场景的识别准确率或客户交付验收。

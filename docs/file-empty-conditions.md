# 文件列表的无文件分支

0.139新增明确文件列表空／非空条件，用于将“没有文件”与“有文件后提取”拆成实际图中的两个出口。它不自动补分支、不交换连接、不把Workflow提示文字称作持久追问或上传会话。

## 精确配置

if-else条件为 varType=array[file]，comparison_operator=empty／not empty，value明确为空文本或null。来源为根Workflow已核对的必填file-list，或同作用域原生HTTP.files，并通过原有全路径上游检查。不接受代码伪造文件数组、跨容器重绑定、file对象属性／contains／exists／数值比较或被忽略的非空右值。普通文字／数值／布尔条件保持原规则。

用户明确selected及false实际出口，例如没有文件时返回补文件说明，有文件时提取，再将文字按已确认规则处理／汇总。required文件列表仍可为空，因此空检查有实际用途；但它不检查文件权限、格式、是否可解析或提取出的文字是否为空。扫描件及坏文件、空文字处理需另行明确。

页面支持选择文件列表类型和根上游来源；变化只改当前字段。切换运算不交换出口，切换类型不丢弃旧运算或比较值。若旧比较值会被忽略，后台明确拒绝，页面提供“明确清空本条件比较值”按钮，仅在用户点击后清空；不强迫手改JSON。失效来源的selector保留，显示待选择而非换成其他文件。

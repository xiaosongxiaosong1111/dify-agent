# 原生文字参数提取与显式失败分支

0.62.0 支持顶层 Workflow／Chatflow `parameter-extractor`，从文字描述提取订单号、姓名等已定义字段。计划支持清单增至 14 类，尚未包含所有复杂节点。

## 配置

明确 query 两段文字来源、1—20 个参数及固定 prompt 推理模式。参数 name 唯一、为 1—64 位英文标识符、不用双下划线前缀；type 支持 string／number／boolean 及对应数组；description 和 required 必须明确。文字参数可设置有界唯一 options 枚举；不猜旧 bool／select、对象结构、动态参数、图片或工具调用能力。

继承任务模型和 Chatflow 有界历史，或设置完整独立模型及参数。提取会调用模型，增加费用；静态检查不能证明提取准确、真实资源可用或结果符合业务规则。

## 不能将默认值当业务成功

Dify 1.17.1 有时整体节点 SUCCEEDED 但 `__is_success=0`，同时返回空文字、0、False 等默认值。Sierra 要求提取节点唯一直接连接已声明 IF：唯一成功 case 使用 AND，恰一条件检查 `[提取ID,__is_success]`、number、`=`、文字 `1`，有明确成功和 false 出口。

只有成功出口所支配的路径可以引用业务提取字段，失败或重新汇合后的共同路径不能直接引用这些默认值。成功／失败回复可各自产生结果再明确聚合。成功之后必要的非空、格式、订单存在性等检查另设业务节点；required 不保证文字非空或真实性。故意把 required 改为 false、删失败检查、从共同结束直接取默认参数不能冒充满足原需求。

failure_policy 是 Sierra 未确认方案声明，包含行为 explicit_success_branch、guard_node_id 和 success_case_id；不是原生 Dify 参数，不写入运行配置。最终用户仍须核对失败时追问／停止／通知等行为，并按修订确认、用样例验证。

## 编辑与输出

提取卡编辑字段说明、必需规则、提取指令和完整参数／query／失败声明 JSON。卡片保留字段名、类型和条件／连线，不自动创建 IF 或把错误 JSON 改回旧值。独立模型编辑与普通 LLM 共用，可信诊断可以定位提取或模型卡。

原生输出有业务参数、数字 `__is_success`、`__usage` 对象；`__reason` 成功时可能 null，不声明始终是文字。返回／检索候选只在成功路径列业务参数，不给共同路径推荐未保护引用。0.63 接入顶层实际提取手改保留和最终原生语义摘要，见 extractor-preservation.md；容器内提取仍未接入，发现限制明确说明，不删节点。

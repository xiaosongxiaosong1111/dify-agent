# 当前App运行Key创建入口（0.253）

运行页可准备本机方案，核对目标App、原空间及共享连接影响，勾选后仅创建1个运行Key并加密保存、切换运行绑定。目标有Key或已有本机归档时拒绝另建，继续使用原登记入口；无需在浏览器接收或复制新密钥。只适配Dify1.17.1 Workflow/Chatflow，原生Agent本入口未适配，选择类型保持。

本机方案15分钟有效，不请求Dify。绑定当前修订成功新建导入、成果字节、任务暂停代数、原URL/版本/空间、连接修订、当前运行Key指纹和共享任务集合。确认前复查并持久核对中记录，阻止同环境任务编辑/登录/手动Key替换和并发确认。

确认通常读取空间、App详情、原Key列表，核对同一空间及App类型且无现有Key，再持久派发意图、仅一次创建POST，返回后读列表核对唯一id/token。共通常4读取/1创建，自动认证及GET401重读可能增加请求，不把此数当逐请求硬限。Dify没有Key列表的条件创建锁；外部并发新增可能使事后出现多个Key，此时结果未知、保持原运行绑定，不自动删除或重发。

成功时新归档（带原空间证明）、新连接Key/配对App、连接修订和成功回执同一事务提交。原运行Key另行加密留档，记录原声明App但不伪称其归属已验证，不自动复用。任务/成果/确认/其他凭据不改。SQL失败回滚全部相关保存，已派发的创建记未知；重启也不重发。同原实例/空间/App已有派发记录后，不因新修订或新连接记录绕过。

Key只进入加密凭据表和瞬时处理内存，不进入HTTP响应、普通对象、日志、浏览器存储或Git。失败只用固定文案/白名单诊断，创建前失败与可能派发后的未知分开。已提交成功后的响应格式化异常不会覆写成功回执。

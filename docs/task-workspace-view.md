# 紧凑工作区与完整版本存档（0.324）

当前界面打开、刷新任务使用独立的 `GET /api/tasks/{id}?workspace_view=compact`：消息仍是已核对的最近50条窗口，历史版本只传列表需要的ID、修订、标签、种类和时间。历史需求、配置、材料、计划和成果正文不再随每次Task读取重复传输。

版本顺序和数量保持。选择“比较与恢复”后，原比较接口仍按ID读取实际完整存档，核对当前Task修订并生成原预览指纹；明确恢复仍有原替换范围确认、失效与新修订规则。索引不当作恢复快照，不会用省略了正文的视图覆盖存档；完整旧Task接口、0.323仅消息窗模式和原写回执均保持兼容。

索引最多5000条、完整索引JSON最多2MB。ID缺失/重复、非文字字段、坏编码、字段或总量超限时，返回明确原因和“索引不可用”，不返回部分列表，不删除存档，也不显示“暂无历史”；当前工作区仍可读取。只有真正的空版本列表才显示空历史。旧修订缺失、布尔值或超出浏览器精确整数范围时不补猜，坏时间不显示为有效日期。字段超限不截断冒充完整标签。

客户端核对工作区及消息/版本索引的Task身份、修订、提交序号、计数、允许字段和只读标记。索引夹带快照字段、数量不一致或来源不完整时拒绝新回执，保留原工作区，不静默改读全量接口。合法刷新中发现索引不可用时，清除旧比较/确认入口；原后台存档不改。兼容的完整写回执仍可能携带全部版本，后续紧凑读取再投影。

新模式只投影消息和版本读取副本。SQLite仍读取原Task对象，当前材料、规划/运行记录等其它字段和单条消息仍完整传输，没有Task总量硬限或其它数组分页，不宣称全部长任务内存/网络问题已解决。只读投影不解密、不写Store、不改模型上下文/原话/版本或确认，也不调用模型/Dify。

新17项及消息/版本恢复57项后端分组、新UI7/消息窗口UI13和构建通过，未全量。测试保留完整私有标记快照、旧模式、预览指纹及真实恢复结果，并区分不可用/真空列表、精确索引字节边界和旧修订；所有业务写入仅在隔离后端恢复测试与明确fixture变ID中，浏览器业务写入0。首次UI夹具残留long变量已修正，原日志保留；最终UI退出时出现Windows连接重置/有界清理诊断，但退出码0、线程退出/临时目录清理/原16保护断言均通过，未当作业务请求失败或重试理由。

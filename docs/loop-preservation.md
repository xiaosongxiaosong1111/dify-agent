# Sierra 受保护循环的实际手改保留

0.37.0。只支持 Sierra 生成的、单层标量顺序循环及完整保护结构；一般原生循环、嵌套、循环内部条件／其他节点或重新命名保护节点尚未适配。

读取最终文件后，用户逐容器核对初始状态、每轮赋值、停止条件、最大轮数、失败／无进展及目标优先规则，选择实际用户状态中的进度字段，填写 2—10 连续无进展上限和业务进度理由，并明确确认。声明绑定完整文件 `root_token`；代码、状态、模型、连接、布局或冲突变化后失效。理由是用户对业务进度的声明，不证明代码有改善或已经跑通，也不把轮数等同费用硬上限。

后台从原生 loop_variables、break_conditions、loop_count 和 v2 assigner 的实际绑定提取静态验证投影。必须有唯一 loop-start→入口检查→1—12 个代码／模板／文字LLM→无进展保护→v2完整赋值链；循环外所有出口必须先经过停止复核，不得旁路、跨作用域、漏节点或多出回边。

私有无进展状态必须为预期名称、数字0初始值，更新必须绑定实际保护输出。入口／进度／停止三份保护的语言、输入／输出声明、绑定及代码 AST 必须与实际状态、更新、停止及本次进度声明一致；注释和空白可保留。未知保护控制字段、错误继续／默认值、内部记忆／启用重试、部分更新或改写保护行为拒绝，不删除后通过。

原生文件的全部布局、代码、保护、条件、模型及连接保持原文；规则只进入验证投影和本机保留记录，不重编译最终值。确认保留形成新修订，仍需需求／配置确认和独立真实导入试跑。生成时已修复 assigner 与进度输入共享列表导致的 YAML 锚点：新循环输出能通过 Sierra 自己的安全读取，不放宽读取器的共享／循环锚点保护。

预览新增 `loop_candidates` 和 `loop_reviews`。每项精确字段：`root_token`、`progress_variables`、`no_progress_limit`、`progress_reason`、`acknowledge_behavior=true`；所有当前循环均须声明，不接受未知／已删除循环或过期声明。`merge_token` 包含声明，未经预览改理由不能采用。overlay 留存声明；循环说明也可保存为未确认 `loop_draft`，未填完可留空，恢复时清除确认。

若同时有并行与循环容器，必须一并核对两类声明；任何一类缺失都不能采用。没有自动切换模式、提高次数或删保护的修复。

验收摘要包含实际循环状态声明／初始值、停止规则和赋值绑定，以及保护代码。数据范围升级 `scope_version=3`，旧启用轻量策略必须重新接受新范围后才能派发，不自动沿用版本2确认。用户发起建议前可查看本机摘要；本次没有新模型调用。

完整运行验证独立于本功能静态／保留检查。六场景技术包已获用户具体资源批准，管理连接401恢复前尚未创建或运行；不能把保留静态通过当作 Sandbox 或完整图成功。

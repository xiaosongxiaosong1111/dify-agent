# 文件流程能力范围说明

0.178实现，合并0.179部署，实际部署与验证以development-status.md为准。修复旧能力页将“用户文件上传与OCR”和“人工输入／审批节点”笼统列为未适配的问题；不把已实现的受限路线与通用功能、真实验收混为一谈。

能力接口版本2仍以compiler_scope描述整体生成范围，Workflow另返回独立implemented_file_flow_scope_only文件声明。列出八类精确根节点图：原生提取、单文件文字模型、单文件对象、列表拼接文字、列表拼接对象、单文件对象校验、列表对象校验、可选单文件分支。每项注明根节点数、输出、模型／拼接／校验和对应Flow版本；可准备单次试跑仅表示实现了入口，资源、权限、具体方案及用户批准仍是前置条件。

六种上传与专用试跑格式为TXT、MD、CSV、JSON、YAML、YML；逐项展示固定Dify源码对应的解析方式和可能变化，不承诺当前文件已实测、数字／重复键／表格／YAML语义保真。文件迭代可生成草稿，不表示通用含容器、HTTP、自定义代码、多个模型或任意分支的文件运行已开放；PDF／Word等上传和OCR、真实文件模型验收仍未完成。

Workflow、Chatflow和原生Agent分别给出限制。Workflow保留复杂审核的指定身份、邮件、补充表单与容器组合，以及真实自然定时业务验收等缺口；不再否认已实现的受限人工审核草稿与专用方案。Chatflow和原生Agent不返回Workflow专用文件运行声明，应用类型不会被改变。

前端校对版本、八类路线、节点与Flow版本、功能标志、六格式及未实测标志；不完整、应用不符、错误地声称业务已验证或未知版本均拒绝。旧v1只读生成范围，额外提示不能据此判断新文件单次试跑；无接口／错误不能继续显示旧范围。

能力读取不访问Dify、模型、文件正文、密钥或客户任务；不会准备资源、派发运行或修改任何任务。

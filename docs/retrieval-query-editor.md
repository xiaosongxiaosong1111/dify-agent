# 知识检索问题来源

0.50.0 在知识检索卡补充“检索问题来源”。修改只进入草稿，不调用模型、查询知识库或修改 Dify。

## 配置行为

- 使用应用默认问题输入：Workflow 是实际 start 节点的 query 字段，Chatflow 是 sys.query。页面显示默认实际引用并提示自定义输入名须明确选择；默认不是自动猜测哪个字段是问题。
- 明确选择节点问题来源：先创建待填写两段 selector，不自动选第一个候选；可选择原始输入、改写模型 text、模板 output、明确声明的代码文字输出等。
- 候选仅依据当前根图的所有路径上游关系及文字声明，不列只在兄弟分支产生的值，也不列数值／对象／数组。候选不证明实际输出有效，后台保存再次核对。
- 实际节点与输出字段可手填；无效 JSON 保留文字并提示，不沿用旧值或退回默认输入。只有用户主动选择继承才移除独立 selector，不改变知识库、重排、阈值和连接。

## 生成、读取与诊断

固定 Dify 1.17.1 的知识节点执行代码要求问题输入为 StringSegment。后台对有可靠声明的非文字来源，在生成前明确拒绝，要求用户确认如何提取或转换为问题文字；不自动字符串化、改选字段或删除检索。类型无法静态确定时明确提示未知，不以引用存在充当运行验证。

原生 DSL 的空 selector 可能使节点不检索，不等同于 Sierra 计划里的“继承默认”。保留读取要求原生有完整非空两段问题来源，缺少或未适配形状明确拒绝，不补一个默认来源后算作原样保留。

真实轨迹中知识检索节点的 Query variable is not string type. 会给出专门诊断，指向问题 selector 与实际上游输出，沿用原诊断来源绑定、脱敏与只读保护；不修改运行、验收或自动重跑。

# Sierra 验收样例建议

0.19.0，2026-10-11。对应 T057、T098—T100 的新增部分，不标记整个任务或里程碑完成。

## 产品流程

在“运行”页的“验收样例建议”中请求 Sierra 给出候选。需要需求已确认、需求准入通过、分歧已裁定、现有流程未过期；原生 Agent 还须已有方案。生成只保存独立候选，不改现有样例或确认状态。展示正常／分支／异常／多轮类别、检查目的、当前需求来源原文、关联节点、首轮输入和检查规则，多轮可展开逐轮输入与预期。

用户逐项选择并明确核对后，后台只追加所选样例，分配正式样例 ID，保留现有 ID、输入、预期、必选状态及历史运行。采纳推进修订，失效需求／配置确认、构建产物和当前导入引用，现有流程保留但须复核。随后可在已有样例编辑器修改，再确认、构建／导入及试跑。未选候选不等于取消对应需求。

讨论按钮只将讨论问题填入聊天框，等待用户发送，不自动付费或采用建议。选择及复核状态跨页面保留，并阻止其他任务变更；错误显示在该面板，采纳失败保留选择。服务重启保留候选与采纳记录，但尚未提交的浏览器勾选状态不会持久化。

## 校验和边界

- 只接受指定 JSON 契约，最多 12 个候选、每个最多 10 轮，总大小有限制。候选来源引文必须属于当前八类需求原文，节点引用必须存在；分支类别须关联真实条件节点。来源核对与节点关联不证明语义正确或实际触发分支。
- 入口／输出取自已保存 Workflow Plan；有 DSL 手改引用时必须先有当前修订的最终保留文件，以该文件为依据，不沿用旧计划。文件结构摘要变化会使候选失效。基础模板采用 query / result 或 query / answer；原生 Agent 仅 query / answer。
- 输入仅支持当前入口声明的字符串值，必填变量须齐全。数组仍以 JSON 文本输入后由应用解析。对话每轮须有非空 query，不能手填 conversation_id、未知变量或文件；空业务信息以合法提问场景表达。
- 预期使用已有 contains、equals、json_keys 或 manual 规则。自动路径首段须是实际输出名；不能保证其余路径或业务预期正确，需要复核。语言质量／事实忠实度等应用 manual，采纳不把人工判断算作自动通过。
- 模型不得改变已有样例、生成正式 case ID、标候选为可忽略，或重复已有／本次相同输入和预期。待决定事项非空时阻止采纳。用户采纳可选择子集，后台不以数量宣称覆盖完整。
- 候选绑定任务 ID、修订、需求确认、需求／配置、入口／输出、最终保留文件、环境公开连接状态、现有样例及专项清单。变化、重复采纳、跨任务／未知／重复选择和并发执行均拒绝；恢复旧版本也不会恢复有效的旧采纳许可。
- 模型建议走现有有界执行器，以 `kind=cases` 纳入同一累计助手费用账本、每轮费用／时间限额、暂停及重启保护。结构或业务问题保留候选并暂停，不为通过校验自动删改规则。账本仍不涵盖 Dify 执行费用。

生成提示包含本任务已确认需求、公开配置（去除助手供应商 ID）、当前流程或最终保留 DSL、已有样例和覆盖清单。不会读取加密凭据并注入提示词；用户输入文本中的敏感信息仍需用户避免填写。本轮没有对真实模型发送新数据。

## 接口和记录

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/api/tasks/{id}/case-proposal` | 当前候选、入口／输出依据、过期状态及历史 |
| POST | `/api/tasks/{id}/case-proposal/generate` | 携带严格整数 revision，生成并保存独立建议 |
| POST | `/api/tasks/{id}/case-proposal/adopt` | revision、proposal_id／token、item_ids、acknowledge_review，原子追加本地样例及采纳记录 |

独立 `case_proposal` 记录保留原候选、来源修订、上下文摘要、选择 ID、新增正式样例 ID 与采纳时间；交付报告增加建议记录，实际验收仍由现有运行汇总独立判定。

# 单层容器内HTTP文件文档提取（0.104）

## 可生成范围

Workflow／Chatflow的单层顺序或显式DAG迭代／循环正文，支持 document-extractor；并行迭代仍须逐项独立及并发数的明确声明。来源只接同容器内全路径上游HTTP.files，HTTP继续受GET／HEAD重复读取声明与认证／重试规则保护。容器外文件绑定、用户上传、单文件、URL／普通对象／代码伪造文件和嵌套均不猜测或转换。

配置必须完整：variable_selector:[HTTP节点ID,"files"]、input_type:"array[file]"、empty_policy:"return_empty_array"。原生生成variable_selector与is_array_file:true，保留parentId、作用域标记及原连接。输出text是按文件顺序的array[string]，空文件数组为空文字数组；不能直接作为LLM问题／参数提取的单段文字或作为容器标量共同终点。使用明确模板／代码／标量数组处理转为所需结果，再按声明输出或更新循环状态。

## 业务和环境条件

坏文件可能使整个节点／本轮／整批失败，不静默跳过、承诺逐文件失败汇总或立即取消并发请求。扫描PDF可能没有文字，不提供OCR。DOC／XLS等格式可能经过目标Dify配置的Unstructured服务发送文件及产生额外费用，须确认文件格式、解析环境、权限、出站、限流、空内容行为、人工替代和预算。GET声明不是平台强制只读或费用上限，重复下载／解析不计Sierra模型账本。

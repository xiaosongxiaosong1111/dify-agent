# Sierra AT-11 验收结论记录

日期：2026-10-20（Asia/Shanghai）。范围：BACKLOG 第 19 项「核对 AT-11『未确认配置或资源操作』现状并补隔离检查」。需求基线：`docs/requirements-v1.0.md` AT-11「程序阻止执行，显示待确认内容」。

结论：**本项本地隔离检查通过；未进行真实 Dify 平台或最终业务验收。** 本次仅补测试及记录，不修改产品实现，不处理后续队列项。

## 现状核对

- `main.confirm` 要求先确认当前需求，再确认具体配置；资源方案为空时拒绝。配置确认将模型等配置及 `resource_plan` 一并绑定到当前修订，并保存确认历史。资源方案目前是自由文本，默认已有“只创建新的应用，不覆盖已有应用或知识库”声明；非空检查不等于核验每项资源、目标身份和具体影响，也没有独立的应用导入资源批准对象。
- `main.build` 在确认不齐时拒绝；`main.external_action` 在创建导入／运行记录、调用外部操作之前检查修订和需求／配置确认。其他入口条件可能先拒绝，例如试跑尚未导入或应用 Key 归属不匹配，所以不能宣称所有未确认请求都返回同一个错误。
- 修改资源方案提升修订、撤销配置确认、当前成果及导入绑定，保留未变化的业务需求确认和历史快照；旧修订请求被拒绝，必须确认当前配置后才能重新构建。环境地址变更同样使关联任务修订和确认失效。
- 知识库另有具体准备方案，提供名称、用途、工作空间、索引方式、资料与费用说明。任务配置已确认不代表知识库方案获批；单独确认知识库方案也不会自动执行。高质量索引还要求明确接受未知 Embedding 费用。旧任务修订／连接的方案不能继续执行；本次通过公开环境 PATCH 检查连接变化，因任务同时提升修订，实际先命中任务修订门禁，并非单独连接比较分支的运行证据。
- “显示待确认内容”目前由中文拒绝提示与可读取的任务配置／知识库方案共同提供。构建及外部操作的拒绝响应仅有概括性 `detail`，没有统一、逐字段的待确认明细。静态核对 `frontend/src/App.tsx` 可见配置及资源方案编辑和确认入口；本次没有运行前端体验验收，不能据此宣称用户能在所有页面完整看到待确认内容。

## 新增隔离检查

`backend/tests/test_api.py` 新增 17 个用例：

1. 6 例覆盖 Workflow／Chatflow（`advanced-chat`）／Agent 在未确认需求或仅确认需求时阻止构建；断言中文提示、方案可读、GET 及持久任务不变、无成果文件，编译器不得调用。
2. 4 例分别隔离需求确认和配置确认缺失时的导入／试跑门禁；断言拒绝发生在适配器派发和操作记录写入之前，任务和既有静态成果字节保持。为排除更早的试跑前置条件，直接设置临时任务缺失确认标记及合成导入 ID；这些是人为构造的局部状态，不是真实导入回执，也不证明这些组合可由正常 API 产生。
3. 1 例覆盖空白资源方案不能确认且任务不变。1 例覆盖资源方案变化、旧修订确认／构建／导入拒绝、当前修订未确认拒绝、旧成果下载失效、历史保留，以及当前修订重新确认后可生成 `static_only` 成果。
4. 2 例覆盖经济／高质量索引的独立方案批准、未批准执行拒绝、高质量费用单独同意、批准回执持久化；批准后无资源 ID、无操作记录、无新 Key，不自动派发或修改任务。
5. 3 例覆盖草案确认前任务修订变化、方案批准后任务修订变化、方案批准后通过环境 PATCH 改变连接，拒绝旧方案且任务和准备记录保持。

所有任务与方案使用临时 Store 和数据目录。沿用文件级 autouse fixture 阻断真实同步／异步 HTTP transport 及默认 `main.call_model`；新用例还阻断未确认时的编译／导入／试跑适配器和知识库写方法。知识库方案仅用固定工作空间及模型目录响应，未执行任何资源写入或实际模型调用。构建及任务配置准备沿用 `create`／`approved` 的旧测试辅助函数，关闭新任务准入／流程复核策略以隔离本项门禁，不代表新任务端到端验收通过。

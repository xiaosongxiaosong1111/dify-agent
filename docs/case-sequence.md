# 选择已保存样例并依次试跑

运行页“选择样例并依次试跑”支持Workflow、Chatflow和原生Agent的普通单轮标量样例，一次1—10例，按保存顺序启动。只运行明确选择的样例，不自动推断哪些需求受影响。

1. 保存并复核当前需求、配置、计划及静态成果，确认当前App已发布并配对专用运行Key。
2. 在原累计执行限制中明确保存有限次数上限。选样例并点击“核对所选顺序与本批上限”；只读预览不预留次数、不修改限制、不解密或请求外部服务。
3. 核对数量、顺序、App、已有启动次数和上限，以及本批已有外部资源/费用授权，再主动勾选并启动。
4. 每例复用原 `/run`，原输入、确认、原生节点安全、等待平台、累计次数/耗时/报价与失败监测门禁均继续生效。首例未明确规则通过，包括业务失败、需人工判断、请求失败、平台等待或未知，停止后续，不自动重试。
5. 可点“停止后续样例”，等待已派发例返回；离开或刷新不续跑，不取消已派发请求。查看下方原运行记录。最近5个已启动批次显示保存的选择顺序及未启动项，不把未启动当失败或通过，不继承为当前修订验收。

## 来源与重复派发保护

`POST /api/tasks/{id}/case-sequence-preview` 只读取当前保存修订，返回完整有界来源的SHA256标记、选择顺序、起始记录数及次数上限。标记包括完整任务（排除随运行变化的状态/时间/运行数组）、原历史前缀、实际成果字节、完整环境、未解密的运行Key密文指纹、原执行策略及设置。来源8MB、成果2MB上限；不可核对就拒绝，不展示凭据或摘要前内容。

每次 `/run` 可带 `sequence: {case_ids,start_count,index,token}`，只允许原保存样例，无自由输入或会话混用。后端在原运行锁内、追加记录前重新核对来源、起始记录数+序号、前例归属和规则通过。同一步并发或重放因历史数变化被拒绝；无后台作业或自动恢复。原普通单例调用保持兼容。实际运行记录保存原样例快照及本批选择IDs/序号/标记；只读预览本身不落库。

这是乐观并发来源标记，不是签名、资源批准、账单硬封顶或跨进程作业锁。Sierra当前单后端进程的原Store锁继续使用；不声称支持多个服务进程共写并发。来源/Key/策略同修订变更及任务暂停会停止后续；启动后原报价可能超过阈值，不以未知金额当零。

## 范围

不支持文件、多轮、续聊和复杂输入批次；用原专用入口。停止后不自动返回已消费次数或费用预留。历史已消费真实批不可因本功能重新派发；本次开发没有真实模型/Dify调用。原16任务、凭据、回执和unknown账本精确保持。

定向24个新后端、相关合计65个及隔离实际界面7项/构建通过，详见结果文件。界面使用真实本机API/记录但Dify末端为替身，不是平台或完整业务验收。

已有流程能够通过参数提取节点得到订单号，但0.273订单模板只接受开始文字或整条query，导致合法的提取结果无法接到查询节点。本次把这段连接补齐，不新增参数提取模型或实际调用。

## 使用

在已经包含参数提取节点及明确成功检查的Workflow/Chatflow中，进入订单查询模拟模板，选择已声明的模拟依赖、成功路径上的根代码节点，然后选择例如`extract.order_no · 提取文字（须在成功分支使用）`。输入合成订单表并明确接受替换范围，预览后主动采用、保存计划、确认配置并静态构建。

仅列出原计划中根参数提取节点明确声明的string业务参数，不把数字、布尔、数组、__is_success/__reason/__usage等状态字段或不存在字段转换为订单号。原开始文字和Chatflow整条query选项保持；模板本身不做自然语言提取。

既有完整流程校验继续检查提取节点、__is_success成功IF、唯一成功出口及业务引用的执行路径。查询位于失败分支、公共汇合路径或可能被失败路径绕回时不能使用提取默认值。若不兼容，预览会拒绝并显示具体结构问题，不删除失败处理、不改成功条件或偷偷重连。

采用只改选中代码节点config，提取节点及其模型/参数、成功IF、失败回复、汇合节点和全部连线保持。实际提取仍可能失败或得到无效业务内容，后续模型费用与运行许可要求不变；静态连接成功不证明真实提取质量。

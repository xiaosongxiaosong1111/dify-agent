# 未确认流程草稿

0.51.0 为 Workflow、Chatflow、Agent 的流程编辑提供独立本机保存副本。用户点击保存后，尚未写完的 JSON、无效配置或只写了一部分的内容也能留存；不是自动逐键保存，尚未点击保存的修改仍仅在编辑器中。

## 使用方式

- 保存当前未确认草稿：保留原文字，不规范化、补齐字段、校验完整方案或调用模型。替换已有副本时按钮明确写“替换草稿”。
- 查看保存副本：只读查看，不改编辑器。
- 主动载入：加载为未确认编辑，不自动覆盖正式计划，不沿用旧确认。任务修订变化时标明旧来源，只能主动载入复核。
- 收起草稿：仅当当前原文与刚保存的有效副本完全一致时可操作；编辑器回到正式保存的计划，副本仍留存，可以切换任务后回来恢复。新增修改未留存时阻止收起。
- 删除保存副本：只删除这一份本机未确认副本，不改当前编辑器、正式计划、版本、确认、成果或运行；版本计数不归零，防止旧标签页重新覆盖。

正式采用依旧需要后台校验并保存计划、确认、构建及真实验证。保存副本不算已采用方案；正式保存后独立副本仍保留，修订不同即标旧来源，用户自行决定是否继续保存或删除。当前页面在收起草稿后使用正式计划，不能把副本算作当前验证结论。

## API 与并发

GET／PUT／DELETE `/api/tasks/{id}/plan-draft`。PUT 输入当前任务 revision、非负 draft_revision 和 text；DELETE 输入两个版本。任务版本或副本版本不同返回 409，保持旧副本；不自动合并、覆盖或重试。读取最新副本只刷新面板，不替换编辑器。独立 records kind 为 plan_draft，不纳入正式任务快照、报告或生成请求；没有数据库结构迁移或外部写入。

副本最多 2 MB UTF-8，原文字不能是空白。合法 JSON 还需最多 40000 结构值、60 层检查，超限拒绝，不截断。明确区分“JSON 对象可解析”“不是对象”“未完成／无法解析”，均不是流程验证。保存时检查疑似凭据文字及字段（含转义形式），拒绝且不回显原文；原生秘密变量符号仍应按对应 IR 使用，不能把真实 Key 写入编辑器。

局部 DraftRoute 拦截本接口的格式校验错误，返回中文信息并去掉输入回显，避免非法 Unicode 在默认 JSON 错误响应中引发 500；不改变其他 API 的格式错误策略。原方案、确认、版本、成果、运行、预算与供应商调用均保持。

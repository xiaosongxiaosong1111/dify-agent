# 用 TXT 文件做总结或问答

本文覆盖0.153单文件模型、0.155列表拼接和0.156政策编辑／文件列表操作。当前适配已经实现并通过隔离检查，真实Dify文件／模型执行仍待具体方案批准后的联调；不把示例当作客户验收。

1. 新建任务时选择 **Workflow**，向Sierra描述文件、问题和回答规则。也可在空白任务的“流程→文件流程起步”明确选择“TXT文档问答”，填入未保存骨架，再按需求编辑；模板不自动选择模型或确认规则。下面的内容可作为待讨论的需求范例：

   > 面向内部同事，读取一个必填TXT文件，按本次必填问题回答。开始变量为document（单文件）和question（文字）。流程为开始→文档提取→一个文字LLM→结束，结束返回LLM的text。模型和完整参数先给我核对。文件不存在、解析失败或模型失败时停止，不自动重试；没有依据时如何回答、允许多长的文件及期望答案质量，需要继续和我确认。暂不使用外部接口、知识检索、语音、记忆、结构化输出或批量文件。

2. 完成需求准入和配置确认。模型由你选择，Sierra不会为了试跑换成另一种模型。检查最终流程确实只有上述单文件四个根节点；列表路线须为五个根节点并包含规范拼接步骤，提示词明确引用提取文字和问题。生成DSL、导入新应用后，在Dify核对并发布。用于Sierra搭建建议的模型连接，与Dify应用实际调用的模型连接分别配置。

3. 在Sierra对应环境登记该应用的Service API Key和App ID，并保持管理连接可用。打开运行页的 **运行文件 · 上传方案**，读取最终文件入口，选择变量和原TXT文件，准备并核对文件名、字节数、SHA256及目标App，明确批准单次上传。此步骤不运行模型。

4. 上传成功后选择 **选择用于下方TXT试跑**，再将所选文件填入空白输入；已有内容不会被覆盖。补全本次问题等必填参数。只使用本任务上传记录的Sierra引用，不手填Dify文件ID或URL。

5. 点击 **准备单次文件试跑方案**。核对所列文件、完整输入、实际模型标识、完整参数、全部提示词及引用的开始参数。检查Dify中的实际模型服务地址、留存与计费政策。普通运行确认、文件文字出站确认、费用未知确认都默认关闭；全部明确同意后才执行这一次；列表模型路线还须第四项独立拼接政策批准。

6. 结果进入普通运行历史。技术成功不代表答案完整、忠实或符合业务规则，需要再核对你的实际预期。明确失败时可主动读取原运行诊断；超时或结果未知时不要重复派发，先核对原平台运行。

0.155同时支持TXT列表经过明确规范拼接后进入一个文字LLM。在空白Workflow选择“多个TXT · 明确拼接后交给LLM”，逐项选择规则，再核对五节点草稿；多个上传记录按原顺序填入document数组，补全question。试跑方案除三项原批准外还须单独勾选拼接政策。列表不经规范拼接不会隐式发送模型。长文可能超过模型上下文，本批不拆分、不承诺模型读到全文。其他格式、检索、HTTP、自定义代码、分支、迭代及结构化输出保留为未支持范围，原流程不会被静默简化。

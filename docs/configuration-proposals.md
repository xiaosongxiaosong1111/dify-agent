# Sierra 集中配置方案

版本 0.18.1，2026-10-11。首批全局配置建议和明确采纳流程已实现；真实模型结合本机目录的建议、校验和隔离本地采纳已通过一次成功联调。目标 Dify 应用导入／试跑及复杂配置质量不在本次成功范围内。

## 使用流程

1. 明确并确认需求，在“配置”页点击“读取配置依据”。只读 Dify 模型目录、参数规则及知识库目录，不调用模型，不执行资源写入。
2. 点击“请求 Sierra 给出配置方案”，将本任务需求／配置／已整理专项说明、近期用户讨论、当前流程及目录元数据发给已配置的搭建助手模型。此次调用计入任务累计预算与每轮建议预算。
3. 集中查看每个拟议字段的生成前值、拟议值、理由以及体验／费用／人工影响。遗漏字段保持现有值，不等于删除；可将具体异议送到聊天框再讨论，不自动发送或接受建议。
4. 尚有待决定事项时不能采纳。所有变化要明确接受；保留未验证／文档为空的资源，以及改变模拟依赖，另需明确接受对应限制。
5. 采纳只更新本地配置并增加修订，保留业务需求确认、失效配置确认。已有 Workflow／Agent 计划标为需复核，保留原内容；仍需检查／保存计划并确认配置，才可正式构建和导入。不会实际建库、改凭据或执行 Dify 写入。

## 依据与边界

- 参数规则最多核对 6 个可用 chat 模型，优先当前选择；知识库目录最多 3 页、每页 100 条。截断、连接失败和登录过期都显式记录，不当作完整或已验证目录。
- 目录快照有效期 15 分钟，绑定任务的目标环境／连接状态。生成与采纳均检查有效性；重新读取目录、改需求／配置／环境／流程／对话、换修订后，旧方案不能套用。
- 新模型只能从已读取可用模型及参数规则选择。更换模型须显式包含供应商／模型／Temperature／Max tokens／完整扩展参数，防止继承隐藏旧参数。实际规则校验类型、数值范围、必填与选项。
- 目录不能证明质量、价格、工具行为或调用成功。未读目录时可以保留当前用户填写的模型／库标识，但须明示未验证并明确接受；不允许编造新 ID。空模型而流程需要 LLM 时必须保留缺口；代码／模板流程不机械强制模型。
- 首批检索只给出已有全局 multiple／Top K／无阈值／关闭重排配置的建议，不虚构新检索策略或改独立节点。复杂策略需要协商，尚未适配的功能不得悄悄删除。
- Chatflow 支持记忆、轮数、开场白及建议问题；Workflow 和原生 Agent 不会静默采用不生效的同名开关。Agent 完整行为、节点级模型、跨环境迁移仍未完成。
- 模拟标签不等于已有模拟数据或样例已跑通。资源操作文本也不等于已执行；实际知识库准备／应用导入沿用独立确认流程。

## 接口与审计

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/tasks/{id}/configuration-proposal` | 读取目录依据、最新方案、差异、限制及方案历史 |
| POST | `/api/tasks/{id}/configuration-proposal/resources` | 带 revision 的只读目录发现，暂停／重启／并发保护 |
| POST | `/api/tasks/{id}/configuration-proposal/generate` | 经已确认需求、目录、费用及时间门禁的模型建议 |
| POST | `/api/tasks/{id}/configuration-proposal/adopt` | revision、方案 ID／token 与明确接受各项影响后本地采纳 |

方案与目录独立持久化，历史恢复不会把旧建议直接重新采纳；采用 task／方案原子提交，拒绝跨任务／过期／重复采纳。报告中保留方案及已接受限制。配置建议使用相同的有限修复、候选保留、暂停和累计助手模型费用账本，生成失败不会应用一半配置。

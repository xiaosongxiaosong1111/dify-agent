# 移除资料后的失效冲突处理

任务345，对应FR-06/10/22、AT-03/08。DeepSeek负责实现与检查工具，Codex负责问题复现、方案、独立验收和集成。

## 原问题

需求中写“退款限7天”，参考资料写“退款限30天”，保存有真实引文的冲突后，用户移除了该参考。原逻辑会正确使旧检查过期，却没有可用收尾路径：提交当前已无此冲突的检查会因不得删除旧行而422，采用原方案又因来源过期409。不能要求用户伪造两个来源或重新上传已决定移除的资料才能继续。

## 明确撤销入口

“需求分歧与裁定”中，只有某条冲突引用的资料ID已经不在当前任务材料列表里，才出现失效冲突撤销入口。用户须复核剩余现行资料、填写具体理由并主动勾选确认，再点击“明确撤销此失效冲突”。正常冲突的来源、推荐、影响和方案选择仍按原方式处理。

撤销只移除明确指向的待裁定行，不改变需求或材料，不采用任何推荐方案。系统保存原完整冲突、缺失材料ID、理由、来源修订与结果修订；原版本和过去的方案决定保留。删除资料不代表原事实为假，也不证明其余资料一致。

若仍有其他待裁定项，它们继续过期并阻止确认；若清单已空，还须另行复核并明确“确认当前检查结果”，随后按当前版本重新确认需求与配置。撤销本身不自动完成这些确认或生成成果。

仅改材料引用方式、修改需求、引文不同或检查过期，不足以使用该入口；仍在当前列表里的资料所对应冲突不能借此跳过。过期修订/检查令牌、错误条目、缺少确认、空理由和坏文字编码会在保存前拒绝。

## API与历史

POST /api/tasks/{id}/conflicts/dismiss：revision、review_token、conflict_id、reason、acknowledge_review=true、acknowledge_dismissal=true。reason须为非空、可UTF-8编码且最多3000字符的文本。操作在任务锁内重新核对当前来源资格。

冲突状态新增dismissal_candidates和dismissals；原任务保存conflict_dismissals。历史在正常检查保存和Store重开后保留。恢复旧版本可以恢复旧待裁定清单，但不自动重放历史撤销；历史事件只是当时记录，不是当前版本已完成的证明。

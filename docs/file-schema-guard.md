# 带严格Schema检查的文件路线

目标Dify1.17.1／DSL0.7.0。仅五个根节点：唯一必填单文件→文档提取→唯一文字LLM的structured_output对象→Sierra strict schema guard v1原代码→结束。可从原结构化流程通过现有“生成严格校验方案”明确失败行为，再采用草稿；保存、确认、构建和准备单次文件运行仍需主动操作。

只执行完整v1模板与原Schema一致、python3语言、唯一data对象绑定和result对象输出的生成代码；手改或自定义代码、Schema变化、异常默认、重试、绕过、未知执行字段、容器、HTTP、更多模型／代码及文件列表不在本批范围，不能删除后运行。结束保留原LLM.structured_output或用户明确选择该校验result，不自行改引用。

Plan7／Flow6提供完整代码、Schema原文及SHA256、实际对象输入与结束绑定、失败规则；界面读取前另核对原代码及Schema文字哈希。需四项独立确认：一次运行、模型内容出站、费用未知、Schema错误终止整次Workflow。输入／文件／样例／目标变化、重新准备及历史查看不沿用旧确认。旧Plan4/5/6不扩大到检查代码。

执行仍只按原Key归属和完整发布图核对后运行一次，无上传、发布、新应用或自动重试。非法对象使代码节点失败，也可能是沙箱／平台错误；失败不能直接推断具体字段。模型费用可能已经发生，不能保证免费、自动取消或金额硬上限。原代码与发布图是静态证明，不表示已取得实际节点执行证据。

远端成功还须返回真正对象并通过本机完整Schema、64KB及安全整数边界，不解析文字、修复、补默认或删字段。校验节点检查Schema，不代替这些本机大小／精度边界或业务真实性判断。非法成功对象仍保持未知／保存安全运行编号而不保留坏对象；明确平台失败保存安全身份供主动诊断，无错误正文。

固定样例对象预览／下载要求唯一原Plan7、原检查／模型／费用批准、唯一派发及同运行／发布／输入／环境／修订，并再次核对原生成声明和Schema；不借当前新方案证明旧对象。实例与界面隔离检查不是Dify真实代码沙箱或客户验收。

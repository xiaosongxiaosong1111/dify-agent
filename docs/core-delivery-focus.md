# Sierra 核心交付优先顺序（2026-10-19）

用户反馈：版本和测试数增加，但主流程体验变化不明显。最近工作确有跨环境映射、手改保留、进度恢复、配置诊断及执行预览实现；问题是局部深化过多，主链可靠性证据不足。不能按版本或测试量推算完成百分比。

## 下一交付目标

集中完成一个公开合成售后知识问答案例：需求描述 → Sierra追问 → 用户确认具体配置 → 生成DSL → 真实Dify导入 → 有命中/无命中试跑 → 修改一个业务要求后重新生成与试跑。保留原始广泛需求，不将未覆盖场景删除或算完成。

| 环节 | 已有证据 | 本次需补的结果 |
|---|---|---|
| 对话及规划 | 早期真实访谈；205合成C07一次生成静态有效检索分支 | 当前完整界面连续操作；明确区分需求草案与确认 |
| 配置 | 参数目录核对、完整配置与资源确认已有 | 案例所选模型/资料/无命中行为在一份方案里明确 |
| 生成 | C07已静态编译、原生保留验证 | 冻结案例DSL与需求对应，不能只展示手写模板 |

| 持续修改 | 版本、手改保留、再次生成等已有 | 改一个真实案例要求，确认失效和保留规则在同一条链上验证 |
| 交付 | 25项最终验收未完成逐项签收 | 输出该案例结果、未覆盖项、复现步骤和用户仍须操作的部分 |

## 实施顺序

1. 只读梳理当前主链，把重复入口或需要用户手工串联的步骤列出来；优先修会阻断该案例的产品行为。
2. 准备公开合成需求/FAQ/输入输出预期和同一批完整资源方案。新的付费模型、建库、应用导入发布运行必须按项目规则获得本批具体批准；旧许可已消耗，不复用。先完成可审查包，再统一确认，不拆成多次零碎许可。
3. 完成已获批范围的真实链路；失败则修具体阻断，达到本批次数/费用约定时停止派发，保存进度，不偷偷重试或缩功能。
4. 报告以“该案例新增能做什么／真实跑到了哪一步／剩下什么”为主；单测和小界面修复作为支撑，不作为独立主交付宣传。

当前Docker/Dify最近核对未运行，仍须检查实际环境，不能声称已连通。所有既有任务、凭据与Dify应用保留。暂缓新增跨环境映射/预览等配套扩展，除非阻断主案例或发现真实缺陷。

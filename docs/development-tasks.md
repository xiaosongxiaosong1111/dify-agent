# Dify Agent 开发任务清单

版本：v1.0。日期：2026-10-09。共 136 个任务。

需求依据：[需求规格 v1.0](requirements-v1.0.md)。界面依据：[原型参考说明](prototype-reference.md)及[交互原型](../reference/prototype.html)。

## 1. 任务粒度与完成规则

- 每个任务应有一个明确交付物和可独立核对的结果；多数按半天左右的工作粒度设计，实际超过一天时继续拆分，不将此作为工期承诺。
- 本清单制定时任务均为“未开始”；当前已有实现与验证见 development-status.md。136 项尚未逐项完成最终验收记录，不能据本表生成精确完成百分比；原型只抵扣设计参考，不抵扣正式实现。
- 状态：未开始／进行中／等待输入／等待验证／已完成／受阻。受阻必须写具体条件。
- 每项完成记录：负责人、成果位置、验证方法、结果、限制、关联版本。
- 用户未确认的配置、默认值和范围不得自行写成既定要求。
- 依赖表中的任务是必要前置；标“同批”或“可并行”的任务可独立开展，整合仍需验收。
- 微小确定性检查使用程序；子 Agent 处理独立工作包，避免同时改相同文件。主 Agent 负责接口契约、整合和最终验收。
- 进入下一里程碑不代表之前未实现的能力被取消；缺口必须保留和报告。

M0 完成条件：存在真实模型调用、目标 Dify 能力验证记录及可用操作清单。未提供环境时，其对应任务为等待输入；界面骨架和本地状态等独立任务可以继续。

M4 完成条件：首个案例实际完成“沟通—确认—生成—导入—试跑—修改—再试跑—交付”。仅有模拟结果不能通过。

M6 完成条件：承诺支持的能力全部有实际证据，其他能力明确列出限制；新电脑能按说明启动并复现案例。

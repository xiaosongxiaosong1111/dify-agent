# 参考DSL原文件的一致性

0.296修复参考摘要采纳后的来源文件问题：原实现固定保存为{id}.yaml，与.yml/.json等原名称后缀不一致，来源读取按名称找不到文件；Windows的write_text还会转换换行，使保存字节与预览时记录的SHA256不一致。

现在新采纳保留原名称后缀（按小写内部保存），直接写入收到的参考DSL文本的UTF-8字节，LF/CRLF不再被磁盘写入转换。保存摘要与来源读取一致，原文件被改动时仍拒绝使用。只修新采纳，不把历史错误后缀文件自动改名、迁移或猜测为当前来源；旧摘要不匹配仍须明确重新上传核对。保存的是接口收到的文本，不宣称恢复浏览器解码前的任意原编码或BOM。

后缀路径只接受有限普通字母数字形式，拒绝Windows备用数据流等不能安全保存的后缀；不执行源文件、不改变当前计划/类型，不自动确认需求配置，也不把结构摘要或“保留指定部分/严格复现”升级为已复现。原有静态保留门禁继续有效。

原检查13失败；修后新增15/相关56后端通过，涵盖.yaml/.yml/.json/大写后缀/无后缀/中文名、LF/CRLF、来源读回、改动拒绝、旧文件不追写和不安全后缀。实际界面5项完成.yml LF及.json CRLF的上传预览→明确借鉴采纳→刷新，并在后台逐字节核对两份原文。前端未改，复用0.295构建；未全量。

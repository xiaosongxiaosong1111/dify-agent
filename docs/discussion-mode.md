# 只读讨论模式

开发0.187，尚未部署，实际状态以development-status.md为准。

## 用户操作

对话框明确选择“需求检查”或“只读讨论”。默认需求检查保持原行为，可更新需求与准入并使相关确认失效。只读讨论仍调用当前任务配置的真实助手模型、保存对话和实际用量，计入同一助手访谈预算；不修改需求、配置、流程、确认、版本或成果。不自动执行外部操作、工具或资源。头脑风暴和“下一步如何做”可先讨论，决定采用后切换需求检查并明确更新确认。

需求页“请Sierra检查需求”明确强制review，避免选了讨论后误以为已复核。讨论问题入口只填输入草稿并选择discussion，发送仍由用户操作。切任务恢复默认review；已保存讨论消息有明确标记，旧消息不改。

## 服务端约束

POST /api/tasks/{id}/messages增加mode=review／discussion，默认review。严格合法文字、布尔流式选项与模式，未知字段或空白／坏编码在记录与派发前拒绝，错误不回显输入。原模型选择、预算、费用、超时、暂停、重启和迟到修订保护继续执行，一次请求不新增其它模型调用。

discussion只接收完整JSON对象且仅message，不能带requirements_patch、intake_review或配置／工具字段；重复键、非有限值、围栏或不完整正文拒绝整份结果，不偷偷采用部分。失败候选及实际用量按原访谈记录保存，不自动重试。不按模型说法改变任务，即使模型声称执行了操作也没有执行工具。

讨论模式采用独立系统协议，按当前应用提供同一公共能力目录，附最小任务进度描述供解释。进度只含state、页面、固定原因与待核对项及未验证标志，不包含任务／环境／应用ID、摘要token、运行输出或凭据。它是派发前保存状态，不是全套预检、资源可用或业务完成证明。本轮用户问题尚未改写任务。

purpose=discussion由服务器设置，讨论用户消息排除出需求准入主题、上下文摘要与可引用证据；后续模型历史明确标记未采纳讨论。配置建议也不把这类用户文字当作需求依据。需求、配置、覆盖、冲突与建议上下文保持原摘要；明确采用应重新走更新／复核，不把讨论当批准。

执行检查点增加mode，旧记录无mode按旧访谈展示。流式预览仍是未完整校验前缀；discussion完整核对后只保存对话与用量，不写需求。暂停或修订变化不应用迟到回复，预算不足仍停止；讨论不是免费请求或继续外部操作的许可。

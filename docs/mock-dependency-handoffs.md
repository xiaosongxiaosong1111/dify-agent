# 模拟依赖逐项接入待办（0.272）

上一版本只把模拟依赖声明写入导出，没有地方逐项保存“位于哪里、接入真实服务要做什么”。本版补配置界面的逐项待办，让交付文件不再只有统一的“以后替换”提醒。

## 使用

在配置页填写模拟依赖，保存显式流程后，在“模拟依赖逐项接入待办”中为某项点击“填写接入待办”，明确选择位置并填写接口替换、鉴权引用和要重新验证的样例；不要填写真实密钥。保存配置后须重新确认，随后构建和下载。

每项可以关联一个位置；多个位置须先拆成不同依赖声明。界面列出已保存显式Workflow/Chatflow的根节点；原生Agent只可选择系统指令位置，不新增工具支持。没有显式流程时原声明可以保留，界面不会猜节点。基础模板编译的实际节点ID也可通过API明确填写，但该兼容路径没有新增界面向导。

刷新可恢复已保存值。当前节点删除后，原ID及待办保留，界面提示重选；依赖声明被改名或移除时，旧待办保留并提示明确处理。未知位置或孤立待办会阻止新成果，不能静默改绑。旧声明未填待办时仍可构建，但静态警告和报告明确显示缺少逐项信息。

已读取实际DSL的任务会另外核对最终保留文件的节点引用和待办说明；缺说明时拒绝构建，需明确补齐实际DSL说明并重新分析确认。系统不替用户改写手改文件，说明齐全时原文件逐字交付，原合并记录保持。

配置保存沿用既有修订规则，原配置确认和成果失效；待办进入新导出说明、Agent包metadata及交付报告，节点、代码、模型参数和提示词保持。位置检查只证明引用存在，不能证明业务上正确的模拟行为或真实服务可用；没有“完成”字段可以直接把待办标成已接入。真实替换和试跑仍按原批准边界进行。

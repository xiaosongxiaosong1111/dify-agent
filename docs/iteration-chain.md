# 顺序多代码计算链

目标Dify1.17.1 / DSL0.7.0。当前范围及实际部署见development-status.md；本功能只准备草稿，不执行用户代码或计为真实平台/业务验收。

## 输入与输出

0.197起，完整有效Workflow可保留计算链之前的全部受支持上游处理图，经一个JSON文字数组解析代码→2—8个纯Python顺序代码正文的迭代→唯一End。其它根节点须为该链祖先，原上游节点／连接／参数保持；上游错误策略与副作用、费用许可不自动改变。首计算输入本项文字，以后每步仅输入原前步完整result；输出只能唯一result文字、数值或逐步明确Schema的对象。明确原变量名，不更改函数正文逻辑。保留ID、标题、根连线和原顺序／并发声明，父仍terminated且不展开。链正文不支持DAG、分支、额外输入／输出、模型或HTTP；链后处理、旁路及其它消费者仍拒绝，不删减后生成。

结果改为index、ok、value、error_category、failed_stage五字段对象数组。失败位置及首次失败步骤保留；步骤为1基，失败值null。成功value保留最后一步原类型，error_category及failed_stage均null。数值有限，不含布尔；int范围±9007199254740991，不舍入或承诺定点精度。只捕获原计算的ValueError／TypeError／ZeroDivisionError／KeyError／IndexError／OverflowError，异常子类归合法基类；不复制输入或异常正文。

后续节点仍执行封装检查及失败记录传递，不调用该项后续原计算，不减少原生节点次数。每步输入/输出格式检查位于捕获之外，未知、沙箱、超时及坏合同仍终止，不返回部分成功、不重试、不补默认。AST限定不是通用安全沙箱或耗时证明。并发已派发项仍可能执行，不能保证即时取消。

## 使用

流程页选择目标并确认五字段和失败传播合同，可单独勾选增加汇总；汇总新增一个纯代码节点和successes／failures／total／succeeded／failed五个结束字段，保留原完整结果字段。第二个明确确认不可由失败继续确认替代。先预览完整计划、步骤输入输出类型和原/封装代码摘要，再采纳到未保存原文。保存后需求和配置失效，须重新复核后按原资源许可导入、试跑。

已有完整规范链（含受支持上游图）可选择追加汇总。后端逐步提取原正文与类型并完整重建相等后才加新节点，原计算保持。原计算在符合限定规范时可明确手改；手改封装／绑定、总步数／顺序不匹配拒绝覆盖。已有汇总仅提示保留，不重复插入。原结束字段与新增字段冲突不自动改名。

汇总对照原输入项数、连续0基索引、五字段、严格成功布尔、最后一步原类型及失败步骤1—总步数；坏记录、缺项或未知类别整体失败，空数组计数明确为0。不读取历史运行，不把未知当0。

## API及失效

POST /api/tasks/{id}/iteration-chain-outcomes；严格revision、完整plan_text、node_id、acknowledge_chain_contract=true及UUID request_nonce。include_summary默认false，须与acknowledge_summary_outputs相同；operation为wrap或append_summary，追加必须明确汇总。重复键、坏编码、非有限值、疑似凭据和2MB原文保护沿用原草稿规则；不保存、联网或执行代码。响应绑定任务／修订／nonce，返回完整候选、源/候选SHA、原/封装代码SHA及类型步骤、五字段合同、未验证标志和新增节点/结束字段。

草稿／目标／任务／修订／汇总选择变化清旧确认与方案，未知或迟到回执不采用，15秒超时无重试。引入、移除或改变两个链标识的语义触发原需求准入batch_outcomes复核；标识不是信任或执行批准。旧单步文字、数值和对象协议保持。

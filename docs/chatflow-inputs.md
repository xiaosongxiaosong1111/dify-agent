# Chatflow 自定义标量输入

0.129已部署。目标 Dify 1.17.1。用户主动选择 Chatflow；没有更换应用类型。

流程页可配置开始节点 text-input／paragraph／number／select，自定义名称、标签、必填、默认和选项；与Workflow相同的明确类型及默认规则。问题仍来自 sys.query，自定义值通过开始节点ID引用。query／conversation_id 为 Sierra 试跑传输保留名，不允许声明同名变量，避免被误送到问题或会话字段。

生成器与最终DSL保留检查均识别这些变量；不删除人工变量、默认值、顺序或下游引用。更改配置仍经过原有保存修订及重新确认流程，编辑变量名不会自动改写引用。

运行页从当前最终成果读取字段，独立展示问题和自定义变量；本机检查绑定当前修订／成果hash，不调用模型或Dify、不填写默认或保存输入。普通试跑对有自定义入口的Chatflow在预算登记、待执行记录和派发之前校验全部输入：必填、数字真实类型、选项、长度及未知字段。问题必须是非空文本。实际payload分为query及inputs，缺省值留给Dify，不改原记录。

首批仅支持带自定义变量的新会话单轮。手填conversation_id、复用成功会话和多轮固定样例均在派发之前拒绝；未宣称续聊时变量更新语义已验证。既有无自定义入口的多轮与续聊路线保持。文件／数组／其它输入类型不在本切片范围，不能默默转换为文字。

依据：本机Dify 1.17.1 api/core/app/apps/advanced_chat/app_generator.py 的 query 与 _prepare_user_inputs(user_inputs=inputs, variables=app_config.variables) 分离。编译／夹具验证不等于实际平台或客户业务通过。本次无真实模型费用／Dify新资源写入。

验证：85项新旧输入／对话相关回归通过8.65秒，前端构建通过；9页面／视觉全部fixture，真实写0、原Task不变；最终完整2598项通过200.48秒。首次1旧不支持表单断言已更新。主资源501.04KB出现既有体积提示，不影响构建通过。

0.133已扩展初始参数完全一致的新会话固定多轮，先检查所有轮次再派发，query可变，自由续聊仍拒绝。详见chatflow-case-inputs.md；本文件上文仅为0.129历史切片范围。

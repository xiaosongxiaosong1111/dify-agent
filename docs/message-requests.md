# 对话发送标识与响应丢失恢复

0.301的网页发送对话会携带UUID发送标识、发送时保存修订、原文字、review/discussion模式和流式选项。后端先持久登记标识、用户消息和访谈操作，再允许模型派发。同一任务/标识/载荷再次提交，只读取原操作；原操作已完成、失败、暂停、中断或因修订变化失效，都不会再次派发或复制消息。进行中/结果未知会拒绝重复派发；标识相同但内容、模式、选项或修订不同也会拒绝。

请求只保存载荷摘要及执行关联，不再复制一份正文或提示词。已有访谈记录和预算账本仍是运行状态与用量的依据，不伪造供应商计费结果，也不宣称跨外部系统的恰好一次事务。无模型路线同样去重。旧客户端不带标识时保留旧契约，不能声称它们自动获得同一发送去重；旧消息和已消费真实批不补标识、不重放。更新网页后需刷新才能加载新客户端。

客户端未取得响应时保留该页按任务暂存的发送标识和原输入，再次主动提交仍使用原标识/原修订，不因服务器已更新修订而自动创建新请求。也可点“只读核对原发送”，通过`GET /api/tasks/{task_id}/message-requests/{request_id}`读取既有回执并恢复当前任务，不发消息。已完成的原文字在仍与编辑器相同时清除；用户另改的文字保持。不同内容/模式的新消息要先核对未确认发送，避免把新标识当成隐式重试。

若本机查无记录，先核对历史后可明确结束本次待确认发送，原文字保持且不立即重发。运行中/未知没有自动重试出口，原费用与未知用量仍保留。标识在页面内按任务保留，不写浏览器存储或保存密码；刷新后本地暂存会丢失，但后端已登记回执和对话仍保留，网页不会自动重发旧输入。此版本不宣称跨刷新草稿和请求标识的完整自动恢复。

新20项/相关159项定向通过，涵盖同标识重放、改载荷、在途并发、失败/旧修订、重启、跨任务、无模型及登记失败前禁止派发；旧不带标识客户端、讨论语义、流式进度、原话证据、需求准入和预算路线保持。实际UI8项验证服务器完成后客户端丢响应、再次提交复用标识、只读恢复、错状态拒绝、任务切换、到服务器前中断、查无记录明确结束及刷新不自动发送。四次浏览器POST尝试仅两次隔离模型替身调用及两份用量记录；实际模型/Dify0。构建/截图通过，未全量。

# Chatflow 自定义输入固定多轮

0.133已部署。扩展0.129的新会话单轮输入支持；自由续聊仍不开放，不把手填conversation_id作为来源。

自定义初始参数必须每一轮完整提供，且与首轮完全一致（包括省略／null）。query可逐轮改变。先从当前最终成果读取入口，再在第一轮预算登记、待执行记录及派发之前检查所有轮次的必填、实际类型、选项、长度、未知字段和固定参数一致性。任意一轮失败则不调用第一轮，不自动复制、忽略参数或填默认。前置检查通过不代表模型或平台已执行。

执行仍复用既有固定多轮逻辑：第一轮不带会话ID，后续使用平台实际返回的同一conversation_id；每轮持久检查点，返回ID变化／调用中断不计通过，不盲目重试。用户暂停则保存已完成轮次，后续未派发。每轮原输入与预期保留，不将可选默认写回原记录，不把一个回答成功当整段对话成功。

模型建议的多轮候选也检查当前已声明自定义参数稳定性，不让“首轮有预算，后续少填／改变预算”的候选直接采纳。界面固定样例输入保持只读，显示每轮参数须一致、全部检查后才发首轮，不自动继承或补默认。原无自定义参数的多轮、Workflow／Agent路线保持。

范围：文字／数字／固定选项等现有标量入口；不适配文件、动态改变初始参数或从已有自由对话继续。可把完整连续问题整理为全新固定多轮样例，不改变应用类型。Schema来自本机最终文件，不能证明目标平台当前已发布入口一致；目标Dify1.17.1的app_generator分别处理query与_prepare_user_inputs，真实模型／平台／上下文业务仍须验证。没有默认开启记忆，也不承诺记忆关闭时能正确回答历史问题。

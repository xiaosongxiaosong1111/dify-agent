# Workflow 文件入口

0.137 开发新增根 Workflow 的单文件、文件列表声明、原生 DSL 生成、根文档提取绑定及手动修改保留。本批是配置和生成能力；不是 Sierra 已完成上传或真实解析。

## 明确配置

- 类型：`file` 或 `file-list`，明确 `required: true`，可见。可选文件的空值类型、Chatflow／Agent 文件、全局 `sys.files` 仍未适配，不换应用类型。
- 文件范围：`allowed_file_types: [document]` 和空扩展名列表表示整个文档类别；若按后缀收窄，明确 `[custom]` 及非空的小写点前缀后缀列表。平台工具文件有独立路径，声明不能充当所有入口的权限保护。
- 上传方式：`allowed_file_upload_methods` 明确非空、无重复的 `local_file`／`remote_url` 列表。远程下载权限不是选择远程方式即可获得。
- 文件列表 `max_length` 为文件数量，明确 1—20 是 Sierra 本批配置范围；不是 Dify 全局上限，也不是大小或页数。单文件须省略或 null。
- 不接受默认文件 ID／URL／对象、选项、未知字段或静默规则补齐。原值和不兼容配置保留，校验返回明确问题。

根必填单文件到文档提取输出字符串，空输入政策明确 `fail_if_missing`；文件列表到提取输出文字数组，明确 `return_empty_array`。Dify 中 required 文件列表仍可为空，不能把必填写成“至少一个文件”的业务保证。无文件追问／空内容拒绝要另配分支。失败文件不会自动跳过，扫描件不提供 OCR。DOC／PPT／PPTX／EPUB／ODT 可能需目标环境 Unstructured 服务及原文件出站／费用批准；XLS／XLSX 用 Excel 解析，不把它们笼统归为 Unstructured。不保证表格／排版保真。

## 页面与运行边界

流程页可明确添加单文件／文件列表，选择文件范围、扩展名、上传方式和数量；新增未选内容保持待选。切换类型／范围不删除旧配置；完整 JSON 未完成保持原文。文档提取可选全路径上游根文件入口，类型变化不代改空输入政策。保存仍按原修订／配置确认流程。

0.150已增加明确批准的单次上传方案；文件运行引用、归属／有效期及冻结运行绑定仍未接通。最终成果包含文件入口时，本机输入表单、自动试跑及模型样例生成明确暂停，不能用 JSON 文件对象／URL／伪文件 ID 绕过。生成 DSL 后可明确选择导入 Dify 并手动上传验证，或讨论已有 HTTP 文件来源；不会自动替换业务方案。没有实际模型、文件下载、Dify 创建／运行。

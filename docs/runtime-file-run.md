# 文档文件试跑

0.151 在既有单次上传之外增加独立的文件试跑方案。代码和隔离验证不等于真实 Dify 文件执行或客户验收。

当前支持根 Workflow 的三条精确路线：“开始 → 原生文档提取 → 结束”（TXT单文件或文件列表），以及0.153新增的“开始 → 原生文档提取 → 一个LLM → 结束”（仅TXT单文件），以及0.155新增的“开始 → 数组文档提取 → 明确拼接规范代码 → 一个LLM → 结束”（TXT列表）。唯一文件变量须为必填，全部结束输出直接引用最后提取／LLM节点的text；只使用本任务和当前修订已经上传成功的文件。含HTTP、自定义代码、分支、迭代、多个模型、审核、定时、其他格式或其他输出来源时明确拒绝，不删除节点或转换文件后执行。Chatflow、可选文件、OCR、固定文件验收样例及通用文件表单尚未接通。

用户在已上传文件方案点击“选择用于下方TXT试跑”，再明确填入空白输入草稿。已有输入不覆盖；填写输入不会自动准备、读取 Dify 或运行。也可手动填入 Sierra 引用：

```json
{"document":{"sierra_file_id":"Sierra上传记录UUID"}}
```

列表为有序引用数组；保留重复项和空数组，不过滤坏项。完整输入以原始 JSON 文字送后台严格解析，拒绝重复键、非有限数及未知变量；最多 64000 字节。所有普通标量／对象规则仍检查，不自动转换或补默认值。

准备 API 只读本机成果和上传记录、保存独立运行方案，不解密密钥、不联网、不修改 Task。方案包含文件名、字节数和 SHA256、原环境及 App、成果原字节 SHA256、修订、完整输入、一次运行和最多两次管理读取。有效期 30 分钟指本机批准期限，不代表远端文件有效期。原生文件 ID、上传用户 ID、服务／管理凭据及其绑定摘要不进入公开方案；文件正文不重新上传或进入搭建模型。

明确批准后，冻结原管理与服务凭据，先读取指定 App 的 API Key 列表并在内存精确匹配所选 Service Key，必须唯一对应；再读取实际发布 Workflow，完整核对发布 UUID、核心节点／连接及特性、环境变量、会话变量。读取不是原子快照；当前上下文改变、凭据替换、图或配置不匹配时不启动运行。Key 列表和其他 Key 不保存、不显示。

通过检查后，后台将 Sierra 引用装配为原生 `local_file` 对象，只存在于请求内存中，以与上传相同的 `flowcraft-local` 用户派发一次。普通 `/run` 仍拒绝直接文件 ID、URL 或未经方案证明的 Sierra 引用。远端文件存在性、有效期和用户权限最终由 Dify 执行检查，失败不重新上传、不自动重试。审批后最多等待 60 秒核对、90 秒运行；超时不代表远端已取消。

运行接入普通 Task 运行记录、累计启动次数／耗时／已记录费用限制、失败暂停及已有等待状态门禁。结果必须有相同发布 UUID、相同运行 UUID 和明确 `succeeded`，输出字段与结束节点一致，且是完整字符串／逐文件字符串数组；缺项、类型错误、不同发布或暂停回执均不能作为成功。未知回执不原样保存文件对象或表单凭据。成功是平台技术状态，自由试跑没有固定样例通过标记，不作为客户业务验收。

已尝试的方案不重复执行；核对失败记 `not_dispatched`，派发后中断记 `unknown`，重启不重放。独立方案历史保留原修订／目标及普通运行记录 ID；资源总览与报告新增第八类摘要，不展示输入、文件正文、文件名或私有 ID。部署空闲检查覆盖核对和执行状态。

接口：`GET /api/tasks/{id}/file-runs`、`POST .../file-runs/prepare`（`revision,input_text`）、`POST .../file-runs/{plan_id}/execute`（`revision,resource_token,acknowledge_run`）。

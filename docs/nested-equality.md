# 严格嵌套等值与历史结果

0.147修正equals检查：对象／数组每一层都核对JSON类型和值，false不等于0，true不等于1，整数1不等于浮点1.0；对象键顺序无关、数组顺序／重复项／长度必须一致。不会将JSON文字解析成对象或改变输入输出。json_schema仍遵守其Draft7语义（数学整数1.0可满足integer），两个检查方式含义不同。

新的equals结果记录comparison_version=2。历史单轮对象／数组equals若缺少严格整数版本2，当前汇总标为待重新核对，不沿用旧通过结论；原始历史输出和evaluation不修改，也不自动调用模型、派发Dify或预留费用。用户先查看原结果及标准，再明确安排新的核对。旧自动规则不能用历史人工标记绕过。普通字符串等值历史保持既有行为；固定多轮汇总本来就依据完整同会话记录重新执行当前检查。

修复只改变本机已声明规则，不证明业务覆盖；旧历史条目里的“通过”仍是当时的记录，当前汇总明确显示待复核。当前修订、环境、实际输入及样例匹配继续必须成立。

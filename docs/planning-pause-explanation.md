# 规划候选修复暂停说明

0.55.0 新增修复候选触及方案范围时的解释。在既有 scope_change 防护拒绝候选时，保存固定类型的变化摘要并在规划记录中显示，包括顶层契约、连接、节点数量／顺序、节点属性、代码内容、输入输出／条件／模型／资源／执行政策及单层内部节点。

界面只显示节点在参考候选列表中的位置，不显示名称、ID、代码、提示词或资源值。节点变化默认折叠。最多记录 100 项、检查 1500 个节点位置；结构处理限制 40000 项和 60 层，超限／异常结构明确提示摘要不完整。摘要没有显示的部分不能据此视为没变化，代码变化标签本身也不宣称所有代码差异都有语义改变。

摘要写入暂停记录后才停止，候选保留、不会应用。这里不增加自动修复范围，不增加模型调用，也不提供隐式采纳入口；用户仍需核对候选、显式修改正式计划，再按新修订确认和验证。

当前单个 Python 语句头缺冒号通常已经在本机修复，不会进入额外模型修复。本功能是既有防御边界的说明能力，不能称为 Dify 运行后自动修复，不能称为新增复杂工作流支持。

15 项新增后台检查涵盖摘要不回显原值、嵌套共用上限、异常结构及修复拒绝前的暂停检查点。完整后台 1493 项通过，既有 Starlette 提示 1。前端构建和 4 项受控页面检查通过，真实任务保持、写入 0；没有新增 Dify 应用、执行或付费供应商调用。

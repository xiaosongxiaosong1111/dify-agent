# 读取实际 DSL 与保留手动修改

当前0.214知识集扩展见[知识集保留](agent-knowledge-preservation.md)，0.213补充见[原生文本Agent保留](agent-text-preservation.md)；下方Workflow历史能力边界以各专项扩展说明为准。原始版本 0.11.0；目标 Dify 1.17.1 / DSL 0.7.0，验证日期 2026-10-10。

## 用户流程和真实来源

“构建”页新增“保留 Dify 手动修改”。可读取此任务已有真实导入应用的当前编辑草稿，或上传不超过 2 MB 的实际 YAML。源 App ID 从任务导入记录获取，不猜测、不接受任意路径。官方导出使用 `GET /console/api/apps/{id}/export?include_secret=false`；Workflow／Chatflow 默认导出编辑草稿，**不是已发布执行版本**。本功能不更新或覆盖源应用，合并后另建新应用并重新发布、绑定 Key、试跑。

读取失败明确返回网络／权限等条件，不能回退旧文件冒充最新。文件上传不会当作在线读取：来源是否属于本任务、是否为最新版本需用户核对。解析拒绝重复键、循环／共享锚点、超过结构上限、非 JSON 值、错误类型／版本、密钥字段及明确疑似明文 token。不会将用户密钥写入引用、预览、报告或 DSL。

读取会保存比较基线和当前文件，推进任务修订，使原需求／配置确认与运行证据失效；未确认保留方案时不能构建、配置确认、导入或试跑。历史生成文件、原始引用及旧版本保留。缺少基线则说明条件，不编造比较结果。

## 三份文件与确认

比较上次生成建议（base）、当前实际草稿／文件（current）、本次任务配置与计划生成的方案（generated）。默认保留只在当前文件中变化的部分，采用只在本次生成中变化的部分；同一处双方均改变且值不同，必须选择 current 或 generated。节点／连接按稳定 ID 局部比较，节点的不同字段可以独立合并；其他列表按整体值比较，删除与修改也会产生冲突。平台导出补齐字段、依赖或规范化造成的差异可能出现，**不能将每项差异都断言为人工修改**。

界面展示全部保留项、生成变化、冲突及文件预览。切换冲突选择后后台重算预览，不能让用户批准一份与实际选择不同的文件。选择明确、核对最终文件后确认形成新修订，随后重新确认需求／配置并构建；不会沿用旧确认或旧通过数。预览绑定任务修订、引用 ID 及三份文件摘要；过期预览或多余选择被拒绝。

当前保留的是最终 DSL 文件，**没有将任意实际 DSL 完整反解析回任务计划**。任务配置与 JSON 计划是生成建议；实际节点、模型与代码以确认后的合并 DSL 为准，这个区别在配置／流程／构建页与交付报告明确显示。后续修改会使保留审批失效，要求再次分析，不能静默丢掉保护。成功导入时保存生成建议基线，避免下一次往返将曾保留的内容错当成可覆盖默认值。

## 门禁和能力边界

- Workflow／Chatflow 支持已适配的开始、文字 LLM、知识检索、条件、代码、模板、结束／回答节点的结构、引用和代码语法检查；原始布局、标题、参数和平台字段保留在文件中。额外平台字段／完整业务／资源账号可用性没有因静态通过就宣称验证。
- 本次保留合并不支持 HTTP 节点、循环／迭代、文件／视觉输入、原生配置包节点及复杂资源迁移；不支持的节点或无效引用在完整文件保留后阻止确认。不会删掉后算完成。
- 原生Agent的单个文本包已支持受限保留并确认：指令、显示信息、开场白及建议问题；模型须匹配当前选择。知识集按0.214受限子集检查且库ID并集必须匹配当前选择；工具／文件／Skills／复杂检索／非默认执行配置仍明确阻止，完整文件不丢弃，不替换为Workflow。
- 修改任务或换环境后须重分析；跨环境资源重新映射尚未实现。缺少条件可保留记录等待核对，或明确放弃本次引用，改按生成建议推进。放弃必须勾选接受不再保护实际修改，并重新确认；不删除源应用及历史文件。
- 合并文件构建与导入前核对确认摘要，外部导入使用已核对内容的内存副本，未确认的文件改动不能导入。在线来源导入前再次读取源草稿：有新变化或无法核对则在创建前停止。检查不会锁住 Dify 编辑，检查后的新变化需要再次读取。
- 静态合并不能证明发布／试跑成功。仅新建应用，管理 Key、运行 Key 和知识库 Key 仍独立登记。

## API

| 接口 | 行为 |
| --- | --- |
| POST /api/tasks/{id}/dsl-reference | `{revision}` 读实际草稿；或 `{revision,content,filename}` 保存上传文件。返回 task/reference，新修订失效确认 |
| GET /api/tasks/{id}/dsl-merge | 分析三份文件，返回 preview/content/validation/conflicts/preserved/generated_changes/merge_token |
| POST /api/tasks/{id}/dsl-merge/preview | `{revision,choices}` 重新预览明确选择，不写任务或外部系统 |
| POST /api/tasks/{id}/dsl-merge/apply | `{revision,reference_id,merge_token,choices}` 检查全部冲突和结构后保存新修订 |
| POST /api/tasks/{id}/dsl-reference/discard | `{revision,acknowledge_loss:true}` 明确放弃保护，新修订／确认失效，历史不删除 |

## 真实证据

独立技术任务 `84ce7e19-3ab4-4971-b5d8-268dfaddab2a`，合并修订 7。源 App `3688a74c-d2e2-48a6-a183-235f24145733`；最终独立 App `714ceb37-130e-4037-af7f-62ecc713fe96`。只新建自己的代码技术应用，不修改用户既有应用。

开发联调用官方草稿接口模拟用户手改，实际将源代码改为 strip().upper()、修改节点标题并将 x 增加 77；本次生成方案提出 strip().lower() 与另一标题。系统实际展示代码和标题两个冲突，明确选择 current，最终构建、导入及实际导出保留大写代码与布局。最终新 App 在 Sandbox 运行“Alpha 首尾空白→ALPHA”和“只有空白→空字符串”两个必选样例通过。合并前后源草稿内容摘要一致，证明合并没有覆盖源应用。**零模型调用**，不计为模型规划成功或客户业务验收。

后台新增 20 项受控检查；全量 355 项通过。8 项浏览器检查覆盖实际来源恢复、失败说明、上传失效确认、冲突选择、真实后台重算预览、明确放弃和任务不被 QA 改动。原生包合并、再次往返、超时／串源保护等仅有已说明的代码或受控验证，不冒充所有场景真实验证。证据 work/roundtrip-live-result.json、work/roundtrip-ui-result.json，测试 backend/tests/test_dsl_roundtrip.py。

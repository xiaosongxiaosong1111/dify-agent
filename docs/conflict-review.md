# 需求分歧与裁定

Sierra 0.15.0，2026-10-10。适配 Dify 1.17.1；本能力不调用 Dify 写接口。

## 使用流程与边界

“需求”页新增独立的分歧工作台。可以请求主模型对照当前描述、解析材料和本任务已确认历史，或通过高级 JSON 提交人工检查结果。未保存草稿切换页面仍保留，阻止其他方案编辑和构建，可明确撤销。

每项分歧展示 2—6 条精确来源、需要裁定的问题、2—4 个处理方案、推荐理由和各方案对体验、费用、人工工作的影响。推荐项不预选。来源不同或日期更新不代表一方正确；事实裁定仍由用户负责。

用户选择后，界面展示将修改字段的**当前原文与拟写入全文**。只有明确接受全部替换和影响后，服务才写回允许的八类需求字段；不修改类型、模型、Key 或 Dify 资源。原始来源、选项、实际写回前后、源修订及结果修订保留在决定历史中。

保存检查／应用决定会推进修订，清除需求、配置和成果确认，并使已有流程及覆盖清单需要重新复核。不能只记录裁定而让旧工作流继续计为完成。处理最后一项后仍需复核当前检查结果，再进行需求确认与后续规划。

## 门禁与来源

- 首次成功保存后为该任务启用冲突门禁。未决项、来源变化、无效引用、未复核结果或恢复后缺少检查记录，阻止需求／配置确认、构建、导入与运行。不能直接删除已有未决 ID；可更新其真实来源／选项，再明确裁定。
- 多项冲突中，一次决定修改了需求后，其余旧选项不自动沿用：保留未决项并要求重新检查。候选不能静默省略这些 ID。
- 来源为当前八类需求、已解析材料 ID，或本任务具有匹配需求确认记录的历史版本 ID:字段。引文必须精确来自对应原文；其他任务、未解析资料、未确认草稿不能冒充确认来源。历史事实不因此自动优先于用户当前意图。
- 确认绑定需求／材料的内容与清单。配置、覆盖清单等不改变这些来源的修订，不强制重复同一事实裁定，避免确认循环；与当前任务操作有关的修订校验仍保留。需求／资料变化、恢复或修改后又改回，不自动恢复旧确认。
- 恢复不会删除已记录的决定历史；过去的决定不自动证明当前业务已实现。交付报告包含分歧、确认状态、来源及用户决定。
- 原有未启用的任务继续使用原准入规则，界面显示尚未检查。本版没有强制迁移全部旧任务，也没有每轮访谈自动启动冲突扫描。

## 模型检查

通过共用的有限建议执行器记录调用、单价、预留费用、可用用量、候选与暂停原因；缺价格不派发，支持时间／估算费用上限、有限 JSON 修复、无进展停止、用户暂停和重启恢复。范围仅本轮建议，不是供应商账单保证或完整任务预算。

给模型的来源摘录最多 24000 字，单段最多 6000 字，明确截断；当前八类需求另完整提供。已知未决项只提供 ID／标题／来源引用，近期已决项提供摘要，降低重复内容。模型不得编造未读部分、替用户决定或声明所有资料已无矛盾。模型返回空列表也需要用户复核；它只是“已提供范围未发现”，不能证明没有遗漏。

检查最多 20 项；标题／引文／问题／理由／影响等文本最多 3000 字。选项须提供非空、最多 8000 字的完整字段替换，用户检查不会无意丢失同字段其他规则。来源子串验证无法证明语义冲突或规则保留完备，人工确认和后续业务验收仍必要。

## 验证

- 新增 31 项后台检查：来源与选项真实性、禁止静默删除、明确双确认、实际需求写回与历史、剩余项复核、旧确认与恢复、元数据修订不循环、已确认历史限定、有限模型建议／遗漏／缺价／暂停，以及冲突和覆盖共同到达静态构建。
- 最终后台全量 487 项通过；TypeScript／Vite 生产构建通过；保留 1 个已有 Starlette TestClient 依赖弃用提示。
- 独立无头 Edge 新增 8 项受控检查：草稿／跨页保护、来源错误、推荐不预选、完整替换双确认、范围结果复核、写回与刷新历史、真实任务不变／无页面错误。另回归覆盖界面 8 项及诊断界面 7 项。写入全部由独立浏览器拦截，没有向用户任务保存虚构冲突。记录 `work/conflict-ui-result.json`。
- 本轮模型响应为受控验证，没有新增真实 DeepSeek 或 Dify 调用。真实冲突识别质量、复杂材料漏检率、OCR、来源行号及自动每轮检查尚未验证／实现，不能宣称需求已全面分析。此前新建／发布 Dify 迭代技术应用仍等待明确批准。

# 布尔开关输入

0.143新增Workflow／Chatflow开始节点type=checkbox，声明类型为boolean，适合“是否人工审核”等明确的真／假规则。支持配置、原生DSL、手改保留、当前成果表单、入口检查、固定样例与可信来源续聊的同类型校对。

只有JSON true／false是合法提交值。false不是未填写、0、空串或文字false。已核对目标Dify1.17.1代码：原生checkbox会转换若干文字及0／1，Sierra本批有意更严格，不沿用这些隐式转换。必填省略／null即拒绝，即使配置了默认；可选必须明确有效布尔默认，省略／null按原生默认语义，但日志和实际发送的原输入不被本机填值改写。

布尔默认不能是数字／文字／null，options、未知业务范围参数不忽略。已有description／hide及合法元数据仍保留；数字、选项／布尔的max_length元数据不充当业务范围或布尔限制。Workflow可用实际boolean来源接boolean条件；不把它当number。Chatflow问题仍是query→sys.query，保留原应用类型及传输保留名。固定多轮／可信原参数续聊须保持初始开关完全相同；false与0或文字不同，变化在预算／pending／任何派发前拒绝，不自动继承或切新会话。

页面配置默认值和运行值均需明确选择true／false。是否“提供值”的复选框只控制字段存在；勾选后仍待选，不默认false。取消提供才移除字段。类型切换不转换原默认／删旧选项；错类型的原JSON保持，用户主动选择后才替换。可明确将最终成果的默认填入本次输入，不用未保存草稿代替最终声明。

验收候选只接受真正布尔或省略可选字段，不能以null／数字／文字冒充。模型没有被调用，新类型并不授权新增数据出站；既有资源／费用授权边界保持。

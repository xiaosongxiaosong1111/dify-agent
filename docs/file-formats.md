# 文档文件格式与运行范围

0.157扩展根Workflow的文件试跑后缀：TXT、MD、CSV、JSON、YAML、YML。仍支持三节点单文件／列表提取、四节点单文件提取→一个文字LLM，以及五节点列表提取→明确规范拼接→一个文字LLM。输出为文字或逐文件文字数组；JSON／YAML文件不因此变成结构化对象或Schema验收。

“流程→文件流程起步”显示明确后缀范围。沿用原TXT示例；其他后缀由用户主动勾选，不自动放开document大类。范围不能全空、重复或包含未知后缀。列表可显式允许混合后缀，保持所选声明顺序；后续输入的文件顺序与重复项仍单独保持。创建只填未保存草稿，不自动确定模型、确认业务规则、上传、发布或运行。后缀范围也随多文件拼接模板请求核对，已有内容不覆盖。

| 后缀 | 固定版本的预期解析 | 必须理解的变化 |
| --- | --- | --- |
| .txt | plain_text | 编码探测范围有限，可能误判、忽略无效字节；不保证完整文字或原编码 |
| .md | plain_text | Markdown标记作为文字保留，不渲染页面、不访问链接、不识别图片；同样有编码风险 |
| .csv | csv_to_markdown | 第一行作表头、转Markdown表格；单元格换行展平、竖线不转义，可能歧义，不保证一致列数或类型 |
| .json | json_normalize | 解析并重新输出；重复键可能仅保留最后一个值，数字写法／精度、空白和转义可能改变；不是严格JSON或Schema校验 |
| .yaml / .yml | yaml_normalize | 安全加载多文档并重新输出；重复键、注释、隐式类型、别名、日期／数字及排版可能改变 |

上述是源码推导的预期行为，不能宣称已观察目标部署解析结果。没有读取本次上传正文，也未逐文件验证内容完整性。需要原文／精确数据保真时，应先调整方案或明确采用用户准备的文字替代文件；Sierra不会自行转换后缀、重命名文件或默默丢内容后算完成。仍须按实际预期验收输出。

准备单次运行时，从原上传记录逐个冻结后缀、预期解析器、可能内容变化、基准版本及源码验证等级。公开解析清单按实际输入位置排列，重复文件重复列出；原生Dify文件ID、上传用户和凭据不公开。空列表没有待解析项，后续空值／模型行为仍以完整方案为准。

新方案版本4、数据流版本3，普通运行批准明确涵盖逐文件解析行为和可能内容变化。文字出站、费用未知以及列表拼接的既有独立批准继续保留。旧schema1—3历史可读但不能执行，不靠重新勾选扩大旧授权。变更文件记录、后缀／解析说明、源码基准、成果、图、连接、凭据或执行策略都会使冻结方案失效；没有自动重试。

源文件哈希证明上传源字节，不证明解析输出完整。六种固定解析路线不进入Unstructured解析器，但平台会从其存储读取文件，存储／扫描等平台策略与模型服务费用仍需核对。模型真实端点、内部重试和费用仍未实际验证，不把纯提取当作平台完全免费。

PDF、Word及其他后缀保留已有DSL声明／部分上传能力，本批文件试跑明确拒绝；不能据支持上传推断支持运行。Chatflow文件、可选文件、OCR、文件固定验收样例、HTTP／分支／容器／多个模型等复杂图继续保留缺口，不静默简化。

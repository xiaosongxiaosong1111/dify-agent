# 失败诊断与处理建议

Sierra 0.14.0，2026-10-10。目标 Dify 1.17.1。

## 已实现的使用方式

“运行”页展开试跑记录，可选择“分析已保存结果”或“读取 Dify 节点轨迹并诊断”。本地分析不请求模型或 Dify；读取轨迹只使用管理凭据调用运行详情及节点列表的 GET 接口。不执行流程、不修改 DSL／配置、不自动修复或重跑。

结果区分：实际运行失败、请求结果未知、执行返回但声明的验收规则未通过。显示来源修订、采集修订、多轮中选中的轮次、远端采集状态、失败节点／执行 ID、脱敏错误、处理建议与历史诊断。交付报告包括诊断记录，原运行和验收判定保持。

建议按实际错误特征识别代码语法、JSON 解析、Sandbox 依赖、限额／余额、凭据、输出声明、变量／必填输入、超时等迹象，并明确“需核对”。不足以判断时保留“尚不能可靠归因”。这是确定性提示，不是大模型语义排错，也不是已经确定的根因。

## 来源与采集规则

- 新试跑记录存 App ID、应用类型与环境 ID／地址／版本摘要；Dify HTTP 错误码可用时单独保存。读取对应 App 的对应 workflow_run_id，不改用任务目前的新应用。
- 远端运行标识须为唯一一致的 UUID；运行详情的 ID 必须一致，再请求节点列表。采集期间任务修订、输入／样例／复核／结果或环境发生变化时，拒绝应用本次诊断。
- 原生 Agent、缺可信应用类型／环境快照的旧记录、环境地址变更或没有实际运行 ID，只能进行本地分析。旧记录不会自动补造来源。用户可在 Dify 控制台核对原始日志，后续试跑保存完整来源。
- 多轮记录优先分析待返回轮次；否则选择最后一个验收失败轮次，无失败时取最后已完成轮。显示所选轮次，不声称整条链所有轮次都已分析。
- 读取权限失败、格式不兼容、标识不符等明确显示原因，并保留本地证据；空列表不代表无失败。超过 2000 条节点拒绝采集；超过 500 条摘要明确截断，优先保留最多 250 个失败／异常条目及最多 250 个其他条目，不能作为完整轨迹证明。
- 节点摘要只取执行 ID、节点 ID／类型／标题、状态和错误；不复制原始输入、输出、过程数据、执行配置或图。已登记凭据、常见 Key／JWT／Bearer 和凭据赋值形式在诊断文本中脱敏，错误最多 4000 字，其他文本最多 200 字。未知格式的敏感内容仍需人工审查，不能声称任意日志全部可自动安全公开。
- 来源“当前”只代表采集时与当前修订／环境一致；使用建议前仍需重新核对当前环境与方案。历史诊断保留，不自动计作新修订修复依据。
- 诊断会追加本地 SQLite 元数据，**不推进方案修订、不改变需求／配置确认、不改变原运行／样例判定**。即使读取到远端终态，结果未知的原记录仍保留，重复执行保护不解除。

## 验证证据与缺口

- 新增 29 项后台检查：实际记录来源快照、HTTP 权限错误、本地只读、路径与身份绑定、敏感文本与原始数据过滤、格式／重复／空／大轨迹、采集失败、来源变化、旧来源限制、多轮选择、验收失败和未知重跑保护。
- 最终全量后台 456 项通过，保留 1 个已有 Starlette TestClient 依赖弃用提示；TypeScript／Vite 构建通过。
- 独立无头 Edge 7 项检查通过：真实保存的历史本地诊断恢复、源变化错误、受控权限失败与建议、修订／轮次／状态不改判、历史保留、刷新恢复和真实任务不变／无页面错误。界面写入全部拦截；记录 `work/diagnostic-ui-result.json`。
- 一条此前真实技术失败记录实际完成本地分析，仅追加诊断元数据，原运行与确认不变，零模型调用、零 Dify 请求。旧错误不足以定位根因，结果为 unclassified。记录 `work/diagnostic-local-history-result.json`；不能当成本轮重新运行或节点采集通过。
- Dify 1.17.1 管理接口字段核对来自同 tag 的 `api/fields/workflow_run_fields.py` 和 `controllers/console/app/workflow_run.py`。远端节点采集当前为受控响应验证，尚未针对新绑定真实记录实测。

本轮不包含 Dify 运行时自动修复、自动恢复／重跑、改动已确认规则、导入失败诊断、原生 Agent 工具轨迹分析或完整任务预算。此前顺序迭代的新建／发布技术应用联调仍待明确批准，没有为诊断另行创建应用或运行 Key。

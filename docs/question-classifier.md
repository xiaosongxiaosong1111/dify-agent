# 原生文字问题分类与业务路由

0.60.0 支持在 Workflow／Chatflow 顶层创建 Dify 1.17.1 `question-classifier` 节点，将诉求分到不同分支。支持清单从 12 类计划节点增至 13 类；不能把新增类型视为全部复杂流程完成。

## 配置及用户选择

明确文字 `query_variable_selector`，2—20 个分类说明及稳定 ID、可选显示标签、补充指令。每个 ID 恰有一个显式出口；未知、重复、缺失或默认出口拒绝。ID 不用 source／false／true，分类说明不能重复；第一版类别和指令为实际文字，不支持动态变量模板。

逐节点模型卡可继承任务模型或独立选择完整模型／参数。Classifier 与 LLM 都纳入任务模型依赖检查；缺模型可以保存明确待配置草稿，不当作已可运行。Chatflow 分类按任务已确认的记忆配置继承历史，会增加模型用量，不支持独立记忆或图片输入。

Dify 对可解析 JSON 缺少分类字段或未知标量 category_id 选择第一类；JSON 解析、字段格式及供应商错误可能直接失败，不能声称全部异常走第一类。Sierra 要求明确 `unmatched_policy={behavior:first_class,class_id:首项ID}`，不偷偷猜回退类别。该字段是 Sierra 方案说明，未伪装成原生 Dify 执行参数。建议明确的其他／追问类别在首项，由用户决定并纳入配置及试跑样例确认。没有原生置信度输出或阈值保证；要求按阈值等待人工时需另议实现条件。

## 界面和输出

分类卡编辑说明、标签、指令、问题来源和完整类别 JSON，直接字段保留 ID、顺序和连线；改变数量／顺序／ID需核对完整 JSON 和连接，不能自动迁移到其他分支。点击填入首项方案只写未确认草稿，仍须保存计划、确认配置。

支持 `class_id`、`class_name`、`class_label` 文字输出及 `usage` 对象。标签为空时原生返回默认 ClassN；不是空文字。文字输出可作为检索问题或最终返回；用途与全路径引用仍按正式校验。类别本身不是知识问答结果，分类是否准确要用实际样例验证。

模型／分类编辑器按需载入，来源可信诊断可以定位分类或模型卡。原生 Agent 使用另一个配置包，不被改为 Chatflow。0.61 接入顶层分类实际 DSL 手改保留及最终语义摘要，范围见 classifier-preservation.md。Classifier 在循环／迭代内仍未适配，发现限制要明确协商，不删除节点后宣称成功。

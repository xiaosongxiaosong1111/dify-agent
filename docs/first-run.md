# 本机首次使用

项目位置：`E:\workSpace\dify-agent`。本机页面：<http://127.0.0.1:8765/>。

## 当前电脑

依赖已经安装、前端已经构建。双击项目内 `start.cmd`，或在 PowerShell 执行：

```powershell
Set-Location 'E:\workSpace\dify-agent'
.\start.ps1
```

停止仅属于本项目的后台：

```powershell
.\stop.ps1
```

## 模型设置

打开“模型接入”，新增服务，选择服务商和型号，输入自己的 API Key 即可。自定义地址、用途和价格等位于高级设置。Key 在本机后台保存，不要发到聊天中。服务地址须和协议对应；实际可用模型以自己的账户为准，不能照抄过期模型名称。

点击“测试连接”，等待和结果直接显示在模型卡片下方；JSON 图标另测短对象输出。关闭设置后在同一页面重新打开仍可查看结果，整页刷新会清除临时反馈。成功只代表文本调用成功，工具、结构化输出和图片能力不能因此自动算通过。本版真实需求对话依赖结构化结果，错误会明确显示，不用预设回复冒充模型调用。

本机目前已配置 DeepSeek 主模型 deepseek-flash，文本和 JSON 对象探测已真实通过。模型接入页显示两个独立状态；JSON 测试按钮仅验证短对象，不代表工具、图片或复杂规划质量。技术联调示例已保留在任务列表：此前模型计划复核后，已真实导入本机 Dify、发布并在沙箱跑通两个文本清理样例。另有真实模型节点、知识检索及原生 Agent 技术验证，客户业务仍需按需求验收；静态编译标签与真实操作记录分开保存。

## 从需求生成基础 DSL

1. 新建任务，由你自己选择 Workflow、Chatflow 或原生 Agent。Agent 当前支持文本及明确知识集范围，需要在“流程”页保存独立 Agent Plan；必要的复杂检索策略、自定义工具等未支持功能须先协商。
2. 描述需求，或手动编辑八项说明。暂不适用的项目明确写“不适用”。
3. 上传资料后确认借鉴、保留指定部分或严格复现；解析失败需要移除或补充可读资料。
4. 在“运行”页定义正常输入、关键分支和必要异常的验收样例，填写具体输入及检查规则并保存。
5. 确认需求，选择目标 Dify 环境。在配置页点击“读取 Dify 实际模型”，选择目录中可用模型并检查参数规则；同模型先保留当前参数，需要时主动填入参考值并采纳。建议先进入草稿，保存与复核资源计划后再确认。知识库可用管理连接读取真实目录；限定单库 Key 不能列举全局目录，可保留已知 ID。Chatflow 可填写开场白及开场建议问题。
6. 在“流程”页检查并保存所需节点计划；检查资源方案后确认配置，点击后台构建。
7. 查看静态检查警告及 YAML，下载文件和说明。此时仍是待真实验证成果。

未保存的编辑会阻止构建、导入和试跑；请先保存并确认。在“流程”页面可人工填写多节点 JSON 计划，或接入真实模型后生成建议。后台支持有向无环的检索、条件分支、代码、模板和无认证 HTTP 等节点。保存计划后需确认配置；需求、材料或验收样例变更后，旧计划过期，须人工复核并再次保存，或重新生成。只有代码／模板的流程不必配置模型即可构建。静态检查不会执行代码或 HTTP 请求。

## 流程规划限制与进度

模型设置中填写输入／输出 USD 每百万 tokens 单价（缓存命中单价可选），没有可计算的价格时规划会停止，不盲目调用。“执行规则”中的重试、时间和费用上限目前只约束每次流程规划，不包含对话、探测及 Dify 导入／试跑费用。

规划页显示实际调用记录、估算依据、诊断与有限修复，提供暂停按钮。暂停无法撤销已派发的供应商调用；后续调用停止，迟到结果不应用。超限、缺资源、没有进展或必须修改方案时暂停并保留候选；最后候选尚未应用，不等于已确认计划。服务重启不自动重复未完成请求。详见 [规划契约](planning-contract.md)。

## 真实 Dify 导入与试跑

目标实例需为 Dify 1.17.1。用户已选择自己在 Dify 页面创建管理员。工作台中先新增并保存环境，再点击“邮箱密码连接”，直接在本机页面输入 Dify 登录邮箱和密码。成功读取应用列表后，管理 Token 与 CSRF Token 加密保存，密码不保存。此入口不会创建管理员，也不会自动注册或发送邮件；登录过期需重新连接。仍可手动填写管理 Token／CSRF；应用运行 Key 和知识库 Key 必须分别配置，不能混用。

导入只新建应用，不覆盖旧应用，也不自动发布。实际导入成功后，到 Dify 确认并发布，取得该应用自己的 Service API Key；在环境设置填写此 Key 和对应 App ID，再执行样例。

Workflow 基础输入为 JSON，例如包含 `query` 字段；Chatflow 同样使用 `query`，可选 `conversation_id`。成功返回一次实际运行结果不等于所有业务样例已经通过。

选择已保存样例后，输入预览只读，后台使用样例快照执行检查；自由试跑不计入样例通过数。人工样例需在返回结果后填写明确意见，可确认通过或不通过，意见变更会留存历史。汇总仅采用当前修订、当前环境中的最新匹配记录。旧修订记录仍可阅读，不计入当前通过数。没有试跑和凭据时仍可保存样例，不会生成虚假运行结果。

本机 Dify 1.17.1 已通过 Docker Desktop 启动，初始化入口为 <http://127.0.0.1:8080/install>。Docker 程序、安装包和容器镜像磁盘位于 E 盘。本机管理员由用户自行初始化，管理连接与文本清理技术应用运行 Key 已配置；知识库 Key 仍未配置。安装成功不会自动获得全部权限。真实联调见 [记录](dify-live-validation.md)。

## 准备新知识库

在已保存的任务“配置”页展开“准备新知识库”，填写用途、名称、索引方式，选择已解析资料或粘贴文本。生成资源方案后先预览全文与费用说明，确认后再主动启动。提交不是完成：等待实际索引就绪，再点击加入任务配置；修订和确认状态会更新，流程独立 ID 需复核。

准备过程中可以暂停后续派发；未知写入须在 Dify 核对现有 ID，不能盲目重建。旧方案不自动加入新的任务修订。详细规则见 [契约](knowledge-provisioning-contract.md)。本机保留“技术联调：知识库准备（产品入口）”的真实记录。

## Chatflow 记忆与原生 Agent

Chatflow 的有限记忆默认关闭，在配置页明确启用并保存／确认后重新构建导入；运行页可选择当前修订与环境的成功会话来源。复用当前历史，不回退或分叉，自由试跑不计固定验收。

原生 Agent 在“流程”页生成或编辑 `schema_version,scope,system_prompt` 文本方案；资料问答使用 `scope=knowledge` 并明确 `knowledge_sets`，检查并保存后再确认具体模型与资源配置。导入后在 Dify 发布、开启此 Agent 的 API，登记该 App 的专属 Key，当前试跑仅接受 `query`。检查部署内建 CLI／沙箱，不把空自定义工具列表当作没有内建能力。见 [Agent 契约](agent-plan-contract.md)。

知识集需完整使用配置页已选库；当前多库检索、自主生成检索词、关闭重排／阈值／元数据过滤。自主检索不保证每轮必检索，有确定性要求时先与助手讨论类型差异，由你决定。

## 常用模型三步接入（0.8.0）

在“模型接入”添加服务商，选择具体型号，填 Key 并保存即可。预设包含官方地址／协议和预算参考价，无须展开高级设置。随后可点“测试连接”，此动作会实际调用模型。已有同服务 Key 留空复用，换服务商需要新 Key；使用代理或其他厂商时选择自定义。见 [预设说明](provider-presets.md)。

## 原生 Agent 连续追问

在“运行”页选择自由试跑，首次使用“新会话”，后续在“自由试跑会话上下文”选择本任务当前修订／环境的成功自由记录，再提交新的 query。历史显示实际会话与来源。固定样例不能混入来源，不计自由追问为正式验收。原生历史由 Dify 管理并增加输入费用，详见 [会话说明](agent-conversation-contract.md)。

## 正式多轮验收

在“运行”新增验收样例，填首轮输入与预期后“追加对话轮次”，分别填写各轮规则。保存会使确认失效；复核流程并重新确认、构建／导入／发布及配对运行 Key 后选择该样例执行。每次新会话、逐轮检查，失败停止后续；运行中可暂停，已派发请求需核对。每条链计一个样例，最多 10 轮，额外历史会产生费用。完整说明及真实结果见 [多轮契约](conversation-cases-contract.md)。

## 继续修改 Dify 手动调整的应用

在“构建”选择“读取当前 Dify 编辑草稿”，或上传当前无密钥 YAML。读取会使旧确认失效；检查生成计划，点击“分析保留字段与冲突”，逐项选择并核对重新计算的最终文件，确认保留方案后再确认需求／配置、构建和导入新应用。源应用不会覆盖。当前文件及最终模型／代码可能与生成建议不同，必须以合并文件为准。原生包、HTTP 和复杂节点合并暂不支持；精确说明见 [保留契约](dsl-roundtrip-contract.md)。

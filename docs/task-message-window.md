# 按需读取任务的对话窗口（0.323）

当前界面打开、刷新和通过主接口读取任务时，只取得最近50条对话及真实总数；更早/较新/最新窗口由用户主动点击后只读取得。原始 `message:N` 索引保持，长原话仍可按已核对来源分页查看；需求准入和下一步等面板使用真实消息总数，不把“本页50条”误当总量。

旧 `GET /api/tasks/{id}` 仍返回原完整Task。新可选 `?message_window=recent` 只替换返回副本中的messages，增加message_count和message_window来源描述，不写入Store或变更真实历史。当前主界面的Task GET主动使用此模式并验证数量、范围、Task身份/修订和提交序号；无效回执不会当成完整历史或静默降级到全量读取。旧写操作/独立子回执仍可返回完整Task，界面继续支持其本页显示窗口。

`POST /api/tasks/{id}/history/window` 翻页时提交当前修订、持有窗口的起止/已知条数/指纹和新范围，每次最多50条。原窗的全部保存字段参与指纹，原话或标签变化、历史缩短、跨Task或业务修订变化会拒绝；后来追加允许。向前后读取限制在原已知范围，主动“回到最新”则验证原窗后以当前总数重新定位。源失效清旧缓存页并提示重新读任务，网络/坏格式保持原页、不自动重试；切Task或迟到的旧提交响应不覆盖当前页。

每页是其读取时的当前记录，不声称所有历史页属于首次读取时的一份不可变快照。尚未读过的更早页若被改变，读到的是当时实际保存的内容；不能据来源指纹推断未读部分没变化。旧窗口有新增消息提示时不强行跳走，用户可明确回最新。读取不改变模型上下文或批准，不解密、不发模型/Dify请求。

这是消息传输层的首批优化。单条消息仍完整传输，Task其它字段（材料、版本、运行和规划记录等）仍保留；SQLite仍按原Task对象读取，没有拆表、全Task大小硬限或其它数组分页，不宣称所有长任务网络/内存问题解决。

新26项后端及任务摘要/原话34项分组、新UI13/长原话UI8/历史查找UI8和构建通过，未全量。包括旧默认/写回执兼容、完整历史保持、窗口连贯、追加/原窗变更、空历史、当前页语义、精确计数、坏回执/晚到和零浏览业务写入；后端只读Spy阻止Store写入或解密。初次UI脚本替换漏async/counter导致夹具语法错误，TypeScript发现响应窄化后遗漏messages类型，均已修正，原日志保留，未降低生产验证。

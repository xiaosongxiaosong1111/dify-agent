# 合并选择与并行说明的未确认进度保存

0.35.0，2026-10-12。补齐合并页面草稿在跨页／浏览器刷新／后端重启后的进度恢复。保存草稿不代替明确确认，也不批准 Dify 操作。

编辑冲突选择和并行说明后，可“保存合并草稿（不确认）”。仅写入本机 SQLite `merge_draft`：业务修订、实际引用 ID、整个所选最终文件摘要、冲突选择、并行说明／草稿勾选、独立草稿版本和时间。可以保存未填完、未确认的说明，不要求为了保存进度先声明业务独立。任务修订、需求／配置确认、DSL overlay、产物、预算、模型调用和 Dify 状态均不改变。

当前任务未存编辑跨页面保留并阻止其他修改；保存失败显示原因且保留编辑。重新分析会清空本页未存选择，按钮有明确提示，已存记录仍保留。刷新浏览器后未存编辑可能丢失，系统不假装自动保存；需主动保存再离开。

有已存草稿时主动“恢复已存合并草稿（重新复核）”。后端先核对当前修订、引用、生成方案及所选完整文件摘要；前端再请求当前预览并核对摘要，恢复选择与说明，清除独立性勾选和完整保留确认。即使记录曾有草稿 ack=true，也不是当前审批，不自动套用声明；仍要重新确认／预览／采用、创建新修订，再确认需求与配置。

文件或修订变化后，旧记录只读显示原文及失效原因，不能恢复确认。未知并行容器、过期草稿版本、未知冲突路径、非布尔勾选、超过2000字的说明、额外字段和疑似已知明文密钥拒绝。合并草稿最多64000 UTF-8字节，独立版本阻止多个窗口覆盖旧进度。当前仅保留本任务最新已存草稿，非无限草稿历史；正式采用的选择与声明仍有 overlay／任务版本记录。

`GET/PUT /api/tasks/{id}/dsl-merge/draft`，PUT 需当前业务 `revision`、`draft_revision`、`reference_id`、观察的 `document_token`、`choices`、`parallel_draft`（各项仅 reason、严格布尔 ack）。正在运行／有未结算调用时拒绝写入；读取不调用模型或 Dify。报告专门列“合并进度草稿（未确认）”，不会与实际保留审批或成功试跑混算。

验证见 development-status.md。SQLite 重新打开测试使用独立临时目录，浏览器所有写请求拦截；没有写入用户实际任务或 Dify 资源。

## 0.37.0 循环草稿

同一未确认进度记录可保存loop_draft，键为当前实际循环ID，各项仅reason、progress_variables、no_progress_limit（严格2—10整数）及ack（严格布尔）。进度字段可尚未选完、理由可空以保存进度，但字段不能未知或重复；正式声明仍须完整、匹配当前保护代码及摘要。恢复清除循环ack与完整保留确认，不将草稿当审批。

# 正式多轮对话验收

版本 0.10.0；目标 Dify 1.17.1，验证日期 2026-10-10。

## 明确的数据与操作

Chatflow 与原生 Agent 的现有单轮样例继续保持 `id/name/required/input/expectation` 结构。需要多轮时，添加 `followups` 数组；每项仅有 `input` 和 `expectation`。后续 1—9 轮，连同首轮最多 10 轮。每轮须有非空 query，不能填写 conversation_id；原生 Agent 每轮只支持 query，Chatflow 可以带其应用输入变量。Workflow 不接受多轮样例。各轮可采用 contains、equals、json_keys 或 manual。

```json
{
  "id": "memory_chain",
  "name": "两轮编号回忆",
  "required": true,
  "input": {"query": "请记住联调编号 CASE-MEM-9461，只回复收到。"},
  "expectation": {"mode": "equals", "target": "answer", "expected": "收到"},
  "followups": [{
    "input": {"query": "上一轮编号是什么？只回复编号。"},
    "expectation": {"mode": "equals", "target": "answer", "expected": "CASE-MEM-9461"}
  }]
}
```

在“运行”中新增验收样例，填写首轮后选择“追加对话轮次”。保存会推进修订、清除需求与配置确认，使已有计划待复核。必须复核并重新确认、构建、导入／发布、配对该 App 运行 Key 后才可执行。选择固定样例后自由会话来源禁用；整个多轮样例每次从新会话首轮开始。

各轮顺序执行，下一轮使用前一轮实际返回的会话 ID；会话不一致或缺少明确回答／原生终态时标为未知，不算通过。自动规则未通过立即停止后续派发，记录“请求成功但规则失败”，不能用人工意见覆盖。manual 轮次不自动通过：自动规则全部通过且全部轮次完成后，由用户按每项人工标准复核整个对话，意见及历史留存。

## 保存、暂停与统计

每轮派发前保存 pending_turn，明确本轮输入与来源；返回后保存实际结果、输入与预期快照及逐轮检查。运行界面读取后台检查点，显示已完成轮次和当前轮。暂停按钮不被运行中的禁用编辑区阻挡；请求暂停后保留等待并继续核对已派发的请求，后续轮次不再派发。Chatflow 本轮阻塞调用可能继续；原生 Agent 收到暂停或取消时，会在知道远端 task_id 的条件下尝试停止。

总采集时间为 `min(300 秒, max_minutes × 60)`，包含整条多轮链；停止远端的清理请求可能额外等待最多 10 秒。达到上限、中途断连或无法确认终态时保留完整已完成轮次及当前轮诊断，标记未知并禁止盲目重复运行。后台重启会将未确认结束的 run/import 从 pending 改为 unknown；检查点和暂停状态保留，不自动重发。

当前不自动从中间轮次恢复；已知失败后由用户重新运行会从新会话首轮开始，仍会产生费用。未知结果须先核对 Dify，不能直接重跑。此功能限制轮数与采集时间，**不包含整任务模型费用硬上限**；每轮会话历史增加输入用量。模型业务输出中的费用或 Dify 插件报价 0 不能作为免费依据。

一条链计一个验收样例，不按轮数多计。汇总要求当前任务修订与环境、完整匹配的输入／预期／实际会话记录。全部轮次完成且规则通过（或必要人工复核通过）才能计入已声明样例通过数。缺轮、旧版本、变更预期、串会话不能计为通过。自由对话与固定链的记录分开，固定链不能作为自由会话来源。

# 手写模型数字的原文保护

0.228，2026-10-19。覆盖配置页手写 Temperature / Max tokens；目录模型选择器的数值保护由 0.227 引入。

输入以文字草稿保留，允许 `1e` 这样的未完成中间态。只有数值含义能在浏览器解析和发送时保持，且符合 Sierra 当前支持范围，才填入任务的有效配置草稿：Temperature 为 0—2，Max tokens 为 1—1000000 的整数；具体型号实际约束仍需查目录和试跑。不会舍入高精度小数、危险整数、下溢数或补默认值。

有错误或后台配置与本页输入冲突时，会阻止保存、保存并确认、构建和任务切换。即使有效配置对象没变，未完成文字也算未处理编辑。切换工作台页面后继续保留；刷新或关闭浏览器可能丢失，当前尚无未完成数字的后台草稿持久恢复。

可修正输入，或明确“回到当前配置中的数值”；后者回到当前有效配置，不表示撤销整个任务。后台同任务修订变化时，手改输入保留；有效文字与新配置不同会显示冲突，须明确采用到当前修订草稿或回到当前配置。保存回执和完整模型选择会同步数字状态，不混用不同任务。

此次同时修复模型与知识库选择器使用相同环境 ID 作为同级界面 key 的问题；重复编辑和切页曾导致旧模型卡片累积。现在两者使用独立的 Task / Env 命名空间，多次编辑后各仅一份。

验证：21 数值辅助检查、8 项独立组件状态场景、10 项应用源及 10 项部署静态资源界面隔离检查、5 项目录源及 5 项部署界面检查、原 41 项映射／13 项模型采用源界面回归、TypeScript/build 通过。API 写入只使用模拟回执，原 11 任务、密文和密钥保持。后台仅版本号变化，沿用 0.226 完整 4717 项通过记录，没有重复全量，也不声称真实 Dify 或业务验收。

0.230补充：现在可主动保存两个数字文字的独立本机进度，刷新后明确恢复；并非自动保存整张表。已存模型/环境/参数未变且Task修订一致时可恢复，旧上下文只读。其他未存配置仍需单独留存。[详细范围](model-number-drafts.md)。

# Workflow首次发布入口（0.249）

0.275已扩展Chatflow首次发布及类型核对，见[当前说明](chatflow-publication.md)。下文保留首版范围与历史验证。

运行页现在可以读取当前新建导入App的草稿及发布状态，核对目标、任务修订、成果摘要后，勾选并确认发布。只适配Dify1.17.1手动Start Workflow；不覆盖已有发布，不创建运行Key，不试跑，不代表业务验收。Chatflow/原生Agent仍使用Dify发布，类型不变。

## 绑定与失败处理

- 当前修订须需求/配置已确认、成果存在，并有同环境/修订/App的成功新建导入记录及匹配导入基线。
- 提案绑定成果原始字节SHA256、完整节点data/连接/变量/features、环境连接、暂停代数及平台原生草稿hash和内容摘要，15分钟有效。画布位置不作业务图匹配依据；父节点关系和节点类型仍核对。
- 准备只读草稿/发布状态。确认前再次读两者，草稿改变、已有发布、任务/连接/成果变化均拒绝。准备/确认不会自动进行下一步骤。
- 发布前持久记录派发意图；同一App有派发记录后不能再从此入口发布。超时、401、返回格式不符、返回后的发布图不符或本机变化均记未知；重启也不重发。明确发布前失败可以重新核对。未知结果须到Dify人工核对，本版不提供自动消除未知或再次发布。
- 发布接口没有原子草稿条件锁，最后核对与POST之间仍可能被外部编辑。界面披露该边界，POST返回后另读发布图；即使事后不匹配也可能已对外发布，保持未知并阻止重发。
- 常规路径共5次管理读取、1次发布写入。认证续期/401重读可能增加读取，不把此数字宣称为平台请求硬上限。管理自动登录保持原URL/版本/空间绑定，不重放写入。

# 创建时主动选择目标环境

新建任务现在同时主动选择应用类型和目标Dify环境，也可明确“尚未接通／暂不绑定”；未选择不能创建，每次打开重置选择。环境失效拒绝在弹窗内可见，原输入/选择及当前任务保持，不自动重试或连接。

需求FR-01及前端入口约定要求创建时选择类型和目标环境；后端已有environment_id及存在性核对，旧界面只发送名称和类型，用户只能之后在配置页补选。现在不默认套用首个环境或当前任务环境，必须明确选一个已登记环境，或主动选择暂不绑定。名称、类型、环境原样进入正常本机创建接口；取消不写，不修改当前任务。

每次从侧栏或欢迎入口打开新建弹窗均重置类型与环境，避免把上次已取消的选择当作新任务意图。选环境未选类型、或选类型未选环境都不能创建；目标已失效时正常拒绝，弹窗保留内容供核对，不自行换目标。

旧界面缺环境入口反例失败，三类型各绑定/不绑定共6个临时API场景、5UI、构建及视觉过；0.399.0-899a0bd48e86e26067a3/296/PID30664十二根733保护部署过，原26密文费用保持，真实模型Dify0/暂缓保持。

创建仅保存本机任务及已登记环境引用，不测试连接或新增远端资源；明确不绑定存null，后续在配置页补齐。断开环境仍按现有规则标注待验证，不代表真实导入/发布/运行或业务验收。后端除版本元数据不变，未跑全量。

证据work/new-task-environment442；临时后端的Workflow/Chatflow/Agent分别验证null与明确目标，环境本身不变、未创建DifyApp、无运行或确认。界面整批三次模拟本机创建（暂不绑定成功、失效环境拒绝、Agent绑定成功），其它写入0。原生产任务数量仍26。

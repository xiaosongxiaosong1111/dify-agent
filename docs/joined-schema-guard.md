# 多文档拼接与工作流Schema检查组合

0.177已实现的组合，实际部署和验证证据以development-status.md为准。

目标图为六个根节点：开始文件列表 → 文档提取数组 → Sierra规范拼接 → 一个LLM结构化对象 → Sierra v1完整Schema检查 → 结束。现有多文档结构化草稿可通过现有“插入Schema检查”明确生成方案、采纳、保存并重新确认；不新增默认字段、隐式模型、逐文件模型调用或第二次校验规则。

两个代码节点按精确生成代码、输入输出与连线分别核对。拼接政策继续明确格式、分隔符、文件数量、字节上限、空列表及空文本规则；校验使用原完整Schema，不转换值、补默认、删除字段或重试。结束可以保留原模型对象引用或明确返回校验result，不绕过校验节点执行。

本次运行使用新Plan9／Flow8，须独立确认普通运行、模型内容出站、费用未可靠预估、完整拼接政策及Schema失败使整次Workflow终止。原五节点或旧对象方案不能扩大授权。失败或超时仍可能已经产生模型费用，当前费用阈值不是金额硬上限。

对象回执继续做本机大小、整数及完整Schema检查；无效对象不留正文、不修复重跑。固定样例读取对象证据须匹配原拼接和校验批准。原节点观察须同时匹配原图、同运行发布、完整前置节点成功、原拼接政策及校验代码；后继失败或本机输出失败不会因校验节点成功而被解除。平台节点失败也不能单凭状态推定具体字段问题。

只支持这条明确生成的根节点路径；手改／自定义代码、额外代码、HTTP、分支、容器、多模型或其他格式不能删掉后执行。编译、模拟回执及合成轨迹不等于真实文件／平台／业务验收。

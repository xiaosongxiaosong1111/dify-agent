# 条件类型的确定性补齐

0.54.0 在 Agent 生成流程候选时，仅在条件缺少 varType 的情况下，根据已有明确声明在本机补齐，记录 deterministic_fixes，不再要求用户或模型重复填可确定的类型。已有 varType 无论正确与否均保持，交给正式校验检查，不修改比较运算、右值、资源或业务规则。

来源包括实际文本输入、已声明代码输出、LLM 文字／用量／结束原因、模板、知识结果、HTTP 正文／状态／文件、明确聚合／迭代输出和标量循环用户状态。未知类型、畸形字段、重复节点 ID 或重复状态名称不猜测。没有声明的实际数据类型也不推断。

单层循环内部可使用当前循环状态和外部明确声明，单层迭代 item 只在输入数组声明与来源声明一致时确定元素类型，index 固定为数值。内部处理输出按自身声明核对。补齐不等于全路径可用，引用存在、支配与跨作用域检查仍由正式校验负责；不能通过补类型使兄弟分支或非法输入合法。

sys.query 只由实际任务的 Chatflow 类型提供依据，不读取候选 JSON 里自称的应用类型／内部覆盖属性。用户所选应用类型不变，资源值不编造。嵌套容器仍未适配，不通过归一化删除或展平。

次数、时间和费用设置沿用规划阶段规则，max_retries=0 时不执行归一化。候选本机补齐仍待配置确认和真实导入／运行，不能算作完成全部场景。操作与 0.53 的本机单冒号修复一样不执行代码，不为元数据补齐追加供应商请求。

验证：22 项新增后台，最新完整 **1478 项通过**，既有 Starlette 提示 1；42／100相关检查通过。包含外部作用域、冲突迭代声明、不覆盖已有类型、重复 ID／状态、恶意 JSON 内部属性和畸形字段，以及仅一次模型替身请求的行为证据。前端未改，沿用 0.53 已构建产物，不为此重复前端检查。实际模型、HTTP、Dify 操作 0，未使用旧真实联调授权。

# 文字流式接收与费用完整性

## 0.102协议底座

Sierra保留原普通请求行为；只有明确stream=True才使用供应商SSE，普通请求不接受增量回调，图像入口不复用此开关。这一步是后端协议底座，尚未把所有聊天／规划入口改为流式，也不证明任意模型或账号的流式能力已验证。

OpenAI兼容请求保持既有模型参数适配，stream:true并请求include_usage，以delta.content累积单候选文字。仅在收到[DONE]后返回完整正文。最后用量帧可没有choices；中断可能没有最终用量，不能按部分用量算完整费用。[OpenAI官方Chat参考](https://developers.openai.com/api/reference/resources/chat)

Anthropic使用message_start、文字块开始／增量／结束、message_delta、message_stop。累计usage覆盖旧值而非相加，完整结束才返回正文。首批不接受工具／音频／思考内容，未知非内容控制事件在本机大小上限内忽略。[Anthropic官方流式说明](https://platform.claude.com/docs/en/build-with-claude/streaming)

## 接收边界

总接收不超过2MiB，单SSE事件／残行不超过64KiB，正文不超过512000字符。按UTF8完整行组装，支持CRLF／CR／LF、跨字节分块及多data行。设全请求时间上限，持续ping不能无限续期。错误HTTP、错误事件、非SSE、格式不合、缺完成标志和大小超限都不自动改为普通调用或重试，不把截断正文当成结果。

## 费用与候选

完整结束的白名单用量仍按登记价格估算；中断时partial_reported_usage作为部分观察单独保留，不冒充最终usage、不释放原预留或按零结算。未知费用沿用现有账本核对和累计预算门禁。部分正文不会因此应用为需求或计划，调用方只有在完整返回并做语义／修订校验后才能采用。

所有本轮协议检查使用httpx受控流，无真实供应商请求、客户数据出站或Dify写入。具体模型质量与费用需后续获批真实联调。接下来接访谈执行检查点与界面，不能把本底座算完整T043。

## 0.103访谈入口与持久检查点

发送前可主动勾选“本次访谈启用文字流式接收”，默认保持普通请求；换任务或刷新需重新主动选择。缺少模型／Key、明确流式能力失败或协议不支持时前置拒绝，不先记录用户消息或假派发。失败不自动改普通请求重发。

每次真实模型访谈有独立操作记录，包含任务／起始修订／模型／协议／流式选择、等待／接收／完整校验／终态、字符计数、分段次数与时间。计数不含原始增量、思考、提示词和Key，也不是token／价格／百分比。四分之一秒最多写一次中间计数，结束时补齐最后累计值。

页面只读刷新检查点，当前记录与任务归属／修订核对；跨任务响应不展示，刷新不重新派发。暂停已发请求可能继续计费，迟到完整回复仅保留原有候选记录；暂停后禁止反复点击。失败、暂停、旧修订和中断都明确记录“未采用”。正常完整JSON仍须通过既有结构／需求准入和修订检查，之后才保存消息与补丁；保存不等于用户确认或业务验证。

服务重启将未确定访谈记录标为中断，现有预算恢复保留未知费用，需求保持，不重放调用。前端目前展示阶段／字符进度，尚未把未校验的JSON拆成可用逐字回复；完整T043及所有模型/规划流式路线仍未整体完成。

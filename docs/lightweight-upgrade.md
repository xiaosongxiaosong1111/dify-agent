# 轻量格式失败后的单次升级（0.317）

这是验收样例建议的可选新策略，**默认关闭**。原有轻量路由继续保持失败不自动换模型；升级只作用于以后主动启动的新建议，不读取或重放历史失败包、不恢复旧操作。开发和本次验证全部使用隔离替身，原16任务路由未启用升级，没有真实模型/Dify请求。

## 使用

在任务上方“验收建议模型路由”选择已有轻量服务，再明确勾选“轻量JSON格式失败后单次升级”。核对固定任务主模型的名称、型号、地址、协议、配置版本与估算单价；它必须是不同于轻量服务的当前任务主模型，并有密钥和价格。确认升级范围和原路由数据范围两项，填写原因后保存。保存只记录策略与历史，不调用模型。

运行页请求样例建议前会显示本次轻量服务、固定升级主模型和最多两次调用范围。只有轻量一次返回**无法解析为JSON对象**、且最终输入/输出用量明确、可按配置价计算费用时，才向固定主模型发送原始有限上下文一次；不附加无效模型正文作为需求。两阶段各一次，均请求最多6000输出tokens和120秒，不在各阶段继续修复。即使全局允许更多修复，该策略仍最多两次；全局修复上限为0时不派发此策略。

模型选择、密钥、地址、价格、用途、能力或任务主模型选择变化会使策略来源失效，不能自动换一个可用服务。升级有独立范围版本1，旧版本批准不能授权未来扩大范围；关闭时清除升级指向并保留全部历史。正常轻量成功只有一次调用，候选显示真实轻量来源；经升级生成则标为“单次升级主模型”。所有候选仍须逐项选择和人工采纳，不自动追加样例或试跑。

## 不会升级的情况

- 连接错误、超时、供应商明确报告的截断/错误、未知或不可用最终用量。
- 模型说明缺条件/需裁定，或JSON能解析但样例契约校验不通过等业务、资源、结构问题。
- 暂停、修订或策略/模型来源变化、总时间已满，或下一阶段费用预留超限。
- 助手累计账本已有未知模型调用，或主阶段本身失败；不会启动第三次调用。

两阶段共用一次建议的总时间/费用估算和同一任务累计账本。先结算轻量实际报告用量，再用该已知费用和主模型预留核对剩余轮次预算；主阶段也单独预留/结算。未知费用及旧预留不清零、不借用，估算不是供应商账单硬封顶。两个账本entry以同一操作ID关联，重试/中断仍保留，不能把显示的调用记录条数当实际HTTP次数。

建议进度可看两阶段模型、逐次状态和用量，轻量原无效返回预览单独保留（最多16000字符，超出会标记截断）。父操作汇总费用/耗时，候选来源指向实际生成模型。服务在两阶段边界或主阶段中断后，重启只暂停并保留已知和未知记录，不继续升级；未派发上游不伪装为模型调用完成。

## 接口和验证边界

原`PATCH /api/tasks/{id}/assistant-routing`新增可选`upgrade_enabled`、`upgrade_main_provider_id`、`upgrade_main_provider_token`、`acknowledge_upgrade_scope`、`upgrade_scope_version`；启用必须独立确认并固定当前范围版本与主模型指纹。关闭须清主模型指向。GET的`upgrade`说明当前条件、固定来源、两次上界及轮次限制。原无字段客户端保持默认关闭；策略保存仍受Task修订和policy_revision约束。

仅`cases`建议接入两阶段驱动；访谈、流程、配置、冲突、覆盖与代码修复不使用此升级。原主/轻量服务适配器、任务累计预算、旧默认修复行为和数据范围版本18保持；不把本功能当通用多Agent分工、语义质量升级或省Token保证。

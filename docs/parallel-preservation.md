# 并行迭代的实际手改保留

0.34.0，2026-10-12。在已有单层顺序迭代链／内部条件聚合图保留上增加并行模式；不把并行转换成顺序，不添加或改写原文件字段来假装通过。

读取／上传当前文件后，先分析三份 DSL。合并预览列出实际 `is_parallel=true` 的迭代容器和并发数。每个容器须由用户核对当前代码、模型／提示词、顺序依赖、共享状态及外部副作用，填写 1—2000 字原因，并明确确认逐项独立及费用风险；随后“核对并行独立性并重新预览”。这是用户声明，静态检查无法证明任意代码没有副作用或客户业务逐项独立。

声明绑定整个当前合并文件的结构摘要 `root_token`。代码、条件、模型、并发数、连接、布局或冲突选择改变，旧声明都不能沿用。声明内容改变也要求重新预览及完整保留确认。每个实际并行容器均须确认；未知容器、已改为顺序的未生效声明、过期文件摘要、缺原因／确认、整数替代布尔标记均拒绝。最终 `merge_token` 包含完整声明，未经预览改变原因不能采用旧 token。

适配边界仍为单层、1—12 个内部处理节点，代码／模板／文字 LLM／条件／无分组聚合，实际并发数 2—10。顺序的并发参数仍须为 1；未知模式、嵌套、跨作用域、内部 LLM 历史、失败继续／跳过和输出展开仍拒绝。任何项失败须停止整批；已派发项可能继续执行，不能保证立即取消。并发增加速率限制及同时计费风险，Dify 执行费用不计入助手累计预算。

独立性声明仅进入临时验证投影和本地保留记录，不写进原生 DSL。原实际布局、代码、条件、提示词／模型、选中输出、候选优先级、数组结果和图顺序保留。最终采用创建新修订，需求／配置需重新确认；构建仍从确认的完整文件出发，外部导入仍只新建且须具体审批。

接口 `DslPreviewRequest`、`DslMergeRequest` 新增可选 `parallel_reviews`，以容器 ID 为键，各项精确为 `root_token`、`acknowledge_independence=true`、`reason`。未传保持原顺序路线；含并行则阻止采用。预览新增 `parallel_candidates` 和已验证声明回显；本地 `dsl_overlay.parallel_reviews` 留存原声明，报告自动包含。0.35.0 起当前任务未存编辑跨页保留，可显式保存未确认草稿；刷新或服务重启后主动恢复选择／说明，并清除独立性及完整确认勾选。参见 [合并草稿](merge-drafts.md)。

验证记录见 development-status.md。隔离 capture→preview→apply→confirm→build 证明完整文件一致，受控页面全部写请求拦截；没有真实并行图执行、Dify 新应用或付费模型调用，不能据此声称业务独立或执行成功。

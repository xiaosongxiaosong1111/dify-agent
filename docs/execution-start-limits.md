# Dify 累计试跑启动与耗时阈值

0.59.0 在运行页新增可选的“Dify 累计试跑次数与耗时阈值”。初始不限制；用户明确填写、说明原因并确认范围后保存。0 次表示停止新启动，空值表示关闭对应限制，关闭不清除历史。策略有独立版本和审计，不改变业务修订或既有配置确认。

## 行为

每个任务累计所有修订的试跑批次，包括失败、未知与旧 App／环境的本任务操作。一次正式多轮样例计一个启动批次，不逐项计内部对话、迭代、循环或重试。导入、建库、助手模型建议不纳入这里，助手模型预算仍使用独立累计账本。

在启动记录落库及 Dify 请求派发前，于同一任务锁内检查计数和耗时阈值。达到上限返回明确阻止信息，不新增运行记录、不派发、不重试；换修订不清零。未保存的策略修改阻止工作台业务操作，需明确保存或放弃。冲突策略版本不会覆盖其他操作的新值。

耗时采用 Sierra 请求的已记录起止时间，不声称等于 Dify 实际远端执行时长或账单。未完成／结果未知的操作即使有服务重启 completed_at，也不能把重启时刻当实际完成；缺时间、无时区、倒退或异常记录均未知。启用耗时限制后，未知历史会阻止新启动，须人工核对或主动调整策略；不把未知计零。

阈值阻止后续启动，不会取消已经派发的远端工作流，因此单批可能跨过阈值。不得称为精确墙钟截止或账单金额硬上限；用户仍需核对供应商实际费用。外部服务和原生节点内部重试费用也不由本模块控制。

## API／验证

- `GET /api/tasks/{id}/execution-limits`：策略、累计批次、已知耗时、未知数和启动阻止信息。
- `PATCH /api/tasks/{id}/execution-limits`：revision、policy_revision、max_started_runs（null 或 0—10000 整数）、max_total_minutes（null 或 1—10080 整数）、acknowledge_scope=true、note。字段严格，疑似凭据说明不保存。

11 新增本机检查，包含派发前阻止、跨修订计数、不清历史、未知耗时、策略冲突与确认。5 项受控页面、构建／视觉通过，只在内存拦截策略写入，真实任务和 Dify 资源不变。

0.59 同时为模型修复发送固定的 NameError／AttributeError／算术类型等提示，只提供预定义类型和代码中已有的标识符，不发送原错误全文或客户值；同一节点多个不同错误保留，超过范围拒绝而不静默省略。除零和 JSON 解析问题标明须确认业务规则，不能自动用空值或跳过使样例通过。5 项隐私／提示专项通过。
